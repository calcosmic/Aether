# Markdown Authoring Best Practices

## Heading Hierarchy

Use a single `#` h1 per document as the page title. Use `##` for top-level sections and `###` for subsections. Never skip levels for visual effect — use heading levels to convey document structure, not size.

Do not use bold text as a substitute for headings. If a block of content needs a label that belongs in a table of contents, make it a heading.

## Link Conventions

Use descriptive link text that makes sense out of context: `[skill format specification](specs/skill-format.md)` not `[click here](specs/skill-format.md)`.

Prefer relative paths for internal links. Absolute URLs are appropriate only for external resources. Keep relative paths consistent with the file's location in the repository.

Check that all internal links resolve to existing files before committing. Broken links degrade navigation and signal out-of-date docs.

## Code Blocks

Always specify a language tag on fenced code blocks: ` ```bash `, ` ```json `, ` ```yaml `. This enables syntax highlighting and signals to readers what runtime or parser to use.

Use inline code (`backticks`) for file paths, command names, variable names, and short literals in prose. Do not use inline code for emphasis — use bold or italic for that.

## Frontmatter Usage

Use YAML frontmatter only when the document will be processed by a static site generator or metadata pipeline. In plain documentation repos, omit frontmatter unless specified by a format standard.

When frontmatter is present, keep it minimal: only fields that are actually consumed downstream. Remove unused fields rather than leaving them with empty values.

## Table Formatting

Use tables only for genuinely tabular data — rows of comparable items with the same set of attributes. Do not use tables to force two-column layout for non-comparable content.

Align column separators consistently. Include a header row and use the `---` separator row. For long tables, consider whether a definition list or section headings would be clearer.

Keep cell content concise. If a cell requires a sentence or more, a table is probably the wrong structure — use a definition list or subsections.

## List Consistency

Use unordered lists (`-`) for items without a meaningful sequence. Use ordered lists (`1.`) when sequence or numbering matters (steps, rankings).

Keep list items parallel in structure: all noun phrases, all imperative verbs, or all complete sentences — not a mix. Start each item with the same grammatical form.

Do not mix ordered and unordered lists at the same level. Nested lists are acceptable up to two levels deep; deeper nesting is a sign the content needs restructuring.

## Images and Alt Text

Every image must have alt text that describes the image's content or purpose: `![Flow diagram showing data moving from input to output](assets/data-flow.png)`.

Use empty alt text (`alt=""`) only for decorative images that add no informational value. Screen readers skip empty-alt images entirely.

Store images in a dedicated assets or images directory. Use lowercase kebab-case filenames. Avoid generic names like `screenshot.png` or `image1.jpg`.

## Markdownlint Compliance

Run `markdownlint` (or `markdownlint-cli2`) on all Markdown files before committing. Address all warnings — common violations include trailing spaces, missing blank lines around headings, and inconsistent list marker style.

Configure a `.markdownlint.json` or `.markdownlint.yaml` at the repo root to establish project-wide rules. Shared configuration prevents rule drift across contributors.

Do not disable rules inline without a documented reason. If a rule fires repeatedly on legitimate content, adjust the project configuration rather than suppressing it per file.

## Document Length and Scope

Keep each Markdown document focused on a single topic. If a document grows beyond what fits on one screen without scrolling, consider splitting it into multiple focused files with a parent index.

Avoid orphaned documents with no inbound links. Every document should be reachable from an index or navigation file.
