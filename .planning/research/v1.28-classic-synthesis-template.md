# Phase <N> Classic-to-Go Synthesis

This artifact is mandatory before Phase <N> implementation plans are approved. It answers: **what specifically made the Classic behavior work, what does the current Go system do now, and what is the best architecture for Aether today?**

It is not a nostalgia checklist and not a second owner interview. Feature names are investigation headings; evidence and conclusions drive the implementation.

- **Operational outcome:** What work or decision did the system actually complete?

- **Non-goals:** What adjacent behavior is deliberately outside this phase?

## 4. Comparative synthesis matrix

For each meaningful mechanism, compare the alternatives rather than assuming restoration.

| Decision ID | Desired outcome/value | Classic mechanism | Current mechanism | Options considered | Selected disposition | Evidence and rationale | Safety/compatibility consequence |
|---|---|---|---|---|---|---|---|
| `SYN-01` | | | | `keep-current` / `restore-modern` / `replace-better` / `retire-with-proof` | | | |

Disposition meanings:

- `keep-current` — current Go already provides the best mechanism; improve visibility or integration only if evidence requires it.
- `restore-modern` — restore the Classic causal behavior or experience on the modern Go authority and safety model.
- `replace-better` — neither implementation is sufficient; build a demonstrated better interaction using current architecture.
- `retire-with-proof` — remove or leave retired only when the useful outcome has a proven successor or the owner explicitly approves losing it.
