## Traceability contract

During v1.28 roadmapping, each row must map to one evidence-backed outcome:

1. `restore-exact` — reproduce the Classic behavior exactly;
2. `restore-modern` — restore the experience while keeping the modern Go safety kernel;
3. `replace-better` — replace it only with a demonstrated better interaction;
4. `drop-owner-approved` — retire it only when the existing report supports that outcome or Callum resolves a genuinely unanswered conflict.

No `PENDING OWNER` row may be deleted or treated as dead code merely because the modern runtime has no caller. CAP IDs are frozen from the filtered order in the source JSON; that source retains the complete claim, old/current evidence, corrections, and skeptic status. Duplicate subjects such as `seal` are distinct source rows and therefore have distinct CAP IDs.
