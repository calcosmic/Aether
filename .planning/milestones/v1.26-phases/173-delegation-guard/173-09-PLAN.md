<objective>
Stop ghosts from progressively locking the colony out of spawning.

Purpose: SPAWN-08 names the harm precisely — an orphaned helper wastes money once, and then keeps
wasting it, because it holds a slot in the tree budget forever. As the run continues, the budget
fills with entries that will never finish and the colony can no longer spawn anything. D-15 wants
both an automatic reaper and an operator command; D-16 wants the reaper deliberately conservative,
because killing live work is worse than a ghost holding a slot for a while — the failure modes are
not symmetric; D-17 makes the threshold configurable, the one place in this phase a knob is
warranted; D-18 requires reaping to actually release budget, or the whole thing is decoration.

Output: an `abandoned` status registered as terminal, a scan that only ever touches entries past a
generous configured threshold, an automatic call at run start, one operator command, and a budget
count that excludes abandoned entries.

Honesty constraint that governs every claim in this plan: there is no heartbeat. Nothing in this
system says "still working". Do not write, in code comments, output text or the summary, that the
reaper "detects abandonment". It detects that a configured elapsed time has passed with no
completion. That is the whole of what it knows.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Wall-clock elapsed time → a decision to mark another process's work dead | The only signal available; the process it judges may still be running |
| `SpawnReapThresholdMinutes` in colony state → reaping aggressiveness | An operator-editable value that directly controls how readily live work is killed |
| `spawn-orphans --clear` → mutation of the shared spawn tree | A manual command mutating state other processes are concurrently writing |
