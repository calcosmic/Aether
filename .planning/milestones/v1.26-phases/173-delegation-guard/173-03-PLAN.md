<objective>
Invert the one delegation guard this repo already knows fails in the wrong direction.
`spawn-can-spawn-swarm` currently answers "yes, you may spawn, and you have 5 budget left" when
it cannot read the colony state at all — the exact defect D-19 and ROADMAP criterion 4 name by
file and line.

Purpose: a guard that cannot read its own data and says yes is worse than no guard, because it
reports a checked answer. ROADMAP criterion 4 requires *every* delegation guard to deny on
unreadable state. This plan closes the one that is already known broken; plan 10 proves the
property holds across all of them together.

Output: a fail-closed swarm guard plus fault-injection tests that go red if it ever fails open
again.

Scope note: this plan does not merge `spawn-can-spawn-swarm` into `spawn-can-spawn`. RESEARCH.md
Pitfall 5 is explicit that they are separate, currently-divergent paths and that
`spawn-can-spawn-swarm` has no real caller today, so merging would change an unobserved code
path with no downstream flow to notice. Fixing in place is the narrower, safer scope.
</objective>
