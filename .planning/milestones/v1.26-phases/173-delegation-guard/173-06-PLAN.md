<objective>
Catch the loop depth cannot see: a caste spawning a helper to do the work it was itself spawned to
do, one level down, repeatedly.

Purpose: an A to B to A chain never exceeds the depth cap — each hop is only one level — and it
never terminates on its own. A spawn tree cannot contain a literal cycle (each entry names one
parent and is written once), so the hazard is *repetition* along the ancestor chain, not a graph
cycle. SPAWN-05 requires the runtime to detect that repetition and name the ancestor it matched.

Output: the body of `spawnAncestorCycleReason`, whose contract plan 04 already wired into the one
decision function, plus a normalisation function small enough to test on its own.
</objective>

  <action>
Fill `cmd/spawn_ancestor.go`. Delete the `CONTRACT-STUB-PLAN-06` marker comment.

Write `func normalizeSpawnTask(task string) string`, a small pure function with these rules and no
others, so it can be reasoned about and tested exhaustively:
- lowercase the whole string;
- replace every run of Unicode whitespace with a single space;
- strip leading and trailing spaces;
- strip a trailing full stop;
- collapse nothing else. Do not stem, do not remove stop words, do not strip punctuation beyond
  the trailing full stop, and do not truncate. Every additional transformation widens the set of
  distinct tasks that collide, which turns a cycle guard into a false-positive generator.

Write `func spawnAncestorChain(st *agent.SpawnTree, startName string) ([]agent.SpawnEntry, error)`
returning the requester's own entry followed by each ancestor up to the root, nearest first:
- Parse once with `st.Parse()`; walk the returned slice in memory, never re-parsing per hop.
- Start at the entry whose `AgentName` matches `startName`, taking the latest such entry.
- Follow `ParentName` upward. Stop when the parent name matches `spawnParentIsRoot`, when no
  entry matches the parent name, or when the number of hops reaches a hard limit of
  `spawnMaxDelegationDepth + 2`. That hop limit is a defensive termination bound against a
  corrupted or hand-edited tree containing a self-referential parent link; a plain visited-set is
  also acceptable and preferable if it is simpler — use one or the other and say which.
- If `st.Parse()` errors, return the error.
- If `startName` resolves to no entry AND is not a root sentinel, return an error naming it.

Write the body of `spawnAncestorCycleReason(in spawnDecisionInput) string`:
- If `in.RequesterName` is empty or is a root sentinel, return the empty string. The coordinator
  has no ancestors, so there is nothing to repeat.
- Build the tree and call `spawnAncestorChain(st, in.RequesterName)`. On error, return a deny
  reason of the form `ancestor chain unreadable (<err>): refusing to spawn` — D-19 fail-closed.
  Do not return empty on error.
- Compute `normalizeSpawnTask(in.Task)` once. For each ancestor in the chain, compare its `Caste`
  case-insensitively against `in.Caste` and `normalizeSpawnTask(ancestor.Task)` against the
  computed value. On the first match, return a deny reason of the form
  `<in.Caste> was already asked to do this task by <ancestor.AgentName> at depth <ancestor.Depth>; spawning it again would repeat work already in progress above`.
  D-10 requires the ancestor to be named, so the ancestor's own name must appear in the string.
- If no ancestor matches, return the empty string.

Two things this function must not do: it must not consider siblings or unrelated branches (only
the chain from the requester upward), and it must not deny on caste alone. Two different tasks for
the same caste in one chain is ordinary delegation.
