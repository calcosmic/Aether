platform — not the model — appends a `<usage>` block to the session transcript for every
`Agent`/`Task` dispatch. The Go runtime reads that file itself, so no number ever passes through
the orchestrating LLM's hands (D-06).

shapes, and tests asserting literal figures plus every refusal path.

    Create `cmd/wrapper_usage_claude.go` in package `cmd` with:

    - `const claudeTranscriptMaxBytes = 32 << 20` and `const claudeTranscriptMaxLineBytes = 2 << 20`,
      documented as the T-174-02 resource-exhaustion bound, citing `internalWorkerRequestMaxBytes`

    Implementation shape:

    Validate `path` with `validateSpendTranscriptPath` before opening it and return its error
    unchanged — the transcript path is an untrusted file-read target (T-174-01) even though the
    platform normally supplies it.

    Open with `os.Open`, wrap in an `io.LimitReader` bounded by `claudeTranscriptMaxBytes`, and
    scan with `bufio.Scanner` whose buffer is sized to `claudeTranscriptMaxLineBytes`. Never call
    `os.ReadFile`. When `scanner.Err()` reports `bufio.ErrTooLong`, skip that line and continue
    rather than aborting the parse.

    Make two passes over the collected lines in one scan:

    Pass A — build a map from `tool_use` id to description. A line qualifies only when the decoded
    JSON structurally contains a `tool_use` block with a non-empty string `id` and a string
    `input.description`. Handle both a top-level object of `type` `"tool_use"` and a `message`
    object whose `content` array holds `tool_use` entries, because both shapes appear in real
    transcripts; decode into `map[string]interface{}` and walk it defensively rather than binding
    a rigid struct.

    Pass B — collect usage blocks:
      - Foreground: a `tool_result` whose `tool_use_id` is a non-empty string, whose
        `content` array's first element has a string `text`. Extract the usage block only from
        inside that `text` value.
      - Async: a line whose decoded `type` is `"queue-operation"` and whose `content` is a string.
        Extract `<tool-use-id>` and the usage block only from inside that `content` value.

    In both cases the id is read from a structural field or from the `<tool-use-id>` element
    inside content Go itself decoded — never by scanning the raw file for `<usage>`. Add a comment
    naming T-174-03 and stating that a raw substring search across the whole file is forbidden
    because a worker's own task text can legitimately contain the literal `<usage>`.

    Add `func parseClaudeUsageBlock(text string) (tokens int64, toolUses int, durationMS int64, ok bool)`
    handling both the plain `key: value` form and the XML `<key>value</key>` form for
    `subagent_tokens`, `tool_uses` and `duration_ms`. Return `ok == false` when `subagent_tokens`
    is absent or unparseable.

    Correlate to Aether workers: for each resolved id, look up its description from pass A and
    match the first `workerNames` entry that appears in the description as an exact substring
    bounded by a non-word character or the string edges (so `Mason-6` never matches `Mason-67`).
    Skip any id with no description and any description matching no known worker name. Discard any
    resolved entry whose worker name is empty. Never fall back to fuzzy or best-effort matching —
    an unresolved dispatch must produce no entry, so that plan 174-06's resolver reaches its
    estimate fallback rather than silently attributing someone else's tokens.

    Populate the returned `codex.WorkerUsage` with `TotalTokens` set to the parsed
    `subagent_tokens`, `Source` set to `codex.UsageSourceSessionTranscript`, and every disjoint
    column left at zero. Add a comment recording that Claude Code reports one aggregate figure

    exactly why `BilledTotalTokens()` prefers `TotalTokens` and why this source is not

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `spend/session.json` transcript path → `os.Open` | A recorded path used as a file-read target |
| transcript file bytes → parser | An unbounded, externally-written file containing arbitrary model and user text |
| transcript description text → Aether worker identity | The correlation step where one worker's cost could be attributed to another |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-174-01 | Tampering | `parseClaudeTranscriptUsage` path argument | mitigate | `validateSpendTranscriptPath` runs before `os.Open` in the same function; asserted by `TestClaudeTranscriptRefusesPathOutsideProjectsRoot` and by an ordering grep |
| T-174-02 | Denial of service | transcript file read | mitigate | `io.LimitReader` at `claudeTranscriptMaxBytes` plus a `bufio.Scanner` buffer capped at `claudeTranscriptMaxLineBytes`, with `ErrTooLong` skipping the line rather than aborting; asserted by `TestClaudeTranscriptToleratesMalformedAndOversizedLines` |
| T-174-03 | Tampering | usage-block matching | mitigate | Usage blocks are extracted only from a `tool_result` `content[].text` or a `queue-operation` `content` value that Go itself decoded, and the id comes from a structural field or a `<tool-use-id>` element inside that value — never a raw file scan. Asserted by `TestClaudeTranscriptIgnoresUsageTextOutsideAResultBlock` against the 999999 decoy |
| T-174-16 | Spoofing | worker-name correlation | mitigate | Matching requires the exact worker name bounded by non-word characters, and an unmatched id produces no entry at all rather than a best guess; asserted by the `Probe-04` case |
| T-174-17 | Spoofing | source tagging | mitigate | The file contains no reference to `UsageSourceProvider` at all; asserted by a grep returning 0 and by `TestClaudeTranscriptUsageIsNeverProviderTagged` |
| T-174-18 | Information disclosure | fixture contents | mitigate | The committed fixture is hand-written and redacted; asserted by a grep for real paths returning 0 |
</threat_model>
