<objective>
Do for OpenCode what plan 174-04 does for Claude Code — read the platform's own local session
store rather than trusting anything relayed — while respecting the one structural difference:
OpenCode has no hook, so the session must be discovered rather than delivered.

Purpose: CLAUDE.md's Platform Policy names Claude Code and OpenCode as the two maintained user
surfaces. Leaving OpenCode unmeasured would make every later efficiency claim platform-dependent
in a way nothing surfaces. OpenCode's data is also richer — it reports fully disjoint
input/output/reasoning/cache-read/cache-write columns, which is what SPEND-03 asks for.

Output: `cmd/wrapper_usage_opencode.go` plus a committed fixture store, with discovery bounded by
the repo worktree and the current run's time window and an explicit refusal on ambiguity.
</objective>

OpenCode has no `PreToolUse`-equivalent hook (confirmed in `.opencode/OPENCODE.md`), so no
platform channel delivers a session id. Discovery must match the project record's `worktree`
field against the repo root and bound candidate sessions to the current run's time window
(174-RESEARCH.md § "Pitfall 4").

The dispatch description convention is identical on both platforms and unchanged by this phase
(`.opencode/commands/ant/build.md`): `{caste emoji} {Caste} {name}: {task}` — which is why the
child session `title` already embeds the worker name.

Bounded-input precedent in package `cmd` (`cmd/internal_worker_adapter.go:22`):
`internalWorkerRequestMaxBytes = 2 << 20`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `$HOME/.local/share/opencode/storage` → file reads | An externally-written local store with no platform-delivered identifier to anchor on |
| session `title` text → Aether worker identity | The correlation step where a stale or similarly-named session could be misattributed |
| project `worktree` value → repo identity | The only structural signal binding a session store to this repository |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-174-01 | Tampering | `openCodeSessionUsageForRun` root argument | mitigate | `validateOpenCodeStoragePath` runs before any read, rejecting null bytes and relative paths and deciding containment under `$HOME/.local/share/opencode/storage` with `filepath.Rel`; asserted by `TestOpenCodeSessionUsageRefusesStorageRootOutsideHome` |
| T-174-02 | Denial of service | session/message directory scan | mitigate | Per-file byte cap `openCodeStorageMaxFileBytes` and a scan cap `openCodeStorageMaxSessionFiles`; malformed records are skipped, asserted by `TestOpenCodeSessionUsageToleratesMalformedRecords` |
| T-174-03 | Tampering | title-based correlation | mitigate | Matching requires the exact worker name bounded by non-word characters, and any worker with more than one in-window match resolves to nothing plus a diagnostic; asserted by `TestOpenCodeSessionUsageRefusesAmbiguousWorkerMatch` |
| T-174-19 | Spoofing | stale session read as current spend | mitigate | Candidate sessions must fall inside the caller's `[startedAt, endedAt]` window; the fixture's 999999-token stale decoy proves the bound holds, asserted by `TestOpenCodeSessionUsageIgnoresSessionsOutsideTheRunWindow` |
| T-174-20 | Spoofing | another repository's sessions | mitigate | Only projects whose symlink-evaluated `worktree` equals the symlink-evaluated repo root are considered; asserted by `TestOpenCodeSessionUsageIgnoresNonMatchingWorktree` |
| T-174-17 | Spoofing | source tagging | mitigate | The file contains no reference to `UsageSourceProvider`; asserted by a grep returning 0 |
