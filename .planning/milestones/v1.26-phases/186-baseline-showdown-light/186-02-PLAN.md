Write four task specs. Every spec uses the same section structure so the runner and the
acceptance scripts can read them uniformly:

`# Task <NN>: <name>` / `## Substrate` (which repo, which SHA) / `## The task` (the prompt text
handed to the system, verbatim) / `## Setup` (any preparation the harness performs before the
run, as exact commands) / `## Done means` (the observable end state, in plain English, with no
reference to how either system reports it) / `## Allowlist` (the path to the allowlist file) /
`## Per-lane invocation` (the three lanes' entry commands).

The `## The task` text is the single most important line in each file: it is the identical
prompt given to all three lanes. It must contain no word either system invented — no "phase",
"colony", "plan", "worker", "must-have", "criterion", "wave". Write it as one would brief a
human developer. Record the constraint explicitly in each file.

Task 01 — small bug fix with a seeded failing test. Setup: apply a small patch to the Go
substrate repo that introduces one genuine defect and adds one test that fails because of it.
The seeded test must fail before the run and pass after a correct fix; record the exact seeded
test name and the command that runs just it. The prompt says a named test is failing and asks
for it to pass without changing the test.

Task 02 — brownfield feature touching several files. Against the TypeScript substrate repo.
The feature must genuinely require edits in at least three existing files (name the expected
files in `## Done means` as observable end state, not as instructions to the system). Do not
pick a feature that a single-file change satisfies — the category exists to expose multi-file
coordination.

Task 03 — interrupted execution. Runs the Task 01 prompt against the Go substrate, but under
the kill rule: the harness watches the substrate clone and, at the moment of the first file
write inside it, starts a 120-second timer; when the timer expires the harness sends SIGKILL to
the system's process group. The operator then issues exactly one documented resume command and
nothing else. Record the resume command per lane: for the GSD lane the documented GSD resume
command; for the two Aether lanes `/ant-resume` followed by the runtime's named recovery
command (`/ant-recover`) — verify against `.claude/commands/ant/resume.md` and
`.claude/commands/ant/recover.md` that both exist and record their real names, do not guess.
State that the kill rule is identical across lanes by design, and that any second operator
input after the resume command counts as an unscripted intervention.

Task 04 — fresh-repo full lifecycle. Starts from an empty git repository, not a substrate
clone. For the Aether lanes: install, `/ant-init`, the full cycle, `/ant-seal`. For the GSD
lane: new-project setup then the phase cycle. Because the lanes' lifecycles genuinely differ,
this spec's `## The task` is the same product goal for all three (a small, self-contained
program with a stated behaviour and its own tests), and only `## Per-lane invocation` differs.
Additionally record the extra assertion CONTEXT.md's Specifics block requires for this category:
after an Aether-lane run, `git status --porcelain` in the Aether source repo itself must be
empty — Aether must not have modified itself while working on someone else's project.

Every `## Done means` section must be phrased so that a script can check it without asking
either system whether it succeeded. If a criterion can only be confirmed by reading the
system's own report, rewrite it.

  <action>
Create `bench/tasks/allowlists/` containing one file per task, named to match the task spec
(`01-bug-fix.txt`, `02-brownfield-feature.txt`, `03-interrupted-execution.txt`,
`04-fresh-repo-lifecycle.txt`).

Each file is a plain list, one glob pattern per line, of the repository-relative paths a
correct solution to that task is permitted to create or modify. Lines beginning with `#` are
comments and are ignored by the consuming script. Patterns are shell globs matched against
`git diff --name-only` output.

Rules that make the count meaningful:
- The allowlist is derived from the task's `## Done means`, not from what a system happened to
  touch. Write it before any run.
- Each allowlist must include the lane's own legitimate working state as a separate,
  clearly-commented block, because those paths are not unnecessary modifications — they are the
  system doing its job. For the Aether lanes that is `.aether/**`; for the GSD lane that is
  `.planning/**` and `.claude/**`. Mark this block with the comment
  `# lane working state — not counted as unnecessary` so the git-cleanliness checker (plan 03)
  can treat it differently from the task-content block.
- Include the task's own test/build artifacts only where the repo's own conventions commit them;
  otherwise leave them out so a system that commits build output is correctly counted.
- Do NOT add a catch-all pattern. An allowlist containing `*` or `**` alone would make the
  unnecessary-modification metric always report zero, which is the same failure shape as this
  repo's "fewer than 27 castes loaded" criterion that passed without proving anything.

Add a header comment in each file naming the task it belongs to and the one-line rule: any
changed path not matching a pattern here is counted as an unnecessary modification.
  </action>
