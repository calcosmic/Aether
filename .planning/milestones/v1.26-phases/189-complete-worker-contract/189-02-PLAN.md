the same colony-wide context build's external dispatches already carry -- a context capsule and
active pheromone signals -- and the same handoff/return schema statement Plan 189-01 added to

(`cmd/codex_continue_plan.go:14-67`) carry neither a capsule field nor a pheromone field anywhere --

in this file). `SkillSection` exists and is populated, but no wrapper instructs its delivery either:

each dispatch's runtime-provided `brief` verbatim" -- no capsule, no skill, no pheromone. Continue's
OWN native/internal dispatch path (`plannedContinueReviewDispatches`,
`plannedContinueWatcherDispatch`) already carries all of this; only the external/wrapper path lags.

sections, and the wrappers (all three platforms, parity-tested) instruct their delivery") and
criterion 2's continue half (continue's finalizer, `mergeExternalContinueResults`, enforces the
identical handoff schema build's finalizer does -- confirmed by reading -- so criterion 2's fix
belongs here too, reusing Plan 189-01's exported constant rather than a third hand-copied sentence).

Output: two new manifest-level fields, a duplication-safe handoff-schema append on every external
dispatch's brief, and a byte-identical three-file wrapper instruction update plus a small doc-
accuracy fix to `.codex/CODEX.md` -- each proven by an executable test, not by prose alone.
