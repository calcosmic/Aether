<objective>
Make `worktree-merge-back` work outside Go repositories, and make it refuse safely when
it cannot tell how a project is tested.

Today `cmd/worktree.go:751` hard-codes `exec.CommandContext(testCtx, "go", "test", "./...")`.
In a Node, Python or Rust project that command fails, the gate can never pass, and work
never merges back. Meanwhile `resolveTestCommand()` (`cmd/gate.go:244`) has answered this
exact question — CLAUDE.md, then `.aether/data/codebase.md`, then a language sniff — since
the gate was written. `cmd/verification_command_section.go:10-15` carries a comment
recording that this same "resolveTestCommand exists but nobody calls it" oversight has
already happened once in this codebase.

Purpose: ROADMAP criterion 2, half one. D-03 governs the empty-resolver case: refuse to
merge, say why, and never destroy the work you declined to merge.

Output: `cmd/worktree.go` merge gate rewired; new `cmd/worktree_merge_gate_test.go` with
non-Go fixtures. This plan touches only the CLI command; the build-path duplicate,
`mergePhaseWorktrees` in `cmd/codex_build_worktree.go`, is fixed by `187-04-PLAN.md`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Project config (CLAUDE.md, package.json) → executed command | `resolveTestCommand()` reads a command string out of repository files and Aether then executes it. |
| Unverified worktree branch → user's main branch | The test gate is the only thing standing between unreviewed worker output and `git merge` into main. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-187-05 | Elevation of Privilege | Test command string from CLAUDE.md executed by Aether | accept | Pre-existing and unchanged: `resolveTestCommand()` already feeds `checkTestsPass` and the verification section. The string comes from the user's own repository, which the user already controls and which Aether already builds and tests. Splitting with `strings.Fields` into `exec.CommandContext(argv[0], argv[1:]...)` avoids adding a shell, so this change does not widen the surface. |
| T-187-06 | Tampering | Unverified code merged into main because the gate passed vacuously | mitigate | D-03: an empty resolver result refuses the merge rather than skipping the gate. Explicitly does NOT copy `checkTestsPass`'s pass-by-default branch. Asserted by `TestWorktreeMergeBackRefusesWhenTestCommandUnknown`. |
| T-187-07 | Denial of Service (data loss) | Refusal path falling through to Step 5's `worktree remove --force` / `branch -d` | mitigate | Early `return nil` before Step 5, asserted against real git by `TestWorktreeMergeBackRefusalPreservesTheWorktree`. |
| T-187-08 | Denial of Service | A slow non-Go test suite exceeding the 120s BuildTimeout now that non-Go projects are reachable | accept | Flagged and deferred by CONTEXT.md `<deferred>` (`cmd/timeouts.go:11`). Out of scope for this phase; note it in the plan summary so it is not lost. |
