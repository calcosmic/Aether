<objective>
Close CR-01, CR-02 and CR-03 — the three job-level and trigger-level routes that disable
the release gate while every guard in this phase stays green — with a **whitelist of
workflow shape**, not three more string searches.

Every previous attempt at this criterion added a check for a disabling route someone had
enumerated: first a whole-file substring test, then a step-scoped one, then step-level
`if:`/`continue-on-error` plus trigger presence. Each was defeated by the adjacent sibling
of the thing it checked. A blocklist must anticipate the attack; a whitelist does not. So
this plan asserts that the workflow's root keys, the `go` job's keys, the trigger names,
each trigger's own keys, and the two gate steps' keys are **exactly a reviewed set declared
in Go source**. `continue-on-error`, `env`, `paths-ignore`, `if`, and every future sibling
nobody has thought of fail because they are *not on the list*, not because they were
individually named. Adding one is then a visible diff to a named slice in a code review.

Purpose: this is a complement to plan 172-10's execution harness, never a replacement.
172-10 proves the extracted command discriminates; this proves the workflow reaches that
command with an unmodified environment. Both are needed and both stay.

Scope note — one round-3 warning is folded in deliberately because it is inseparable from
CR-02: **WR-04's comment half**. `runGateCommand` leaves `cmd.Env` nil, so the harness
inherits the *local* environment and can never observe a `GOFLAGS` declared in the
workflow. Two doc comments in this file currently tell a future reader that the execution
proof catches "whatever the sixth mutation turns out to be" and that the equality pin is
"NOT the proof". After this plan the key whitelist is the only thing standing between a
workflow-declared `GOFLAGS` and a green build, and the source must say so plainly rather
than imply coverage it does not have. Nothing else from WR-01..WR-14 is in scope.

Output: one YAML-parsing shape audit, one live-workflow assertion, one hermetic
generality table that proves an *unenumerated* key is rejected, and corrected comments.
</objective>
