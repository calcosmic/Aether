# Phase 191.1 Plan 04: Code Review Remediation Summary

**Closed all three blockers and three warnings from the 191.1 code review: covered_task_ids credit now requires an evidenced, identifiable claimant; a preserved continue-advance replay now refuses when the workspace changed underneath it; the out-of-band ceremony advances before it seals; passing verification checks report real per-run content; a legitimate same-name retry no longer self-conflicts; and the out-of-band ceremony refuses malformed bound criteria the same way `aether continue` does.**

## Accomplishments

- **BLOCKER 1 (CR-01) closed:** `mergeExternalBuildResults` now refuses `covered_task_ids` credit unless the claiming worker's own result is a genuine success (`completed`/`manually-reconciled`), carries real file-change evidence, and corresponds to a real dispatch in the manifest. Before this, a `failed` worker with zero evidence — or a completely fabricated worker name matching no dispatch anywhere — could grant full `completed` credit to a task it never touched, durably written into `COLONY_STATE.json`.
- **BLOCKER 2 (CR-02) closed:** a preserved continue-advance payload is now bound to a content-sensitive workspace fingerprint (git HEAD + diff + status) captured at preserve time, re-checked at replay time. Real work landing on disk between preserve and replay (a hand edit, a pair session) now causes the stale record to be discarded, falling through to ordinary fresh verification, instead of being silently replayed against a workspace that no longer matches.
- **BLOCKER 3 (CR-03) closed:** `closeOutOfBandCeremony` now calls `advancePhase` before closing (sealing) the build attempt, not after. A currency refusal (e.g. the colony is paused) no longer leaves the build attempt irreversibly sealed (`Recoverable:false`, `RecoveryCommand:""`) with the phase never having advanced — the exact "stuck, no honest exit" shape this ceremony exists to close.
- **WARNING 1 (WR-01) closed:** a passing verification check's evidence line now carries the real exit code and a trailing line of actual command output, mirroring the failure branch's already-correct pattern, instead of a hardcoded per-check-name constant that was identical across every run.
- **WARNING 2 (WR-02) closed:** the `covered_task_ids` duplicate-claim pass now iterates the same name-deduplicated map the main dispatch loop already computes, so a worker's legitimate same-name retry resubmission (timeout, then completed, both claiming the same credit) no longer trips a duplicate-claim violation against itself.
- **WARNING 3 (WR-03) closed:** the out-of-band ceremony's bound-criteria evaluator now calls the same structural validator `aether continue`'s evaluator calls first, so a malformed requirement (no artifacts, no checks — reachable only via a hand-edited or migrated `COLONY_STATE.json`) is refused instead of vacuously passing.
- Every fix is backed by a regression test built from the review's own reproduction, run fail-then-pass: each test was confirmed failing against the pre-fix code (exact failure output quoted below) before its corresponding fix was applied.
