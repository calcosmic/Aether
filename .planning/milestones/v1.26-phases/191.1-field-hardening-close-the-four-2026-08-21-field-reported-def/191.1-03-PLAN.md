<objective>
Close FIELD-05 from `.planning/phases/191.1-field-hardening-close-the-four-2026-08-21-field-reported-def/191.1-CONTEXT.md`:
an owner-invoked, out-of-band reconciliation ceremony for the scenario
`.planning/todos/pending/2026-08-21-no-reentry-path-for-out-of-band-work.md` documents from a live colony --
real work done by hand outside the dispatch pipeline, with no honest way back in. The runtime correctly refuses
to fabricate worker receipts for work no worker did; it has never had a way to say "I re-checked this myself,
right now, against the real success criteria, and it holds."

This plan builds that door without removing the wall: a new, explicitly-named, operator-only command that
re-verifies CURRENT disk state fresh (real shell commands, real artifact content hashes -- the same evidence
primitives continue already trusts, per 191.1-CONTEXT.md D-10), and on success closes the stuck work citing that
verification -- never a synthetic worker dispatch. Two ratchets lock the two properties that make this safe to
ship: it can never run automatically (191.1-PATTERNS.md Pattern 3), and it can never fabricate a worker receipt
(191.1-PATTERNS.md Pattern 4).

Purpose: three independent downstream repos dead-ended on this exact gap in one day; the source todo calls it
a "dead end by design collision" -- the honesty rules correctly blocking the only routes offered, with no honest
route left open.
Output: one new command; one new provenance record shape; two ratchet tests.

      `Source: "verify-out-of-band"`, with no attempt record created or required.

      executor's choice; must be distinct from `--force` alone) -- and when refusing, prints the phase's prose
      success-criteria text plainly so the operator can see exactly what they are being asked to confirm. With
