## Decisions Made

See `key-decisions` in frontmatter above for the full list. Most significant:

- **Pre-pass over in-loop mutation for covered_task_ids resolution.** The plan's action item 2 described inserting the crediting logic inline, "before the `dispatches[i] = dispatch` write." Implemented literally, this would fail: `mergeExternalBuildResults`'s main loop unconditionally executes `dispatches[j] = dispatch` (the raw, uncredited manifest dispatch) at the top of every iteration `j`, including iterations that run *after* the covering dispatch's own iteration credited them. A same-loop, same-pass credit would be silently overwritten the moment the loop reached the credited index on its own turn, and that iteration would then also wrongly re-append a `violationRuleResultMissing` violation for a dispatch that was supposed to be covered. Resolving every result's `covered_task_ids` into a `coveredBy` lookup *before* the main loop starts, and having the loop's existing "missing result" branch consult that lookup, is what makes a covered dispatch never see a missing-result violation in the first place -- correctly, regardless of whether the covering worker's own dispatch sits before or after the covered ones in manifest order. This satisfies the plan's specified behavior exactly; only the code's internal structure differs from the literal phrasing.
- **No change needed to `cmd/codex_build.go`.** The plan's interfaces block asked this to be confirmed with a test rather than assumed. `TestWrapperBundledWorkerCreditsAllCoveredTasks` part (b) runs the full `runCodexBuildFinalize` path and confirms all 3 tasks end `colony.TaskCompleted` purely from `mergeExternalBuildResults` setting `Status = "completed"` on the credited dispatches -- the existing `reconcileCompletedBuildTasks` -> `completedBuildTaskIDs` -> `dispatchCoveredTaskIDs` chain already picks it up.
