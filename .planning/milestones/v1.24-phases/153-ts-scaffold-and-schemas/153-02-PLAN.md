## Schema requirements (from REQUIREMENTS.md)
- SCHEMA-01: Agent schema validates id, role, prompt_file, allowed_tools (array), plus existence of referenced prompt file
- SCHEMA-02: Phase schema validates id, entry_agent, required_agents, inputs, outputs, success_criteria, failure_policy, ceremony
- SCHEMA-03: Event schema validates NDJSON event shape (type, timestamp, payload)
- SCHEMA-04: Policy schema validates model-routing, memory-rules, skill-creation, safety-gates

## Research patterns (from 153-RESEARCH.md)
- Pattern 1: Zod Schema with File Existence Validation — use superRefine, not refine, to emit multiple issues
- Pattern 2: NDJSON Event Schema — validate line-by-line, reject empty lines
- Pattern 3: YAML Fixture Testing — readFileSync + yaml.parse + schema.parse
- Pitfall 2: YAML null vs undefined — use .transform((v) => v ?? undefined) or z.union([z.string(), z.null()]).optional() for optional fields
- Pitfall 3: Relative path resolution from wrong cwd — always resolve against projectRoot (from tests/helpers.ts)
- Pitfall 4: NDJSON embedded newlines — split on \n and validate each line independently

## Security threats (from 153-RESEARCH.md)
- T-153-01: Path traversal in prompt_file — resolve against projectRoot, reject .. segments
- T-153-02: YAML bomb — fixtures are small and trusted; use yaml package defaults
- T-153-03: Malformed NDJSON — per-line JSON.parse with try/catch
