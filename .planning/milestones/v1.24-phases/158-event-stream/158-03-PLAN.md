<objective>
Build the cross-platform event bridge that lets Go and TypeScript share the same NDJSON event stream. This plan creates bridge stubs on both sides that demonstrate concurrent read/write capabilities without actual cross-process communication.

Purpose: The bridge is the proof that both platforms can coexist on the same event stream. In production, Go and TS will write to `.aether/events/current.ndjson` independently. Clean interfaces matter more than implementation depth.
Output: TS bridge, Go bridge, tests, and the events directory.
</objective>

### Task 1: TypeScript Event Bridge

Create `control-ts/src/events/bridge.ts` with:

- `syncEventsWithGo(eventStreamPath)` — async function that sets up a watcher on the event stream (uses fs.watch or polling in stub mode)
- `readGoEvents(eventStreamPath)` — async generator that yields events written by Go (reads from the shared file)
- Demonstration function that writes a TS event, reads Go events, and confirms format compatibility
- Exports for all public functions

### Task 2: Go Event Bridge

Create `cmd/event_bridge.go` with:

- `SyncEventsWithTS(eventStreamPath)` — sets up a watcher on the event stream (uses fsnotify or polling in stub mode)
- `ReadTSEvents(eventStreamPath)` — returns a channel that yields events written by TypeScript
- Demonstration function that writes a Go event, reads TS events, and confirms format compatibility
- Exports for all public functions

### Task 3: Events Directory

Create `.aether/events/.gitkeep`:

- Ensures the events directory is tracked by git
- This is where `current.ndjson` will live in production

### Task 4: Bridge Tests

Create `control-ts/tests/events/bridge.test.ts`:

- Test that TS can write events and Go (simulated) can read them
- Test that Go (simulated) can write events and TS can read them
- Test format compatibility (same JSON shape from both sides)
- Test concurrent access (both sides writing at the same time)
- Test event ordering (timestamps reflect actual order)

Commit each task individually.
