<objective>
Build the NDJSON event stream stubs in the TypeScript control plane. These stubs define the event types, write operations, and read operations that let the TS side emit and consume structured events. No actual file I/O to `.aether/events/current.ndjson` happens in this phase — the stubs simulate the behavior with in-memory or mock file operations.

Purpose: The event stream is the shared observable truth between Go and TypeScript. Both sides must agree on the NDJSON line format. Clean interfaces matter more than implementation depth — the Go runtime will eventually write to the same file.
Output: Event types, write stub, read stub, barrel export, tests, and public API exports.
</objective>

<tasks>

### Task 1: Event Types

Create `control-ts/src/events/types.ts` with:

- `EventType` enum or union: `phase_start`, `agent_selected`, `task_planned`, `worker_spawned`, `tool_call`, `verification_result`, `memory_update`, `run_seal`, and `custom`
- `EventPayload` interface: a discriminated union where each event type has its own payload shape
- `EventLine` interface: `{ type: EventType; timestamp: string; payload: EventPayload }`
- `createEventLine(type, payload)` helper that injects the current ISO timestamp
- Type exports for all public types

### Task 2: Event Writer

Create `control-ts/src/events/writeEvent.ts` with:

- `writeEvent(streamPath, eventLine)` — async stub that simulates appending a JSON line to a file (returns Promise<void>, logs to console in stub mode)
- `createEventStream(streamPath)` — factory that returns a `{ write(eventLine), close() }` object
- Both functions accept a file path but in stub mode they write to an in-memory buffer or console

### Task 3: Event Reader

Create `control-ts/src/events/readEvents.ts` with:

- `readEvents(streamPath)` — async generator that yields `EventLine` objects (stub reads from in-memory array or mock file)
- `tailEvents(streamPath, options?)` — async generator that yields new events as they arrive (stub simulates with a polling interval or event emitter)
- Both functions return AsyncIterable<EventLine>

### Task 4: Barrel Export and Public API

Create `control-ts/src/events/index.ts`:

- Re-export all public types and functions from the events module
- Update `control-ts/src/index.ts` to export event symbols

### Task 5: Tests

Create `control-ts/tests/events/events.test.ts`:

- Test `createEventLine` produces correct shape with timestamp
- Test `writeEvent` returns successfully
- Test `readEvents` yields parsed events
- Test `tailEvents` yields new events
- Test round-trip: write then read returns the same events
- Verify NDJSON format (one JSON object per line, no trailing commas)

Commit each task individually.
