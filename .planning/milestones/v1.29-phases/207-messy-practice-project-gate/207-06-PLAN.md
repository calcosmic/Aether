  <what-built>
A practice project deliberately full of the kinds of mess real projects have — a shortcut to
a folder, a shortcut that loops back on itself, two names that differ only by capital
letters, a project tucked inside another project, very long folder names, an out-of-date map
of the code, a description corrected halfway through planning, leftover junk, and unsaved
work — built from nothing by a committed script, then walked all the way through by a real
chat: starting a project, surveying the code, discussing it, writing the description,
planning twice, building, checking, pausing, picking back up, finishing, filing it away, and
starting again. Three times over. It checks which files appeared and which commands genuinely
ran, never what the chat said about itself.

Then each of five problems from the bad day was deliberately broken again, one at a time, in
a throwaway copy — and each time the walk stopped at exactly the point that problem hurt.
  </what-built>
  <how-to-verify>
Read the plain-English summary printed at the end of the run — not the report file, not the
test output. It says:

  1. How long the three walks took and, where the tool reports it, what they cost.
  2. Each of the five problems from that day in everyday terms: the one where a folder could
     not be written to; the one where two saved names clashed because of capital letters; the
     one where a helper was asked for something it cannot produce; the one where planning was
     stuck on an out-of-date description; the one where saving your place broke on a shortcut
     to a folder. Each line says whether breaking that fix again made the walk stop there.
  3. The sixth problem — the status screen telling you to run something that is not on the
     menu — has no fix yet. Its check is built and is still failing on purpose. The next phase
     fixes it. Five proven, not six, exactly as you ruled.
  4. What changes for you: before anything is released, this walk runs, and a release does not
     go out if the walk gets stuck.

Then answer one question: is this the check you want running before every release, or do you
want it smaller or bigger? The three real options, with the cost of each and a recommendation,
are printed with the summary — keep three walks, drop to one to save time and money, or also
re-break the five problems before every release rather than only occasionally.
