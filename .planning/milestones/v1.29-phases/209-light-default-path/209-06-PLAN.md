<the_gap>
Measured on 2026-09-24, run 4 of `.planning/phases/209-light-default-path/209-TIMING.md`:
a real unattended `claude` session was given the medium job through `/ant-go`. It printed the
planning-route screen, said real dispatch needs a live helper-sender, and **asked the owner**
whether to "just build it" or "use Aether". It only completed after a human replied.

**Why.** `/ant-go`'s wrapper currently hands off with one sentence:

> Run the planning route with the default preset already named for this door
> (`aether plan --preset fast $ARGUMENTS`) so it never puts a depth question to the owner,
> then build the accepted plan, then tell the owner the one command to check the result.

`/ant-plan`'s own wrapper (`.claude/commands/ant/plan.md`, 281 lines) shows what actually
starting planning takes: `aether host plan` to get a dispatch manifest, `aether ceremony
spawn-plan` to render the spawn screen, dispatching a real Scout worker, `aether spawn-log` /
`aether spawn-complete`, `aether plan-finalize --completion-file`, the iteration card, the
candidate review, and finally the exact `aether plan --accept-candidate` command with its
issued bindings.

`aether plan --preset fast` is not that entry point and produces no dispatch manifest. So the
single door asks an assistant to do 281 lines of work it has not been told how to do, and the
assistant does the only sensible thing left: it asks.

**Why the existing test cannot see it.** `TestGoalReachesBuiltWorkWithNoExtraSteps`
(`cmd/go_default_path_test.go:190`) builds a fixture repository and drives the Go runtime
directly with the planning stage faked already-accepted. It never opens a wrapper file. The
gap is entirely in wrapper text, so that test passes while the real thing fails — the exact
false-certificate shape this project's Definition of Done exists to stop.
</the_gap>
