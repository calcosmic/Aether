telling the owner two things that are not true.

sentence carrying a planning-decision code and a planning filename onto the owner's screen.

decision function covering each gate on its own; a notice that says only what actually happened, in
words an owner can read; and both of the verification's exact mutations confirmed to turn the suite
red and then restored.

file also call `refuse(...)`, which is precisely what let a second decision planted in a file that
only ever receives an already-built refusal sail through. Say in the guard's doc comment that the
list may shrink but must not grow without an owner ruling, and restate honestly what the guard still

Two wording defects, each closed with a test that fails on the current wording.

**Stop claiming a command has run when it has not.** The notice currently reports, in the past
tense, that Aether carried out the named command on the owner's behalf. On the direct lane that is
true; on the plan-only lane it is not — there, the decision only sets the force option and the
function goes on to build a plan a host will later dispatch surveyors from, so nothing has been
re-surveyed at the moment the sentence prints. Replace the claim with one that is true of both lanes
at the moment it is printed: that Aether is going ahead and rebuilding the map of the code rather
than stopping to ask. Keep the command name visible as supporting evidence if you want it there, but
it must read as evidence, not as the claim. Do not solve this by passing a lane flag around unless
the single shared sentence genuinely cannot be made true for both lanes; if you do pass one, it
comes from the two call sites in `cmd/codex_colonize.go` and nowhere else, and the SUMMARY says why
the shared sentence was not enough.

**Stop printing internal bookkeeping to a person.** The stored sentence embeds a planning-decision
code and a planning-directory filename, and it is handed unmodified to the renderer, which prints it
on the owner's screen. Split it: the developer-facing rationale and the decision citation move into
a Go comment sitting directly above the row, where a future reader still finds them; what stays in
the table is a short sentence an owner can read, which translates any word this project invented in
the same breath it uses it. Say in the table's doc comment that whatever is stored there is printed
verbatim to a person, so a future row cannot reintroduce this by accident.

**Lock both with tests that fail on today's wording.** Add
`TestSelfRecoveryNoticeSaysOnlyWhatActuallyHappened`, asserting against the rendered notice that it
makes no past-tense claim that the named command has already been carried out, and that whatever it
does claim is true on the plan-only lane. Add `TestSelfRecoveryNoticeSpeaksPlainEnglish`, asserting
the rendered notice carries no planning-decision identifier, no planning-directory path or filename,
and no invented word left unexplained — reusing whatever predicate the existing voice tests already
use for the last of those rather than writing a second, competing definition of plain English. Both
tests read the notice from the renderer, never from a copy of the string.

**Fix the lucky assertion while you are here** (WR-07). The existing visual-mode assertion in the
end-to-end test passes if the command string appears anywhere in colonize's output. Anchor it on the
notice itself as well — its own banner heading and its no-one-is-here line, both read from the
renderer rather than retyped — so the test cannot pass on unrelated output that happens to mention
the same command.

Deliberately out of scope this round, and say so in the SUMMARY rather than drifting into them:
WR-01 (making the decision function physically carry out the recovery instead of announcing it),
WR-05 (a future opt-in row on a command classified quiet would recover invisibly) and WR-06 (the
