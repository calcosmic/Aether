  <behavior>
    - For each of the five finalizer result maps, every top-level key is either read by at least one render function reachable from that workflow's screen, or listed in the exception file with a reason.
    - A key added to a finalizer result map and read by nothing fails the test, naming the key and its finalizer.
    - A key removed from the exception file while still unrendered fails the test.
    - The exception file's every entry carries a non-empty reason and the name of the finalizer it belongs to; a blank reason fails the test.
    - The result maps under test are produced the way the runtime produces them, not typed as literals into the test.
  </behavior>
  <action>
Write `cmd/rendered_fields_invariant_test.go` containing
`TestRenderedVisualsShowEveryCarriedField`.

1. Enumerate the top-level keys each finalizer actually writes. Derive them by building each
   result map through the runtime's own assembly path with a seeded fixture and reading the
   keys off the produced map — never by typing a key list into the test, which would go stale
   the moment a finalizer changes and would turn the invariant into a false certificate.

2. Enumerate the keys the render side reads. Parse the render sources with go/ast and collect
   every constant string index expression on the result/raw map inside render functions
   (`result["x"]`, `raw["x"]`, and the helper functions those call). Follow the call graph from
   each workflow's entry renderer so a key read by a helper counts.

3. Assert set containment: carried keys minus read keys minus allow-listed keys must be empty.
   Report failures by naming the finalizer and the exact key, so the message says what is
   missing rather than that something is.

4. Create `cmd/testdata/rendered_field_allowlist.json` as a list of
   `{key, finalizer, reason}` entries. Seed it only with keys that are genuinely
   provenance-only or machine-only (for example the dispatch-mode and artifact-source
   provenance keys the plan finalizer writes for wrappers to read), each with a written reason
   saying why the owner does not need it. Every entry must be justified; an entry whose reason
   is empty fails the test.

5. This test must be able to fail. Prove it during execution by temporarily adding a throwaway
   key to one finalizer result map, observing the failure names that key, and removing it
   again. Record that observation in the plan summary.
  </action>
