<objective>
Make the checks visible while they run. Each of the four checks (build, types, lint, tests)
prints a starting line when it begins and a result line when it ends, on both ways of
running them, through the one append-only streaming channel.

Purpose: today the owner sees nothing for minutes and then a tally at the end. D-01/D-02
require two lines per check, live. Placing the hook inside `runVerificationStep` — the one
function `runDeterministicFloor` calls four times, and which both continue lanes reach — is
what makes the guarantee structural instead of a discipline.

Output: a measured `Duration` on `codexVerificationStep`, the start/finish emits, and tests
proving both lanes stream them.
</objective>

    - A check that is about to run emits one starting line naming the check in plain English before the command is executed.
    - A check that passed emits one finishing line carrying the check's name, a pass mark, its counts where the runner reports them, and its measured elapsed time.
    - A check that failed emits one finishing line carrying a fail mark and the step's own one-line summary inline, on the same line.
    - A skipped check emits a finishing line saying it was skipped and why, and does not claim a duration.
    - The elapsed time on the finishing line equals the value stored on codexVerificationStep.Duration for that same step.
    - With visual output disabled (JSON output mode), no live line is written at all.
