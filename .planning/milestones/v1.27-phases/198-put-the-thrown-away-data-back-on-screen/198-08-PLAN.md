<objective>
Show the three things the resume view already collects and has never printed: progress phase by
phase, the recent decisions, and a drift note saying whether the plan has been revised.

Purpose: `buildResumeDashboardResult` builds `recent.decisions`, `recent.events` and
`plan_revision` on every call, and `renderResumeVisual` reads none of them. Per-phase progress
is the one genuinely new computation — today only an overall fraction exists.

Claude's-discretion decisions recorded here: the drift note is derived from the plan's own
recorded revision (`planRevisionSummary`, already computed and already carried), not from a new
drift-detection algorithm — no such signal exists anywhere in the codebase and inventing one
would be a figure the runtime cannot stand behind. Recent decisions are capped at five, the
number `extractRecentDecisions` already collects.

Output: the per-phase list in the result, three render helpers, and tests that fail if any of
the three silently stops appearing.
</objective>
