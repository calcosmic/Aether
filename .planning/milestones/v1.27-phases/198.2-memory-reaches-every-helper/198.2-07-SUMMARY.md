# Phase 198.2 Plan 07: Previous-Phase Carry-Forward Summary

**A builder starting the next phase now reads, in its own build brief, exactly what failed or was flagged in the phase immediately before it -- one sentence per item, never the full reports -- plus the closing summary the owner read, word-for-word; total brief growth across the whole phase stays capped at two named slots, and CLAUDE.md's claims about what a helper is handed are true again.**

## Performance

- **Duration:** 45 min
- **Tasks:** 3 completed
- **Files modified:** 4 (2 created, 2 modified)

## Accomplishments

- `cmd/phase_carry_forward.go`: `resolvePreviousPhaseCarryForward(currentPhaseID int) string` resolves the immediately preceding phase by its position in `state.Plan.Phases` (`precedingPhaseID`, never `currentPhaseID-1`), reads `verification.json`/`review.json`/`outcome.md` through the same read-and-guard shape `criterion_owner_confirmation.go` already uses, and renders one sentence per failed check, unmet criterion or reviewer blocking issue -- sanitised through `colony.SanitizeSignalContent`. An all-passed phase collapses to a single named-count line ("Phase 3: all 12 checks passed, review clean."). The persisted `outcome.md` closing summary is always appended verbatim, never truncated against the item-list budget.
- Wired into `renderCodexBuildWorkerBrief` (`cmd/codex_build.go`) at exactly one call site, before the phase-research section -- both the direct lane and the delegate (`composeBuildManifestBrief`) lane funnel through this same renderer, so a real failing check seeded on the preceding phase reaches both without a second injection.
- `TestBuildCleanupLeavesThePreviousPhasesRecords` proves by test, not inspection, that `cleanupStaleBuildAttemptArtifacts` (scoped to the CURRENT phase's own `build/phase-N/` directory) never reaches the preceding phase's artifacts.
- `TestBriefGrowthIsCappedAtTheTwoNewSlots` proves total brief growth is bounded by `surveyDigestBudgetChars + phaseCarryForwardBudgetChars` plus a small named heading allowance, reading both constants from source; verified to actually catch a regression by temporarily adding an unbudgeted third section and observing the test fail, then restoring.
- `TestThisPhaseAddedNoDispatchOrCheckin` reuses the existing one-worker and check-in fixtures verbatim to prove this phase added no dispatch and no owner check-in pause.
- CLAUDE.md updated: the colony-prime context sentence drops the two sections plan 04 removed (Phase Learnings, Key Decisions) and now names the two dedicated bounded slots (the map digest and this plan's carry-forward); the Wisdom Pipeline's Hive read row now says the research helper is shown the same top-5 shared lessons as every other helper. Every cited test name verified to exist, and `TestEveryLearningClaimInCLAUDEMDNamesALiveTest` (198.1 plan 05's AST guard) passes.
