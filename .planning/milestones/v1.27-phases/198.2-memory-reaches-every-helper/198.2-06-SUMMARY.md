# Phase 198.2 Plan 06: The Codebase Map Digest, Reaching All Three Briefs Summary

**A helper that reads the plan brief, the build brief or the research brief now gets a sentence a survey helper actually wrote about the codebase -- not just a list of filenames to go open, drawn from one deterministic condensation of `.aether/data/survey/*.md` shared by all three.**

## Performance

- **Duration:** ~55 min
- **Started:** 2026-08-30T~14:35Z
- **Completed:** 2026-08-30T~15:30Z
- **Tasks:** 2
- **Files modified:** 5 (1 created, 4 modified)

## Accomplishments

- `resolveSurveyDigestSection()` (`cmd/helpers.go`) reads every `.md` report under `.aether/data/survey/`, sorts them for determinism, and condenses each into the digest using the exact bounded-content-with-omission loop `resolveColonyResearchSection` already established: a running total against `surveyDigestBudgetChars` (2000, kept strictly outside the memory-pack budget per D-01), a per-report cap `surveyDigestPerReportChars` (400), and a closing "not included" line naming any report that did not fit or whose condensed body `colony.SanitizeSignalContent` rejected -- never a silent drop.
- The digest is headed by `surveyStalenessNotice()` whenever the map is old enough for a notice (D-02), followed by a plain-English guidance line that file paths can be trusted while behavioural claims should be checked against the code. A very old map is still sent, headed by its warning -- never dropped past a cutoff.
- Wired into all three briefs from exactly one call site each: the build brief (`renderCodexBuildWorkerBrief`, called by `composeBuildManifestBrief`), the planning brief (`renderPlanningWorkerBrief`), and the research brief (`renderPhaseResearchBrief`). The build brief's own pre-existing age line (via `resolveSurveySection()`) is stripped at that one call site so it never renders twice now that the digest carries the canonical copy.
- 9 new tests in `cmd/brief_digest_198_2_test.go`: 6 pin the digest function's own behaviour (a surveyor's own sentence arrives, deletion changes the bytes, budget bounding with named omissions, a stale map is still sent with its age line, byte-stable determinism, and no survey means no digest), and 3 are per-brief table tests proving the sentence reaches all three real brief-render functions, the age line renders at most once per brief, and a colony with no survey gets a byte-identical brief to before.

## Decisions Made

- The build brief's age-line duplication was resolved with a targeted `strings.Replace` at the one call site where both `resolveSurveySection()` and the new digest render, rather than changing `resolveSurveySection()`'s signature in `cmd/helpers.go` -- Task 2's own `<files>` scope named only `codex_build.go`, `codex_plan.go`, `phase_research.go` and the test file, and `cmd/codex_continue.go`'s separate `resolveSurveySection()` call (explicitly left untouched per the plan) still needs its own age line unchanged.
- A sanitizer-rejected report body is named in the digest's omission line exactly like a budget-excluded one, rather than silently dropped or aborting the whole digest -- this is a real, not theoretical, path: `colony.SanitizeSignalContent`'s shell-injection rule rejects any backtick pair, and real survey reports routinely use backticks for file paths per the surveyor prompt's own instruction. Fixtures for this plan's own tests were written to keep their opening summary (the part the digest's small per-report cap actually captures) backtick-free, matching the realistic shape of a report whose Pattern-Overview-style opening section is prose before the file-path-heavy sections further down.
- `resolveSurveyDigestSection()` only reads `.md` files (matching what the four surveyor castes write), not `.json` -- `resolveSurveySection()`'s filename list still includes both extensions for the pointer it renders, but there is no comparably structured prose to condense from a JSON compatibility file.
