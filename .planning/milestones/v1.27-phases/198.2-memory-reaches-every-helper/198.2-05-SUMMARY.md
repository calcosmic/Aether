# Phase 198.2 Plan 05: Outcome.md Persistence Summary

**Both continue lanes now persist the owner's exact closing screen to `build/phase-N/outcome.md`, fed by the same D-12 renderer and finalizer result map that produced it -- proven by an AST guard that fails by naming any future terminal branch that skips the write.**

## Accomplishments

- `cmd/phase_outcome.go`: `writePhaseOutcomeDocument` -- the only producer of `outcome.md`. Calls `closeoutContinueDirectVisual` (the 198 D-12 single renderer) on the finalizer's own result map, strips terminal colour codes, and writes atomically. Writes nothing and returns a named error when the renderer cannot resolve a phase; a second call for the same phase replaces the first.
- Wired into every terminal branch of both continue lanes: 5 sites in the direct lane (`cmd/codex_continue.go` -- missing build packet, manifest task-set mismatch, gate-blocked, review-blocked, success) and 2 in the chat-driven finalize lane (`cmd/codex_continue_finalize.go` -- blocked, success) -- 7 call sites against the plan's starting estimate of ~4.
- `TestEveryCheckLaneWritesOneOutcome`: an AST guard over both continue files, anchored on `closeLifecycleRun` (the codebase's own existing marker for "a finished run's result map, about to become the closing screen"), that fails by naming the file and line if a future terminal branch is added without the write call. Proven to genuinely fail by removing a call, observing the named failure, and restoring it.
- The write is provably non-fatal (`TestOutcomeWriteFailureDoesNotFailTheCheck`, forcing a real filesystem write failure) and provably absent on the planning-only path (`TestPlanOnlyCheckWritesNoOutcome`).
- Fixed a pre-existing `--skip-watchers` wording mismatch on the direct lane so all three continue lanes report the identical watcher-skip summary -- discovered by the dual-lane outcome-text parity test, which the mismatch was directly breaking.

### Discovered, Out of Scope (recorded in `.planning/WINDOWS.md`)

While building the strict live-pipeline version of `TestBothCheckLanesLeaveTheSameOutcomeText`, a second, genuine content asymmetry surfaced: the direct lane's `runCodexContinueReview` explicitly appends a "review wave skipped" narration step to the worker flow when no reviewers ran (e.g. under `--skip-watchers`), but the finalize lane's `externalContinueReviewReport` has no equivalent branch -- it silently omits the step. This is a pre-existing gap in review-report construction (198.1's territory), not something WIRE-07 asks this plan to fix, and closing it risked a broader, riskier behavior change than this plan's scope justified under the remaining time budget. Recorded as a `deviation` entry in `.planning/WINDOWS.md` for a future phase to pick up. `TestBothCheckLanesLeaveTheSameOutcomeText` was designed around this discovery: a live-pipeline "smoke" subtest proves both real lanes independently produce a correct, phase-named outcome, and a separate hand-built "shape parity" subtest proves the writer itself is byte-for-byte lane-shape-agnostic given equivalent data -- together covering what this plan is actually responsible for.
