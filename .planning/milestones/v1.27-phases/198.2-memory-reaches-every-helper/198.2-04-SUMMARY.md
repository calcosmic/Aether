# Phase 198.2 Plan 04: Dead Capsule Slots and the Writer Invariant Summary

**Removed the two memory-pack sections that could never carry content (Key Decisions, Phase Learnings) and added an AST-driven invariant that fails by name if any future section is added without a real writer feeding it.**

## Accomplishments
- Built `TestEveryMemoryPackPartHasALiveWriter`, which discovers every `colonyPrimeSection` part name by walking the AST of `cmd/colony_prime_context.go` (never a hand-typed list) and fails by name if a part has neither a writer-map entry nor a justified, shrink-only exception. Run before Task 2's change, it correctly failed naming exactly `decisions` and `learnings` -- confirmed by temporarily adding a throwaway unregistered section, which the test also caught by name.
- Deleted the `decisions` ("## Key Decisions") and `learnings` ("## Phase Learnings") section builders from `buildColonyPrimeOutput`. Neither `state.Memory.Decisions` nor `state.Memory.PhaseLearnings` has a writer anywhere in the running program -- `aether init` empties them and `aether entomb` clears them, nothing else ever assigns to them.
- Deleted the four helper functions that became unreferenced as a result (`latestPhaseLearningFreshness`, `phaseLearningPhases`, `phaseLearningConfidenceScore`, `confidenceScoreFromLearnings`) and the now-dead `"learnings"` case in `sectionRelevanceScore`.
- Added `TestPhaseLessonsStillReachAHelperUnderLearnedMemory` and `TestOwnerAnswersStillReachAHelperUnderClarifiedIntent`, seeding content through the real runtime writers (`learn.CollectEvidence`/`learn.NewColonyStore(store).Add`, mirroring continue-finalize's own write path, and `recordDecisionAnswer`, the function `decision-answer` calls) and asserting the content lands exactly once, inside the surviving section's block.
- Re-ran the invariant after the deletion: it now passes with an empty exception list (floor 0) -- no writerless parts remain.
- Fixed every existing test that broke as a result: two tests asserting the removed headings exist (replaced with assertions the surviving headings/content still exist), and six tests that used Decisions/PhaseLearnings purely as inert budget-pressure filler for priority/trimming/freshness comparisons, all repaired by swapping in still-real, still-written sections (`learned_memory`, `instincts`, decayed `hive_wisdom`) so the coverage stays genuine rather than becoming permanently vacuous.

## Decisions Made
- The writer map's "reachedBy" documentation interprets 198.2-CONTEXT.md D-16's five named commands (`/ant-build`, `/ant-continue`, `/ant-plan`, `/ant-colonize`, `decision-answer`) as the READ lanes that hand the assembled pack to a worker, not a restriction on which command may WRITE the underlying data -- several legitimate sections (e.g. `charter`, written only at `/ant-init`; `pheromones`, written by `/ant-focus`/`/ant-redirect`/`/ant-feedback`) are written by a predecessor steering command and read by one of the five. This is documented inline in the test file for auditability.
- `cmd/context.go`'s separate `buildContextCapsuleOutput` fallback assembler (used only when `buildColonyPrimeOutput` produces empty output) still has its own "Recent Decisions" section reading `state.Memory.Decisions`, and the helper functions it calls (`latestDecisionFreshness`, `confidenceScoreFromDecisions`, `decisionPhases`) were kept because that assembler is a different, out-of-scope surface -- the plan's Task 2 scope was explicitly `buildColonyPrimeOutput`'s two dead builders.
- `state.Memory.Decisions` and `state.Memory.PhaseLearnings` were NOT removed from the `colony.Memory` struct -- other surfaces (`abandon_cmd.go`, `entomb_cmd.go`, `internal_cmds.go`, `swarm_display.go`, `recovery_snapshot.go`) still reference them, and removing the fields was explicitly out of this phase's scope per the plan.

## Issues Encountered

**Trim-fixture repair required more iteration than the plan anticipated.** Several existing tests used Decisions/PhaseLearnings as budget-pressure filler to force real trimming in `buildColonyPrimeOutput`'s weighted ranker (`pkg/colony/context_ranking.go`), and naively swapping in another many-line section (e.g. `instincts`) does not reproduce the same behavior: a candidate with many small lines gracefully shrinks to fit whatever budget remains and is essentially never fully excluded, while a candidate with few lines (e.g. `hive_wisdom`, capped at 5 entries) can be fully excluded only when the remaining budget is too small even for its header plus one truncated entry. Getting a fixture to reliably produce a real "trimmed" entry (rather than a vacuously-passing conditional check) required combining a fine-grained, many-short-line filler (to minimize the truncation algorithm's per-line "waste") with a separate, few-line, stale/low-confidence victim section. Verified empirically for each repaired fixture, not just asserted -- confirmed via ad hoc debug logging (removed before commit) that each fixture's `trimmed` list is genuinely non-empty and contains the intended section, not just passing by accident.
