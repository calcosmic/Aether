<domain>
## Phase Boundary

Everything Aether remembers — the Queen file's standing rules, hive lessons pooled
from other projects, instincts (learned habits), the midden (failure log), pheromone
notes (the owner's steering), clarified intent (the owner's answers), the last
worker's handoff (relay note), the colonize survey (codebase map), and Oracle
research write-ups — reaches every helper that should read it, **as content, on the
command lane the owner actually runs** (the `/ant-…` wrappers in Claude Code and
OpenCode). Today the builder and reviewers get it; the planner, the four surveyors,
the phase-research scout, and the session-start greeting get nothing or a list of
filenames.

Proof standard for every item: one test per command that runs the real delegate
(wrapper) lane and asserts a **sentence** from each memory source inside the prompt
actually sent — and fails when any source is missing. A test that exercises only the
native in-process dispatch does not count (that is exactly how the gap went
unnoticed: `TestEightCommandsDeliverPheromoneExactlyOnce` stayed green while the
shipped lane carried nothing).

Verified in code during discussion (2026-08-30):
- `codexPlanManifest` (`cmd/codex_plan.go:216`) and `codexColonizeManifest`
  (`cmd/codex_colonize.go:68`) have no capsule field. The `ContextCapsule` set at
  `codex_plan.go:1498` / `codex_colonize.go:718` is on the in-process
  `codex.WorkerDispatch` the wrappers never use (`ShouldUseAgentDelegatePath()`
  routes every Claude/OpenCode session away from it at `codex_plan.go:418`,
  `codex_colonize.go:113,342`). The build manifest does carry one (`codex_build.go:169`).
- The research scout brief (`cmd/phase_research.go:123-165`) reads no hive wisdom
  and its output template tells the scout to fill `## Hive Wisdom` from nothing;
  the finalize fallback hardcodes "No relevant hive wisdom found" (`codex_plan.go:3385`).
- The survey reaches briefs only as a filename list plus an age notice
  (`resolveSurveySection`, `cmd/helpers.go:200`); the plan-side JSON is rewritten
  from a deterministic scan (`writeSurveyCompatibilityJSON`, `codex_colonize.go:1039`)
  and contains no surveyor prose. Seven surveyor reports (~123 KB in this repo,
  dated 2026-05-19) are never read into any prompt.
- Oracle output reaches briefs only via a hand-typed `aether oracle save` and a
  hand-typed `--research <path>` pointer (`loadColonyResearchDocs`,
  `cmd/colony_research.go:167` reads pointers from colony state).
- The session-start card (`hook-session-start`, `cmd/hook_cmds.go:334` →
  `renderNextActionCard`, `cmd/next_action_card.go`) renders pending questions and
  flags only.
- `outcome.md` (named in WIRE-07) has never existed in any version. The real
  per-phase artifacts are `build/phase-N/verification.json` and `review.json`,
  written by continue (`codex_continue.go:857,944`; `codex_continue_finalize.go:315,557`)
  and read back only by owner-confirmation (`criterion_owner_confirmation.go:121`)
  and seal (`seal_final_review.go:885`).
- `state.Memory.PhaseLearnings` and `state.Memory.Decisions` are read by the
  capsule (`colony_prime_context.go:656-691`) but have no writer besides init
  emptying them (`init_cmd.go:284`) and entomb clearing them (`entomb_cmd.go:680`).

Out of scope: new helpers, new ceremony, new commands; changing what any command
does beyond what it hands its workers; the autopilot stop contract (198.3); deleting
orphan subcommands (198.4); automatic model routing.

## Implementation Decisions

All decisions below were made by the owner on 2026-08-30 unless marked (Claude).

### The memory page limit for planner, surveyors and scout (WIRE-01, WIRE-02, WIRE-03)
- **D-01:** The condensed codebase-map digest gets **its own capped slot**, separate
  from the colony-prime memory budget (`colonyPrimeBudgetChars` = 8000 /
  `colonyPrimeCompactBudgetChars` = 4000, `cmd/colony_prime_context.go:22-23`). The
  memory budget is untouched; no lesson, rule or failure is ever displaced by the
  map. Same pattern as the separate 8K skill-injection budget. Digest cap is
  Claude's discretion (order of half a page; see Discretion).
- **D-02:** A **stale map is still sent, headed by a plain-English age line** ("This
  map is 3 months old — trust file paths, verify claims about behaviour"). Never
  silently dropped past a cut-off, never sent unlabelled. `surveyStalenessNotice()`
  (`cmd/helpers.go`) already produces the age line for the filename list; reuse it.
- **D-03:** The chat (delegate) lane delivers **exactly the same memory pack** as the
  direct lane — one assembly function, byte-identical output on both routes, locked
  by a lane-parity test. No lighter "planning version". — **Reversibility:**
  costly — a second tailored capsule would need its own per-source content tests on
  both lanes and re-opens the two-lane drift this phase exists to close.
- **D-04:** The research scout is shown **the same top-5 hive entries** every other
  worker gets (`readHiveWisdomEntriesForDomains(hubDir, 5, …)` +
  `buildHiveWisdomLines`, `colony_prime_context.go:714-724`). One selection rule,
  no scout-specific set. The output-template instruction to invent a Hive Wisdom
  section is removed and the "No relevant hive wisdom found" fallback in
  `codex_plan.go:3385` goes with it.

### What happens when deep research (Oracle) finishes (WIRE-04)
- **D-05:** A finished Oracle run **files its write-up and registers it by itself**:
  `finalizeOracleLoop` (`cmd/oracle_loop.go:1328`) performs what `aether oracle save`
  (`saveOracleResearchDocument`, `cmd/oracle_research_doc.go:135`) and the
  `--research <path>` pointer do today, with no hand-typed step. The next
  build/plan/research brief reads it through the existing
  `loadColonyResearchDocs` / `resolveColonyResearchSection` path
  (`cmd/colony_research.go`; readers `codex_build.go:3349`, `codex_plan.go:2177`,
  `phase_research.go:136`).
- **D-06:** On finish, **strong findings are auto-promoted into instincts** (learned
  habits) with no prompt — the owner chose this over the recommended "file only,
  keep offering promotion". Reuse `runOraclePromote` (`cmd/oracle_promote.go:32`)
  and its existing confidence bar; do not invent a second promotion path. Every
  instinct promoted this way is **labelled with its source** ("from research:
  <topic>, <date>") so the memory view shows where a habit came from and it can be
  removed if wrong (Claude's guard, not asked). — **Reversibility:** costly —
  undoing means removing instincts that later helpers may already have applied and
  that consolidation may have promoted onward to QUEEN.md / the hive.
- **D-07:** An **interrupted run** (owner stop, or the time limit; stop path
  `oracle_loop.go:591-593`) files whatever it gathered, **clearly marked partial**
  at the top of the document ("partial — stopped after N rounds"). Nothing paid for
  is thrown away. Promotion (D-06) still applies only to findings that meet the bar.
- **D-08:** Researching the **same topic again keeps both** write-ups; helpers see
  the newest first, older ones after if space allows. No title-match replacement.

### What the next phase hears about the last one (WIRE-07)
- **D-09:** The next phase's build brief carries from the previous phase **only what
  failed or was flagged**: failed checks, unmet criteria, reviewer blocking issues,
  open findings — one sentence each. Passes collapse to one line ("Phase 3: all 12
  checks passed, review clean"). Never the full reports.
- **D-10:** **Previous phase only.** Older phases' failures already reach helpers via
  the midden and the open-findings ledgers (wired in 198.1 and this phase); no
  running multi-phase summary.
- **D-11:** The brief also carries the **closing summary word-for-word** — the same
  text the owner saw on the closing card (Phase 198 D-12 made the finalizer result
  map the single source rendered by `renderCeremonyCloseoutVisual`,
  `cmd/ceremony_cmd.go:544`). "Outcome" in WIRE-07 means this summary; whether it is
  persisted as `build/phase-N/outcome.md` at continue-finalize or read from the
  existing `continue.json` is Claude's discretion, but the next build runs in a new
  process, so it must be persisted somewhere and the brief must read the file, not
  memory.

### The session-start greeting card (WIRE-05)
- **D-12:** **A few lines each**: one preferences line (count plus one example, from
  `readUserPreferences`, `cmd/context.go:1609`), the **top 3 instincts by
  confidence** one sentence apiece, and one line for the last handoff naming the
  worker and what it left for the next one (`.aether/data/handoffs/worker-handoffs.json`).
  Card stays under a screen; every item is content, not a heading.
- **D-13:** "Top" means **strongest by confidence**, not most recent. The status
  dashboard's `loadRecentRuntimeInstincts(s,&state,3)` (`cmd/status.go:1042-1047`)
  is switched to the same strongest-first rule, so card and dashboard share one
  loader (the audit flagged the most-recent behaviour as a regression from v5.4).
- **D-14:** On a project with no preferences / instincts / handoff yet, **those
  parts are left out** — no "nothing learned yet" filler. Consistent with the
  no-empty-sections rule (D-16).

### Dead capsule slots and the writer invariant (WIRE-06) (Claude)
- **D-15:** No capsule section may exist without a live runtime writer. `Phase
  Learnings` and `Key Decisions` each either gain a real writer on the path the
  owner runs (continue-finalize already captures verified learnings into the learn
  store at `codex_continue_finalize.go:1607` and, since 198.1, into observations;
  `decision-answer` already records owner answers) or are removed. Where a section
  would duplicate content another section already carries (Clarified Intent already
  renders owner answers), remove rather than duplicate — the brief must never say
  the same thing twice.
- **D-16:** Locked by an invariant test that enumerates every capsule section
  builder and fails if any section has no writer reachable from `/ant-build`,
  `/ant-continue`, `/ant-plan`, `/ant-colonize` or `decision-answer`.

### Carried forward — binding, not re-asked
- **198.1:** feed the existing pipeline, never a second one; every guarantee holds
  on the delegate lane AND the native lane with a test on each; content locks, not
  heading locks; fixtures derived the way the runtime derives them; dry-run never
  mutates; no new ceremony, no new workers; CLAUDE.md claims become true or are
  deleted, each kept sentence naming its test.
- **198 D-12:** one renderer for both lanes; the finalizer result map is the single
  source.
- **197 S-01/S-04/S-05:** next-step commands via the shared resolver; wrapper
  triplets edited byte-identically; all owner-facing text plain English with repo
  words translated inline (the greeting card and the age line are owner-facing).
- **CLAUDE.md "How much proof a change needs":** everything here decides what a
  helper is told — full rigour. A test must be able to fail.

### Claude's Discretion
- Exact size of the map-digest slot and of the previous-phase carry-forward slot
  (order of 1.5–2.5K chars each); where the new sections sit in brief order.
- How the seven survey `.md` reports are condensed into the digest: deterministic
  (no LLM call) — e.g. each report's summary/first section plus headed key-finding
  bullets, capped per report — so that deleting a report provably changes the
  prompt. Same digest for build, plan and research briefs.
- Whether the Oracle write-up is registered as a colony-state research pointer
  (today's mechanism) or the research directory is scanned directly; either way
  the write-up must reach the brief with no hand-typed command.
- The promoted-from-research source label's exact wording and where it is stored
  on the instinct record.
- Whether the closing summary is persisted as `outcome.md` or read from
  `continue.json` (D-11).
- Test design: a per-command table test on the delegate lane using sentinel
  sentences written into each store the way the runtime writes them (a QUEEN.md
  line, a hive entry, an instinct, a midden entry, a pheromone, a resolved
  clarification, a handoff, a surveyor-authored sentence, an Oracle finding, a
  failed-check sentence), asserting each arrives in the assembled prompt; plus a
  brief-size invariant (see Folded Todos).

### Folded Todos
- **Worker turnaround is too slow**
  (`.planning/todos/pending/2026-08-27-worker-turnaround-is-too-slow.md`) — the
  owner's named priority. Constraint for this phase: delivering more memory must
  not add a single dispatch or check-in, brief assembly stays in-process and
  bounded, and total brief growth is capped at the two new slots (D-01, D-09) —
  locked by a test that measures assembled brief size before and after and fails
  if growth exceeds those caps.
