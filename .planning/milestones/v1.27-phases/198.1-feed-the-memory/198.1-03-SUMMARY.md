# Phase 198.1 Plan 03: Feed the Memory (instinct application) Summary

**A worker's own lesson now reaches QUEEN.md through the existing promotion pipeline for the first time, because delivery-and-use is now a recorded fact — checked against the actual text a worker received — instead of an unmet gate nothing ever satisfied.**

## Performance

- **Duration:** ~50 min
- **Started:** ~2026-08-29T22:55Z (approximate; not captured at session start)
- **Completed:** 2026-08-29T23:54:30Z
- **Tasks:** 3
- **Files modified:** 4 (2 created, 2 modified)

## Accomplishments

- A new phase-keyed ledger, `instinct-deliveries.json`, records one delivery per (phase, instinct) pair only when the instinct's own action text is genuinely present in the capsule a worker received — never assumed just because instincts are usually injected. Recording is idempotent per phase and never fails a build (bookkeeping only).
- Both build lanes feed this ledger through the same one-boundary guard Plan 01 proved (`recordDispatchWorkerOutcome`); the delegate lane's dispatch carries no capsule of its own, so `capsuleForDispatch` falls back to the phase's persisted build manifest.
- At phase end, `recordInstinctApplicationsForPhase` turns this phase's recorded deliveries into one `ApplicationHistory` entry per instinct, in the exact shape the `instinct-apply` CLI already writes — the missing input the `QueenEligible` gate (`Confidence >= 0.75 && Applications >= 3`) has been waiting on since it was written.
- `runPhaseEndConsolidation`'s summary now reports `QueenPromoted` (the ids `pipeline.RunConsolidation` actually wrote into QUEEN.md, not merely eligible) and `InstinctApplicationsRecorded`; `LearningBeatLine` gains one additive clause that fires only when something was actually promoted.
- End to end: a fixture colony starting with nothing drives a worker's own sentence through the real capture path, one consolidation pass promotes it to an instinct, and repeated delivery+consolidation rounds promote that instinct into QUEEN.md — with a negative test proving promotion never happens if delivery is never recorded.

## Decisions Made

- **`capsuleForDispatch` guards against a nil `store`.** `loadCodexContinueManifest` (the existing manifest-load helper it falls back to) has no nil guard of its own; some pre-existing dispatch-path tests legitimately run with no store set. Found running the full `cmd` package suite, not by inspection.
- **Filtered "file does not exist" out of `runPhaseEndConsolidation`'s fatal-error check.** A fresh colony has neither `instincts.json` nor `learning-observations.json` yet — normal starting state, not corruption — and `pkg/memory.ConsolidationService.Run`'s own steps already treat a missing file as "start empty." Without the filter, `runPhaseEndConsolidation` misreported "phase advanced WITHOUT consolidation" on literally the first phase of every colony, even though the promotion step underneath had already succeeded. Any other error (corrupt JSON, permission failure) is unaffected and still fails loudly. Full existing `cmd/consolidation_lifecycle_test.go` regression suite (including the corrupt-JSON non-blocking-failure test) still passes unchanged.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `capsuleForDispatch` panicked on a nil store**
- **Found during:** Running the full `cmd` package suite after Tasks 1-3 passed in isolation
- **Issue:** `TestBuildDispatchStartsHeartbeatMonitor` runs `executeCodexBuildDispatches` (and therefore `recordDispatchWorkerOutcome` → `capsuleForDispatch`) with no store set; `loadCodexContinueManifest` calls `store.LoadJSON` unconditionally and panicked with a nil pointer dereference.
- **Fix:** Added a `store == nil` guard in `capsuleForDispatch` that returns `""` (no capsule available) instead of falling through to the manifest loader.
- **Files modified:** cmd/instinct_application.go
- **Verification:** `TestBuildDispatchStartsHeartbeatMonitor` passes; full `cmd` suite re-run twice, both clean.
- **Committed in:** `5b7eab05`

**2. [Rule 1 - Bug] `runPhaseEndConsolidation` misreported "did not run" on a fresh colony's first phase**
- **Found during:** Task 3, proving `TestWorkerLessonBecomesQueenFileWisdom`'s acceptance criterion that no instinct or observation store is ever seeded by hand
- **Issue:** `pkg/memory.ConsolidationService.Run`'s STEP 1 appends a "load instincts: ... no such file or directory" error to `result.Errors` on a colony that has never written `instincts.json` — normal state on the very first phase, not corruption. `runPhaseEndConsolidation` treated ANY non-empty `result.Errors` as fatal, so it reported `Ran: false` even though the promotion write inside `pipeline.RunConsolidation` had already succeeded moments earlier. The plan's own test could not seed an empty `instincts.json` by hand to work around this (that would violate the "no store-save call" acceptance criterion), which is what surfaced the bug.
- **Fix:** Added `realConsolidationErrors`, which filters out errors satisfying `errors.Is(err, fs.ErrNotExist)` before joining the rest into a fatal error. Corrupt JSON and other genuine failures are untouched.
- **Files modified:** cmd/consolidation_lifecycle.go
- **Verification:** `TestRunPhaseEndConsolidationIsNonBlockingOnFailure` (corrupt-JSON case) still passes unchanged; `TestWorkerLessonBecomesQueenFileWisdom` and `TestQueenPromotionNeverHappensWithoutRecordedUse` pass with no hand-seeding.
- **Committed in:** `6a4c0ce1`
