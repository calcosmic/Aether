# Phase 198.1: Feed the Memory — Context

**Gathered:** 2026-08-30 from the whole-system audit (`.planning/audits/2026-08-30-whole-system-audit.md`) and the owner's stated goal. No discuss-phase was run; the owner said "go" on the four-phase reconnection plan.

<domain_context>
Aether's learning loop is wired at the promotion end and starved at the source. `runPhaseEndConsolidation` runs on every durable continue (cmd/codex_continue.go:1103, cmd/codex_continue_finalize.go:612 → pipeline.RunConsolidation) and can write instincts.json and QUEEN.md — but nothing on a normal build/continue writes `learning-observations.json`, the midden, an instinct, or a pheromone. Continue stores one hypothesis-status entry in `learn/entries.json` (cmd/codex_continue_finalize.go:1607) with no bridge to observations. The only observation writer, `aether memory-capture` (cmd/learning.go:71), is reached from a wrapper solely on an owner check-in trim (build.md:324). The only midden writers are autopilot retry exhaustion (cmd/autopilot_retry_record.go:46) and the spawn-budget ceiling (cmd/spawn_budget.go:349). The v5.3.3 playbooks (`git show v5.3.3:.aether/docs/command-playbooks/continue-advance.md`, `build-wave.md`, `build-verify.md`, `continue-gates.md`) show what used to run automatically.
</domain_context>

<decisions>
- **Feed the existing pipeline; do not build a second one.** Observations go through `pkg/memory/observe.go` / the same store `memory-capture` writes; instincts through `pkg/memory/promote.go`; QUEEN promotion through the consolidation already called at phase end. New code is the bridge from build/continue results into those stores, not a parallel path.
- **Automatic on the path the owner uses.** Every FEED requirement must fire from `/ant-build` and `/ant-continue` as run from Claude/OpenCode (the delegate lane) AND from the native lane. A test that only exercises the native dispatch functions does not count (see the plan/colonize capsule finding: `codexPlanManifest` has no capsule field and `TestEightCommandsDeliverPheromoneExactlyOnce` stayed green while the shipped lane regressed).
- **Content locks, not heading locks.** Every acceptance test asserts a sentence a worker wrote (or a failure's own wording) appears in the store and then in the next brief. `strings.Contains(brief, "## Recent Failures")` is not proof.
- **Fixtures derive values the way the runtime derives them.** Worker results must be produced by the real result parser from a realistic worker output, not typed as a struct literal (CLAUDE.md Definition of Done).
- **Dry-run / inspection commands never mutate** (existing rule; keep `consolidation-phase-end --dry-run` clean).
- **CLAUDE.md claims become true or are deleted** — "Decisions become pheromones (auto-emit during builds)", "Midden affects behavior (threshold auto-REDIRECT)", "Learnings become instincts", Wisdom Pipeline stage table. Each sentence kept must name its test.
- **Hive promotion at continue honours `AETHER_HIVE_POLICY`** exactly as seal does (cmd/codex_workflow_cmds.go:703-717); non-blocking.
- **memory-details** returns to a rendered drill-down (wisdom entries, pending promotions, deferred proposals, queen_md_updated); keep the JSON under `--json`.
- **No new ceremony, no new workers.** Feeding memory must not add a dispatch or a check-in; it is bookkeeping done by the Go runtime in finalize steps.
</decisions>

<scope_fences>
- IN: build-finalize and continue-finalize bridges; midden writes on build/continue/quick/swarm failure paths; instinct creation from verified learnings; FEEDBACK/REDIRECT emission; expiry→eternal promotion; hive promotion at continue; memory-details/status rendering.
- OUT (later phases): delivering memory to plan/colonize/research briefs (198.2); autopilot stop contract (198.3); deleting orphan subcommands (198.4). Do not delete the orphaned learning-*/instinct-*/midden-* CLIs here — 198.4 decides, and some become the call targets of this phase.
</scope_fences>
