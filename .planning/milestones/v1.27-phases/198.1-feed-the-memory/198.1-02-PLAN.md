<objective>
The check step (`/ant-continue`) already collects every reviewer's findings, weak spots and reusable lessons, and the program's own build/type/lint/test checks already produce a plain-English summary when they fail. Both are then thrown away. This plan turns the reviewers' lessons into observations and the failed checks into failure records, on both check lanes, and extends the same treatment to the one-off query (`/ant-quick`) and the bug swarm (`/ant-swarm`).

Purpose: close the source end of the learning loop for check, quick and swarm. FEED-01 (check half) and FEED-02 (check, quick and swarm halves).
Output: `cmd/memory_feed_continue.go` — the check-side feed, built on Plan 01's shared helpers.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| check worker → runtime | `reusable_lessons`, `weak_spots`, `blockers` and `summary` on a continue completion packet are worker-authored free text. |
| swarm worker → runtime | Same, via the external swarm completion packet. |
| shell check → runtime | A failing test command's stdout/stderr summary is program output, not worker-authored, but is still stored and re-rendered. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-198.1-05 | Tampering | reviewer/swarm free text → observation store → next worker prompt | high | mitigate | Reuses Plan 01's `captureWorkerObservation`, which sanitises with `colony.SanitizeSignalContent` and gates on `IsAdmissibleInstinctContent`. No second, unsanitised path is added. |
| T-198.1-06 | Spoofing | a swarm/continue worker claiming a status it did not earn to suppress or forge a record | medium | mitigate | Both external lanes record from the MERGED status produced by `mergeExternalContinueResults` / `mergeExternalSwarmResults`, never the raw submitted status — stated as an explicit placement rule in Tasks 1 and 3. |
| T-198.1-07 | Denial of Service | a repeatedly re-run plan-only check flooding the failure log | medium | mitigate | `appendMiddenEntryOnce` refuses an identical unacknowledged entry; Task 2 asserts one record across two floor runs. |
| T-198.1-08 | Information Disclosure | a failing test's output containing secrets being stored and re-injected | medium | mitigate | Check summaries pass through the same `colony.SanitizeSignalContent` path; the existing `check-antipattern` secret scan remains the gate on committed content. Accepted residual: a secret printed by a failing test can reach midden.json, which is already true of the existing verification report. |
| T-198.1-SC | Tampering | npm/pip/cargo installs | high | accept | This plan installs no packages. |
