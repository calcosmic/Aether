<objective>
Build workers already hand back a structured handoff (what they changed, what failed, what not to repeat) and that handoff is already persisted — but nothing turns any of it into colony memory. Failures vanish; lessons vanish. This plan opens the one boundary both build lanes pass through and feeds two stores from it: the failure log (midden.json) and the observation log (learning-observations.json).

Purpose: close the source end of the learning loop for build. FEED-01 (build half) and FEED-02 (build half).
Output: `cmd/memory_feed.go` — the shared feed boundary every later plan in this phase reuses.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker → runtime | `handoff.do_not_repeat`, `handoff.next_worker_instructions`, `blockers`, and `summary` are worker-authored free text submitted through a completion packet. |
| durable memory → next worker prompt | Anything stored in midden.json or learning-observations.json is later rendered into another worker's prompt by colony-prime. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-198.1-01 | Tampering | worker handoff text → learning-observations.json → next worker prompt | high | mitigate | Every worker sentence passes `colony.SanitizeSignalContent` (the existing pheromone sanitiser: rejects XML structural tags, escapes angle brackets, blocks shell-injection and instruction-override patterns) before storage — Task 1 and Task 2. |
| T-198.1-02 | Denial of Service | unbounded midden/observation growth from a looping worker | medium | mitigate | `appendMiddenEntryOnce` refuses a duplicate unacknowledged entry; the observation store dedups by content hash; `IsAdmissibleInstinctContent` caps content at 240 characters. |
| T-198.1-03 | Spoofing | a worker granting itself durable memory via a status it did not earn | medium | mitigate | The feed reads the MERGED dispatch status produced by `mergeExternalBuildResults` (the existing trust boundary), never the raw submitted status. |
| T-198.1-04 | Repudiation | a failure silently not recorded | medium | mitigate | Task 3's AST guard makes a lane that persists a handoff without feeding memory a named test failure. |
| T-198.1-SC | Tampering | npm/pip/cargo installs | high | accept | This plan installs no packages; no package-manager command appears in any task. |
</threat_model>
