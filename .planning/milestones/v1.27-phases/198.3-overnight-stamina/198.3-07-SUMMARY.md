# Phase 198.3 Plan 07: Swarm Three-Strike Escalation Summary

**Swarm retries now derive from durable same-problem results, raise one visible blocker on strike three, and refuse a wasteful fourth dispatch with a safe corrective-phase command.**

## Accomplishments

- Added full-text target fingerprints and a pure, deterministic history reducer that counts only consecutive `failed`/`blocked` results since that target's last `completed` result.
- Unified direct and external completion persistence through one typed result writer and escalation evaluator, including an optional backward-compatible `target_fingerprint` field.
- Upserts exactly one ordinary unresolved `Source: escalation` blocker after strike three; the shared plan 01 snapshot observes it without swarm-specific logic.
- Refuses direct, plan-only, and delegated fourth attempts before worker planning or invocation and returns `aether insert-phase "<issue>"` with all three evidence IDs.
- Preserves durable `result.json` evidence during cleanup while deleting disposable per-run artifacts.

## Decisions Made

- Framing punctuation is an explicit narrow set rather than every Unicode symbol, preventing material targets such as `C++` and `C` from colliding.
- Legacy result records without `target_fingerprint` remain valid by deriving it from `target`; records with a contradictory stored fingerprint are ignored.
- A `completed` result resets only strike history for its own fingerprint. Existing blocker resolution remains in the normal owner-controlled flag lifecycle.
- Refusal is a structured `architectural_concern` result with `dispatch_mode: refused`; it writes no fabricated fourth result record.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Preserved durable result evidence during cleanup**
- **Found during:** Task 1 (history durability)
- **Issue:** The plan required history to survive cleanup, but the existing cleanup command deleted the entire swarm directory and `cmd/swarm.go` was not listed in the task file set.
- **Fix:** Kept the regular `result.json` byte-for-byte while deleting findings, display, responses, and other disposable siblings; result-less runs still remove their empty directory.
- **Files modified:** `cmd/swarm.go`, `cmd/swarm_cleanup_truth_test.go`
- **Verification:** `TestSwarmCleanupTruthPreservesDurableResult` and the complete `TestSwarm` suite passed.
- **Committed in:** `f7319012`

**2. [Rule 1 - Bug] Prevented rapid attempts from overwriting strike evidence**
- **Found during:** Task 2 (three consecutive end-to-end attempts)
- **Issue:** Swarm IDs used whole Unix seconds, so rapid retries could select the same directory and overwrite prior `result.json` evidence instead of reaching three strikes.
- **Fix:** Centralized swarm ID creation on UTC Unix nanoseconds for direct, plan-only, and fallback finalizer IDs.
- **Files modified:** `cmd/swarm_strikes.go`, `cmd/swarm_cmd.go`
- **Verification:** The counting-invoker test persists and observes three separate evidence IDs without sleeps.
- **Committed in:** `c66eb82c`

**3. [Rule 1 - Bug] Surfaced direct result persistence failures**
- **Found during:** Task 1 (shared typed result writer)
- **Issue:** The direct lane discarded `SaveJSON` errors, allowing a run to report completion without durable evidence for later strike evaluation.
- **Fix:** Both lanes now return a persistence/evaluation error from the shared completion seam.
- **Files modified:** `cmd/swarm_cmd.go`, `cmd/swarm_strikes.go`
- **Verification:** Direct/external parity and complete swarm suites passed through the shared helper.
- **Committed in:** `f7319012`, `c66eb82c`
