<objective>
Make provider readiness predictable for an overnight run: one successful check per platform and phase, a fresh check next phase, and one timeout setting/retry contract on every live lane.

Purpose: workers in one phase should not each spend 45–90 seconds repeating the same readiness probe, but a success from an earlier phase must not mask a provider that disappeared later.

Output: phase-scoped readiness cache and direct/TypeScript parity for phase and timeout propagation.
</objective>

## Trust Boundaries

| Boundary | Risk | Mitigation |
|---|---|---|
| persisted readiness cache -> future dispatch | Old or cross-phase success could mask provider loss | Versioned platform+phase key; next phase must miss; failures never become success entries |
| TS manifest -> Go adapter | Forged/invalid phase could poison cache scope | Parse non-negative integer in adapter; cache key includes platform; tests capture exact args |
| environment timeout -> subprocess | Zero/huge/invalid values could hang or skip readiness | Reuse bounded parser/default and context cancellation; table-test invalid values |
| retry -> external provider | Broad retry could duplicate work or hammer auth | Retry only classified timeout, maximum two readiness attempts; no whole-work retry here |
</threat_model>
