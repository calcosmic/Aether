<objective>
Collapse the four rival next-step deciders onto the resolver, and build the one
closing card every command will render.

Purpose: `workflowSuggestionsForState`, `nextCommandFromState`,
`nextUpSuggestionsForState` and `closeoutNextCommand` each decide the next step
from the same saved state and already disagree. Until they are one answer, every
card built on top of them inherits whichever one it happened to call. This plan
makes them a single answer and gives the rest of the phase one card to render.
Output: four delegating deciders, one card renderer, and the agreement test that
stops them separating again.
</objective>

<interfaces>
`resolveNextAction` from plan 197-01 is the only decider. Nothing added by this
plan may choose a command; the surviving functions become adapters that shape
the resolver's answer into the return type their callers already expect.

Keep the existing signatures. `workflowSuggestionsForState(state) (string, []string)`
has callers in `cmd/status.go` and `cmd/proof_cmd.go` and four test files;
changing its shape here would drag those files into this plan's ownership and
block the parallel work in the next wave. Same for `nextCommandFromState(state) string`.

`closeoutNextCommand(workflow, state)` keeps its workflow argument. The workflow
name is real information the resolver's input already accepts — which command
just ran — so pass it through rather than discarding it.

The card is assembled from the existing primitives, not around them.
`renderNextUp` stays the single Next Up funnel: `TestNextUpIsTheOnlyNextUpFunnel`
fails any file outside `codex_visuals.go` that builds its own Next Up banner, so
the card must live in `codex_visuals.go` or call through `renderNextUp`. Put the
card in its own file and have it call `renderNextUp`; that keeps the funnel test
satisfied and keeps platform translation at the writer, per S-01.

Human-facing output goes through the visual writer. `TestHumanFacingOutputGoesThroughWriteVisualOutput`
holds every new renderer to that; build the card as a string and let the caller
hand it to the existing output path, exactly as the sibling renderers do.

The card's context-health sentence replaces what `renderContextClearGuidance`
composes today. Keep that function as the renderer of the resolved health value
rather than deleting it — it has callers across a dozen closing renderers that
the next waves will migrate, and removing it here would pull those files in.

S-05 binds every sentence the card can print. The owner has never read this
repository's source and does not know what any of its invented words mean.
Say the everyday meaning beside the word, every time, including in alternatives.

Do NOT touch `nextCommandForHookState` in `cmd/hook_cmds.go`. Plan 197-03 owns
that file in the next wave and migrates it there.

Do NOT change any individual command's closing renderer in this plan. Those are
plans 197-04 and 197-06. This plan changes what the deciders return and adds the
card; it does not repoint the eleven cards at it.
