<objective>
Resolve the two accounting paths into one authoritative token type, and remove
the only place a token count is invented from a length, before anything renders
a cost.

Purpose: the chat-model client's usage value carries only input and output —
no cache columns at all — and the agent pool reports exactly those two. That is
the same shape as the 186x undercount already in this repository's history,
alive on a second lane. Separately, D-01 as amended forbids any token count
derived from a character or prompt length anywhere; exactly one live producer of
such a figure exists today, and it must go before rows are written over it.
Output: four billed columns on the client usage value, one conversion into the
authoritative worker usage type, a cross-path equality invariant, and a ratchet
locking the no-length-derivation rule.
</objective>

<interfaces>
`codex.WorkerUsage` is authoritative (D-05). `BilledTotalTokens()` stays the one
entry point for a row's total; nothing anywhere may add columns itself.

Import direction is safe and must stay that way: `pkg/codex` imports only
`pkg/storage`, so `pkg/agent` may import `pkg/codex` with no cycle. Do not add
an import from `pkg/codex` to `pkg/agent` or `pkg/llm`.

`llm.Usage` gains cache-read and cache-creation columns. It does NOT gain a
total-computing method — a second implementation of that arithmetic in a second
package is exactly the failure this plan exists to close.

Per D-01 as amended, the character-derived fallback in `pkg/codex` is removed at
source rather than merely hidden by the renderer. Its one live caller is the
directly-spawned dispatch path. After this plan, a worker whose provider reported
nothing carries an empty usage value, which downstream reads as not reported.

The source tag vocabulary on the worker usage type is NOT changed: the tag that
previously meant "estimated" now means "not measured", and the renderer's word
for it is chosen in plan 196-07. Keeping the vocabulary intact is what lets the
salvaged ledger's own tests continue to pass unchanged in plan 196-01.
</interfaces>
