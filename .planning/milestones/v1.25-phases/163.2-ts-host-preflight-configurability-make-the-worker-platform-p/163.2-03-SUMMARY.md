# Phase 163.2 Plan 03: TS Host Preflight Configurability Summary

**Replaced the TS host's hardcoded 20s preflight timeout with the shared `AETHER_PREFLIGHT_TIMEOUT` env knob (45s default, matching Go), isolated the probe's working directory to a throwaway temp dir with cwd fallback on creation failure, wired a loud `AETHER_SKIP_PREFLIGHT` notice on every TS preflight path, surfaced the Go adapter's cache/skip notice to the user's terminal, and rebuilt the committed `dist/` bundle so the fix actually reaches downstream repos.**

## Performance

- **Duration:** ~8 min (first commit to last: 18:01:36 → 18:07:35 local)
- **Tasks:** 3
- **Files modified:** 10 (5 source/test, 5 dist)

## Accomplishments
- `platform-dispatcher.ts` no longer contains the `20_000` literal that killed the 27 July M4L `/ant-plan` run; the probe budget now comes from `resolvePreflightTimeoutMs()` with a 45s default identical to Go's `hostedPreflightTimeout`
- The probe runs in a fresh `aether-preflight-*` `mkdtempSync` directory via a swappable `_makePreflightTempDirRef` factory, cleaned up in a `finally` block; a factory throw degrades to the caller's `cwd` instead of failing the preflight (proven by a forced-throw test)
- `AETHER_SKIP_PREFLIGHT` (truthy: `1`, `true`, `yes`, `on`) short-circuits `preflightHostWorkerDispatch` before either the compat or production branch runs, always printing the exact skip notice to stderr first
- `GoWorkerAdapterResponse.preflight?.notice` is now written to stderr by `preflightGoWorkerProvider` instead of being silently discarded
- `npm run build --prefix .aether/ts-host` was rerun and the regenerated `dist/` files are committed, so the fix reaches repos that only consume the published bundle
- Installed missing `.aether/ts-host` npm dependencies (node_modules was absent in this worktree) as a blocking-issue fix so `typecheck`/`test`/`build` could run at all

## Decisions Made
- Followed the plan's read-first guidance and mirrored the file's existing `_detectAvailablePlatformsRef` seam shape exactly for the new temp-dir factory, rather than inventing a different test-injection pattern
- Placed the skip-switch tests in `host-integration.test.ts` (driving `runDispatchedPlanCommand`) rather than exporting `preflightHostWorkerDispatch`, per the plan's explicit fallback instruction
- Used `realpathSync` to compare the fallback-cwd test's recorded directory against the passed `cwd`, because macOS resolves `TMPDIR` through `/private` and a subprocess's `pwd -P` reports the physical path while `mkdtempSync()`'s return value is the logical one — this is a test-correctness fix, not a behavior change
