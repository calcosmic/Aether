# Plan 147-02: Wisdom and Spawn Tests (Hive, Spawn)

**Objective:** Create dedicated test files for hive.go and spawn.go that prove data-persistence paths for cross-colony wisdom and spawn tracking.

## must_haves

- `hive_test.go` covers hive-init, hive-store, hive-read, hive-abstract, hive-promote CLI commands
- `spawn_test.go` covers spawn-tree-load, spawn-tree-active, and spawn tracking edge cases
- Hub-level hive commands redirect `AETHER_HUB_DIR` to temp directory
- Spawn tests verify `spawn-tree.txt` and spawn tracking state

## tasks

### Task 1: Create hive_test.go

<read_first>
- cmd/hive.go
- cmd/hive_runtime_test.go (existing pattern)
- cmd/ceremony_emitter_test.go (has hive-promote tests — reference pattern)
- cmd/helpers_test.go
</read_first>

<action>
Create `cmd/hive_test.go` with tests for:
1. `hive-init` — initializes `~/.aether/hive/wisdom.json`, verifies file creation
2. `hive-store` — stores wisdom entry, verifies it appears in wisdom.json
3. `hive-read` — reads wisdom filtered by domain tags
4. `hive-abstract` — abstracts an instinct into cross-colony wisdom text
5. `hive-promote` — promotes an instinct to hive wisdom

Each test must:
- Redirect `AETHER_HUB_DIR` to `t.TempDir()`
- Use `saveGlobals(t)` and `resetRootCmd(t)`
- Verify both JSON output and hub `wisdom.json` contents
</action>

<acceptance_criteria>
- `go test ./cmd/... -run TestHive -count=1` passes
- At least 5 tests covering init, store, read, abstract, promote
- Hub wisdom.json verified in temp directory
</acceptance_criteria>
