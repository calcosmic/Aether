# Plan 147-03: Orchestration Tests (Autopilot, Council)

**Objective:** Create dedicated test files for autopilot.go and council.go that prove their state-machine and deliberation data-persistence paths work.

## must_haves

- `autopilot_test.go` covers autopilot-init, update, status, stop, check-replan
- `council_test.go` covers council-deliberate, advocate, challenger, sage, history, budget-check
- Autopilot tests verify `autopilot/state.json` persistence
- Council tests verify `council/history.json` persistence

## tasks

### Task 1: Create autopilot_test.go

<read_first>
- cmd/autopilot.go
- cmd/compatibility_cmds_test.go (has autopilot tests — reference pattern)
- cmd/helpers_test.go
</read_first>

<action>
Create `cmd/autopilot_test.go` with tests for:
1. `autopilot-init` — initializes autopilot state, verifies `autopilot/state.json`
2. `autopilot-update` — updates phase status, verifies state mutation
3. `autopilot-status` — reads current autopilot state
4. `autopilot-stop` — stops autopilot, verifies state reflects stopped
5. `autopilot-check-replan` — checks replan conditions

Each test must:
- Use `newTestStore(t)` for isolated storage
- Verify `autopilot/state.json` content before and after mutations
- Use `saveGlobals(t)` and `resetRootCmd(t)`
</action>

<acceptance_criteria>
- `go test ./cmd/... -run TestAutopilot -count=1` passes
- At least 5 tests covering init, update, status, stop, check-replan
- Autopilot state JSON verified after each mutation
</acceptance_criteria>
