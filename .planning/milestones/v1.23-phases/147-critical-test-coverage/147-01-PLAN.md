# Plan 147-01: Core Data-Persistence Tests (Event Bus, Queen, Instinct, Midden)

**Objective:** Create dedicated test files for eventbus.go, queen.go, instinct.go, and midden_cmds.go that prove every data-persistence path works.

## must_haves

- Each source file has a corresponding `_test.go` file
- Tests verify JSON load/save paths, JSONL append paths, and filesystem state after execution
- Tests use the established `newTestStore` + `rootCmd.Execute()` pattern
- Hub-level commands (queen) redirect `AETHER_HUB_DIR` to avoid modifying `~/.aether/`

## tasks

### Task 1: Create eventbus_test.go

<read_first>
- cmd/eventbus.go
- cmd/eventbus_subscribe_test.go (existing pattern)
- cmd/helpers_test.go or cmd/testing_main_test.go (for newTestStore, saveGlobals, resetRootCmd)
</read_first>

<action>
Create `cmd/eventbus_test.go` with tests for:
1. `event-bus-publish` — publishes an event, verifies it appears in JSONL file via `event-bus-query`
2. `event-bus-query` — returns matching events from the JSONL log
3. `event-bus-replay` — replays events to stdout
4. `event-bus-cleanup` — removes expired events based on TTL

Each test must:
- Call `saveGlobals(t)` and `resetRootCmd(t)` first
- Use `newTestStore(t)` for isolated storage
- Execute via `rootCmd.Execute()`
- Verify both JSON envelope output and filesystem state
</action>

<acceptance_criteria>
- `go test ./cmd/... -run TestEventBus -count=1` passes
- At least 4 tests covering publish, query, replay, cleanup
- Each test verifies filesystem state after execution
</acceptance_criteria>

## risks

- Event bus tests are timing-sensitive — use short poll intervals and explicit sleeps
- Queen tests modify hub files — must redirect `AETHER_HUB_DIR` in every test
- Cross-test pollution if `saveGlobals`/`resetRootCmd` missed
