# Plan 149-04: Verify Deterministic Commands Never Spawn Agents

**Objective:** Prove that display, signal, session, and admin commands (classified as "deterministic" in Phase 146) never dispatch agents regardless of context.

## must_haves

- A test verifies each deterministic command produces zero agent dispatches
- The test covers: status, flags, pheromones, focus, redirect, feedback, history, patrol, preferences, memory-details, verify-castes, bump-version, maturity
- The test fails if any deterministic command spawns an agent

## tasks

### Task 1: Identify all deterministic commands

<read_first>
- cmd/command_guide.go (command classifications)
- cmd/audit_catalog.go or similar (classification from Phase 146)
</read_first>

<action>
1. Read the command catalog to find all commands classified as:
   - `display` (status, flags, pheromones, history, patrol, etc.)
   - `signal` (focus, redirect, feedback)
   - `session` (preferences, memory-details, verify-castes)
   - `admin` (bump-version, maturity, update, migrate-state)
2. For each command, check its implementation file for any agent spawning
3. Document: COMMAND → FILE → SPAWNS AGENTS? (yes/no)
4. Flag any command that DOES spawn agents as a bug to fix
</action>

<acceptance_criteria>
- A markdown table lists all deterministic commands with their spawn status
- Any command that spawns agents is flagged as a bug
</acceptance_criteria>

### Task 2: Fix any deterministic commands that spawn agents

<read_first>
- Any command files flagged in Task 1 as spawning agents
</read_first>

<action>
1. For each flagged command, determine why it spawns agents
2. Decide: is the spawn necessary or accidental?
3. If accidental, remove the spawn logic
4. If necessary, reclassify the command (not deterministic)
5. Add a comment explaining why the command must not spawn agents
</action>

<acceptance_criteria>
- All previously-flagged commands are either fixed or reclassified
- No deterministic command spawns agents
</acceptance_criteria>

### Task 3: Add comprehensive deterministic command test

<read_first>
- cmd/command_guide.go (for command list)
- cmd/dispatch_contract.go (for spawn tracking)
- cmd/spawn.go or cmd/spawn_track.go (for spawn recording)
</read_first>

<action>
1. Create `cmd/deterministic_spawn_test.go` with tests that:
   - Initialize a test store with colony state
   - Run each deterministic command
   - Check that no spawn tree entries were created
   - Check that no worker dispatches were recorded
   - Check that the command completed without spawning subagents
2. Commands to test:
   - status, flags, pheromones, focus, redirect, feedback
   - history, patrol, preferences, memory-details
   - verify-castes, bump-version, maturity
3. Use the same test pattern as existing command tests
</action>

<acceptance_criteria>
- `go test ./cmd/... -run TestDeterministicCommandsNoSpawn -count=1 -v` passes
- The test covers at least 12 deterministic commands
- `go test ./cmd/... -count=1` passes (full suite)
</acceptance_criteria>

## verification

```bash
go test ./cmd/... -run 'TestDeterministic' -count=1 -v
go test ./cmd/... -count=1
```

## risks

- Some "deterministic" commands may legitimately need to spawn agents for edge cases
- If a command needs to spawn, it's a classification error, not a code bug
- The test must use real command execution, not mock, to catch actual spawning
