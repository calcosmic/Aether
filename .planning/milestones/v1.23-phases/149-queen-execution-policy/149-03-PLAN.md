# Plan 149-03: Document Caste Relevance System in Playbooks

**Objective:** Add documentation to playbooks explaining how the Queen decides which castes to spawn, so users can predict spawn behavior from phase characteristics.

## must_haves

- Playbooks document the caste relevance scoring system
- Playbooks document the spawn threshold per flow type
- Playbooks document the always-required castes per flow+depth
- Playbooks document the spawn budget cap per flow+depth
- The documentation is correct per `cmd/caste_relevance.go` and `cmd/queen_spawn_budget.go`

## tasks

### Task 1: Create caste relevance reference document

<read_first>
- cmd/caste_relevance.go (full file)
- cmd/queen_spawn_budget.go (full file)
- .aether/docs/command-playbooks/ (existing playbook structure)
</read_first>

<action>
1. Create `.aether/docs/command-playbooks/caste-relevance-reference.md` containing:
   - A table of all 26 castes with their keywords and base scores
   - The spawn threshold per flow type (build/continue=30, plan=40, colonize/swarm=35, seal=50)
   - The always-required castes per flow+depth combination
   - The spawn budget (max workers) per flow+depth
   - The suppression rules (which castes are excluded from which flows)
   - Examples: "A phase named 'Implement auth system' in build mode → builder (100), gatekeeper (100), architect (100), watcher (20+keywords), probe (15+keywords)"
2. Keep it factual and reference the Go source functions by name
</action>

<acceptance_criteria>
- The reference document exists and is under 150 lines
- A user can read it and predict which castes will spawn for a given phase
- All 26 castes from `casteRelevanceRegistry` are listed
</acceptance_criteria>
