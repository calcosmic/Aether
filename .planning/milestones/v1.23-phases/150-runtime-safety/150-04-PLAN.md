# Plan 150-04: Worktree Safety -- Merge at Build-Complete + Orphan Detection

**Objective:** Worktree branches merge back when build completes, not only during continue. Pre-build checks warn about orphaned branches from prior interrupted builds.

## must_haves

- Worktree merge-back runs during build-finalize, not only continue-advance
- Merge-back failures are blocking (stop the build)
- Pre-build check scans for orphaned worktree branches and warns
- Orphaned branches are listed with their source phase and file count
- A test verifies merge-at-build and orphan detection

## tasks

### Task 1: Extract merge-back into reusable function

<read_first>
- cmd/codex_continue.go (continue-advance worktree merge-back)
- cmd/codex_build_worktree.go (worktree utilities)
- .aether/docs/command-playbooks/continue-advance.md (merge-back step)
</read_first>

<action>
1. In `cmd/codex_build_worktree.go`, create a new exported function:
   ```go
   func mergeWorktreeBranches(store *storage.Store, phase colony.Phase) error
   ```
   a. Collect all worktree branches for the given phase
   b. Merge each branch back to the target branch
   c. Return error if any merge fails
   d. Log each merge operation
2. Move the existing merge-back logic from continue-advance into this function
3. Replace the inline logic in continue-advance with a call to this function
</action>

<acceptance_criteria>
- Function is exported and reusable
- Existing continue-advance behavior is preserved
- Function returns error on merge failure
</acceptance_criteria>

### Task 2: Call merge-back from build-finalize

<read_first>
- cmd/codex_build_finalize.go (build completion flow)
- cmd/codex_build.go (build state and phase tracking)
</read_first>

<action>
1. In build-finalize, after the build packet is created but before marking the phase complete:
   a. Check if parallel_mode is "worktree"
   b. If worktree mode, call `mergeWorktreeBranches(store, currentPhase)`
   c. If merge fails, mark the build as "completed-with-warnings" and create a blocker
   d. Do NOT mark the phase complete until merge succeeds or is explicitly bypassed
2. Add `--skip-merge` flag to build-finalize for emergency bypass
3. Update the build-complete playbook to document the new merge step
</action>

<acceptance_criteria>
- Merge-back runs during build-finalize in worktree mode
- Merge failure blocks phase completion
- --skip-merge flag exists for bypass
- Build-complete playbook documents the step
</acceptance_criteria>

### Task 3: Add pre-build orphan detection

<read_first>
- cmd/codex_build.go (build start/dispatch)
- cmd/build_flow_cmds.go (build command entry points)
- cmd/codex_build_worktree.go (worktree allocation)
</read_first>

<action>
1. Before allocating worktrees for a new build:
   a. Run `git worktree list` to find existing worktrees
   b. Check if any worktree branches are NOT associated with the current phase
   c. For each orphaned branch:
      - Determine the source phase (from branch name pattern)
      - Count files changed on that branch
      - Add to orphan report
   d. If orphans exist:
      - Print a warning with orphan list
      - Offer: "Run `aether build-reconcile --phase N` to recover" or "Continue and ignore"
      - If `--force` flag is set, proceed anyway
2. Add `--force` flag to build command for bypassing orphan warnings
</action>

<acceptance_criteria>
- Orphan detection runs before every build in worktree mode
- Warning lists orphaned branches with phase and file count
- --force flag bypasses the warning
- Detection does not block in-repo mode
</acceptance_criteria>

## risks

- Worktree merge conflicts are hard to resolve automatically
- Pre-build orphan detection adds latency to every build command
- `--force` bypass may hide real problems
- Git worktree list format may vary across git versions
