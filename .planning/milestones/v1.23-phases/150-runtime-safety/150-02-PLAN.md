# Plan 150-02: Status Reports Unreconciled Worker Changes

**Objective:** Running `aether status` shows whether there are unreconciled worker changes from incomplete builds, so the user always knows if unrecorded work exists.

## must_haves

- `aether status` detects when tracked files have changes not reflected in the current build packet
- Status shows a "Reconciliation" section with: changed files count, recommended action
- The detection uses git diff / git status, not new tracking files
- A test verifies the reconciliation section appears when unrecorded changes exist

## tasks

### Task 1: Detect unreconciled changes

<read_first>
- cmd/status.go (loadSpawnActivitySummary, renderSpawnActivity)
- cmd/recover.go (existing recovery checks)
- cmd/recovery_classify.go (stuck-state classification)
</read_first>

<action>
1. Add `detectUnreconciledChanges(store) -> unreconciledChangesResult` function:
   a. Run `git status --short` in the repo root
   b. If there are modified/added/deleted files, collect the list
   c. Check if the current phase has a build packet with worker results
   d. Compare: are the changed files listed in any worker result's FilesCreated/FilesModified?
   e. If changed files exist but are NOT in any worker result, flag as unreconciled
2. Return a struct with:
   - HasUnreconciledChanges bool
   - ChangedFiles []string
   - Recommendation string (e.g., "Run `aether build-reconcile` to record these changes")
</action>

<acceptance_criteria>
- Detection function exists and returns accurate results
- Uses git status, not new tracking files
- Compares against existing worker results in colony state
</acceptance_criteria>

### Task 2: Add reconciliation section to status output

<read_first>
- cmd/status.go (render functions, visual output)
- cmd/codex_visuals.go (visual formatting helpers)
</read_first>

<action>
1. In status output (both JSON and visual modes):
   a. After the spawn/worker section, add a "Reconciliation" section
   b. If no unreconciled changes: show "All changes recorded" or omit section
   c. If unreconciled changes exist:
      - Visual: render a warning banner with file count and recommendation
      - JSON: include `unreconciled_changes` object with `files` and `recommendation`
2. In visual mode, use an appropriate emoji/warning style
3. Keep the section under 5 lines in visual mode
</action>

<acceptance_criteria>
- Status JSON includes unreconciled_changes when present
- Status visual shows a clear warning when unreconciled changes exist
- Status is clean when no unreconciled changes exist
</acceptance_criteria>
