# Plan 150-03: Build-Reconcile Command

**Objective:** If a build is interrupted after workers complete but before finalization, `aether build-reconcile` discovers the completed work on disk and records it into colony state -- no code is silently lost.

## must_haves

- `aether build-reconcile` command exists and is registered
- It scans git diff / git status for changes not in the current build packet
- It creates a synthetic build packet with the discovered changes
- It records the synthetic packet into colony state
- A test verifies the full reconcile flow

## tasks

### Task 1: Implement build-reconcile command

<read_first>
- cmd/codex_build_finalize.go (build packet structure)
- cmd/codex_build.go (build state tracking)
- pkg/colony/ (colony state structures)
</read_first>

<action>
1. Create `cmd/build_reconcile.go` with a `build-reconcile` command:
   a. Load the current colony state
   b. Determine the current phase
   c. Check if a build packet already exists for this phase
   d. Run `git diff --name-status` to find all changed files
   e. Categorize changes: added (A), modified (M), deleted (D)
   f. Create a synthetic WorkerResult for each caste that has changes:
      - WorkerName: "reconcile-{caste}"
      - Status: "completed"
      - FilesCreated: added files
      - FilesModified: modified files
      - FilesDeleted: deleted files
      - Summary: "Recovered from interrupted build"
   g. Create or append to the build packet
   h. Save the build packet to colony state
   i. Output the reconciliation summary
2. Add `--dry-run` flag to preview without writing
</action>

<acceptance_criteria>
- Command is registered and runnable
- Dry-run mode shows what would be recorded without writing
- Real mode creates synthetic build packet
- Output includes file counts by category
</acceptance_criteria>

### Task 4: Add pre-dispatch checkpoint

<read_first>
- cmd/codex_build.go (build dispatch start)
- cmd/codex_build_worktree.go (worktree allocation)
</read_first>

<action>
1. Before dispatching build workers, record a checkpoint:
   a. Capture `git status --short` hash/state
   b. Save to `.aether/data/build-checkpoint-{phase-id}.json`
   c. Include: timestamp, git HEAD, tracked file list
2. Build-reconcile uses this checkpoint to determine what changed since dispatch
3. Clean up old checkpoints during continue or seal
</action>

<acceptance_criteria>
- Checkpoint is created before build dispatch
- Checkpoint includes git HEAD and file list
- Build-reconcile uses checkpoint for comparison
- Old checkpoints are cleaned up
</acceptance_criteria>

## risks

- Synthetic packets may confuse downstream tools that expect real worker metadata
- Git state in worktree mode is complex -- reconcile must handle multiple worktrees
- Checkpoints add files to .aether/data/ -- need cleanup to avoid bloat
