# Plan 148-02: Hypothesis Lifecycle in Learning System

**Objective:** Add first-class hypothesis tracking (hypothesis → validated/disproven) to the learning system so learnings evolve with evidence rather than staying static.

## must_haves

- `learn.Entry` has a `Status` field with values: `hypothesis`, `validated`, `disproven`
- New CLI commands: `learning-propose` (create hypothesis), `learning-validate` (promote to validated), `learning-disprove` (mark disproven)
- The continue-finalize path stores new learnings as `hypothesis` status by default
- Auto-promotion from `memory.Pipeline` can upgrade `hypothesis` to `validated` when trust score crosses threshold

## tasks

### Task 1: Add Status and ParentID to learn.Entry

<read_first>
- pkg/learn/learn.go (Entry struct definition)
- pkg/learn/colony_store.go (Add, List, Get methods)
</read_first>

<action>
1. Add `Status string` field to `learn.Entry` struct with default value `"hypothesis"`
2. Add `ParentID string` field for linking related entries (e.g., a validated entry links to its original hypothesis)
3. Define constants: `StatusHypothesis = "hypothesis"`, `StatusValidated = "validated"`, `StatusDisproven = "disproven"`
4. Update `ColonyStore.Add()` to set `Status = StatusHypothesis` if empty
5. Update `ColonyStore.List()` to support filtering by status
6. Ensure backward compatibility: existing entries without Status field default to hypothesis on read
</action>

</acceptance_criteria>

### Task 3: Wire hypothesis lifecycle into continue-finalize and auto-promotion

<read_first>
- cmd/codex_continue_finalize.go (captureLearning closure)
- pkg/memory/pipeline.go (auto-promotion logic)
- pkg/memory/trust.go (trust scoring)
</read_first>

<action>
1. In continue-finalize's learning capture, set `entry.Status = learn.StatusHypothesis` for all newly captured learnings
2. In `pkg/memory/pipeline.go`, when auto-promoting an observation to instinct:
   - If the observation originated from a learning entry with StatusHypothesis
   - AND the trust score is >= 0.8
   - Update the learning entry status to StatusValidated via ColonyStore
3. Add a comment in the pipeline explaining the promotion threshold (0.8 = high confidence)
4. Do NOT auto-promote to StatusDisproven — that requires explicit human judgment via learning-disprove command
</action>

<acceptance_criteria>

</acceptance_criteria>
