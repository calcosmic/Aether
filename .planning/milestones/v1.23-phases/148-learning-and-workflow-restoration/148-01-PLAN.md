# Plan 148-01: Deep Learning Extraction in Continue-Finalize

**Objective:** Replace shallow placeholder learning capture with deep extraction from worker outputs, findings, and reusable lessons.

## must_haves

- Continue-finalize extracts actual content from worker `Findings`, `ReusableLessons`, and `Recommendations` fields
- Learning entries contain meaningful, phase-specific insights instead of generic `"Phase N completed successfully"` strings
- Evidence collection captures worker-specific contributions with proper source attribution
- Privacy scan still runs before storage; secrets are still blocked

### Task 2: Implement deep learning content extraction

<read_first>
- cmd/codex_continue_finalize.go (full file, especially workerFlow iteration and captureLearning)
- pkg/learn/learn.go (Entry type definition)
</read_first>

<action>
1. In the captureLearning closure, replace the single-phase-name content construction with structured extraction:
   - Iterate over workerFlow steps
   - For each step with Status="completed", extract Findings, ReusableLessons, Recommendations
   - Build a structured content string that includes:
     - Phase name and ID
     - Per-worker summaries (caste, name, task, key findings)
     - Reusable lessons discovered
     - Recommendations for future phases
2. Keep the privacy scan (privacyScan() + learn.ClassifyEntry()) — do NOT remove or weaken it
3. Keep the existing Evidence struct population (trust scoring, gate results, worker evidence)
4. The content field should now be a multi-line structured string, not a single generic sentence
</action>

<acceptance_criteria>
- After running a continue-finalize simulation, the learning entry Content field contains per-worker findings, not just the phase name
- The Content field includes at minimum: phase ID, worker caste/name, and any non-empty Findings/ReusableLessons
- Privacy scan still runs: entries containing test API keys or secrets are classified as ClassBlocked and NOT stored
- Existing tests in codex_continue_test.go still pass
</acceptance_criteria>
