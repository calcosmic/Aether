# Plan 146-04: Add CI Gate for Unclassified Commands

**Objective:** Prevent command classification from drifting by adding a CI check that fails if any catalog entry is missing `classification` or `historical_presence`.

## must_haves

- CI fails when a PR adds a command without classification
- CI fails when classification metadata is malformed
- Local verification script runs fast (< 2s)

## tasks

### Task 1: Create catalog verification script

<read_first>
- cmd/testdata/command_catalog.json
- scripts/classify_commands.py
- scripts/build_reliability_matrix.py
</read_first>

<action>
Create `scripts/verify_catalog_classified.py` that:
1. Loads `cmd/testdata/command_catalog.json`
2. Verifies every entry has:
   - `classification` field with a valid value (public_lifecycle, public_utility, internal_runtime, alias, deprecated)
   - `since_version` field (non-empty string)
   - `historical_presence` field (object with at least 5 version keys)
3. Prints a summary: total commands, missing classification, missing since_version, missing historical_presence
4. Exit code 0 if all pass, 1 if any fail
5. With `--strict` flag: also verify that classification counts are within expected ranges (public_lifecycle: 10-25, alias: 5-15, internal_runtime: 0-5, deprecated: 0-10)
</action>

<acceptance_criteria>
- `scripts/verify_catalog_classified.py` exists and runs in under 2 seconds
- Running it on current catalog exits 0
- Running it on a catalog with missing fields exits 1 with clear error message
- `--strict` flag validates classification count ranges
</acceptance_criteria>

### Task 2: Add CI workflow step

<read_first>
- .github/workflows/ci.yml (if exists)
- scripts/verify_catalog_classified.py
</read_first>

<action>
Modify `.github/workflows/ci.yml` (or create if missing):
1. Add a `verify-catalog` job that runs after tests
2. Step: `python3 scripts/verify_catalog_classified.py --strict`
3. Job fails if verification exits non-zero
4. Include in the Go test workflow or as a separate check
</action>

<acceptance_criteria>
- CI workflow file exists and includes a verify-catalog step
- The step runs `python3 scripts/verify_catalog_classified.py --strict`
- CI fails if catalog verification fails
- CI passes if catalog is fully classified
</acceptance_criteria>
