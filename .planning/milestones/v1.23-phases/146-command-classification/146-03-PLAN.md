# Plan 146-03: Build Historical Reliability Matrix from Git Tags

**Objective:** Extend the catalog with `historical_presence` data showing which commands existed in each release era (v5.4.0 through v1.21), then integrate this into `aether audit-catalog` output.

## must_haves

- Every catalog entry has a `historical_presence` object mapping version tags to boolean presence
- `aether audit-catalog --reliability` outputs a matrix showing command stability across eras
- Matrix is generated from actual git history, not hardcoded

## tasks

### Task 1: Build historical presence scraper

<read_first>
- cmd/testdata/command_catalog.json
- .planning/phases/146-command-classification/146-RESEARCH.md
</read_first>

<action>
Create `scripts/build_reliability_matrix.py` that:
1. Loads the enriched `cmd/testdata/command_catalog.json`
2. For each git tag in `[v5.4.0, v1.10, v1.11, v1.12, v1.13, v1.14, v1.17, v1.18, v1.19, v1.20, v1.21]`:
   a. List all `cmd/*.go` files in that tag (excluding tests)
   b. Extract command names from `Use:` lines via regex
   c. Build a set of commands present in that era
3. For each catalog entry, add `historical_presence` field:
   ```json
   "historical_presence": {
     "v5.4.0": false,
     "v1.10": true,
     "v1.21": true
   }
   ```
4. Cache results in `scripts/.reliability_cache.json` to avoid re-scanning
5. Write updated catalog back to `cmd/testdata/command_catalog.json`
</action>

<acceptance_criteria>
- `scripts/build_reliability_matrix.py` exists and runs successfully
- Every catalog entry has `historical_presence` with all 11 version tags
- `audit-catalog` entry shows `v1.10: false, v1.17: true`
- `init` entry shows `v5.4.0: true` (or the earliest tag where it appeared)
</acceptance_criteria>

### Task 2: Add reliability matrix output to audit-catalog

<read_first>
- cmd/audit_catalog.go
- cmd/audit_catalog_test.go
- cmd/testdata/command_catalog.json
</read_first>

<action>
Extend `cmd/audit_catalog.go`:
1. Add `--reliability` flag that outputs a historical reliability matrix
2. Matrix format: markdown table with columns `Command`, `v5.4.0`, `v1.10`, `v1.11`, ..., `v1.21`, `Stability Score`
3. `Stability Score` = count of `true` values / total tags * 100 (rounded)
4. Sort by stability score descending, then alphabetically
5. Also support `--reliability --json` for machine-readable output
</action>

<acceptance_criteria>
- `aether audit-catalog --reliability` prints a markdown matrix
- `aether audit-catalog --reliability --json` prints JSON with `historical_presence` and `stability_score` for each command
- Matrix includes all 11 historical version columns
- Stability score is a percentage (0-100)
- Commands present in all eras show stability score 100
</acceptance_criteria>

## verification

```bash
# Run scraper
python3 scripts/build_reliability_matrix.py

# Verify output
go test ./cmd/... -run TestAuditCatalog -v

# Manual check
./aether audit-catalog --reliability | head -20
./aether audit-catalog --reliability --json | python3 -c "
import sys, json
d = json.load(sys.stdin)
cmd = next(e for e in d if e['name'] == 'init')
print(f'init stability: {cmd[\"stability_score\"]}%')
print(f'init historical: {cmd[\"historical_presence\"]}')
"
```

## risks

- Git tag scraping is slow (~30s for 11 tags): mitigated by caching
- Some tags may not exist locally: script should skip missing tags gracefully
- Command names extracted from `Use:` lines may mismatch catalog names: validate and warn
