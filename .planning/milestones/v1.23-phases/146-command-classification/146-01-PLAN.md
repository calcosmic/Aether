# Plan 146-01: Enrich Command Catalog with Classification Metadata

**Objective:** Add `classification` and `since_version` fields to every entry in `cmd/testdata/command_catalog.json` so the catalog becomes the single source of truth for command metadata.

## must_haves

- Every catalog entry has a `classification` field with one of: `public_lifecycle`, `public_utility`, `internal_runtime`, `alias`, `deprecated`
- Every catalog entry has a `since_version` field showing the first version tag where the command appeared
- Classification heuristics are documented and reproducible

## tasks

### Task 1: Define classification heuristics

<read_first>
- cmd/testdata/command_catalog.json
- .planning/phases/146-command-classification/146-RESEARCH.md
</read_first>

<action>
Write a Python script at `scripts/classify_commands.py` that:
1. Loads `cmd/testdata/command_catalog.json`
2. Applies classification heuristics:
   - `public_lifecycle`: init, plan, build, continue, seal, colonize, run, entomb (and their finalize/ceremony subcommands)
   - `alias`: Commands whose short_description contains "alias" or whose name ends in `-xml` and maps to another command (watch, pheromone-export-xml, etc.)
   - `internal_runtime`: hook-*, autofix-*, error-pattern-check
   - `deprecated`: Commands explicitly marked deprecated in description
   - `public_utility`: Everything else
3. For commands under `host` parent: classify host build/continue/plan/seal/colonize as `public_lifecycle`, host oracle/swarm/lifecycle as `public_utility`, host watch as `alias`
4. Outputs the enriched catalog back to `cmd/testdata/command_catalog.json` with `classification` field added to every entry
</action>

<acceptance_criteria>
- `scripts/classify_commands.py` exists and is executable
- Running `python3 scripts/classify_commands.py` modifies `cmd/testdata/command_catalog.json` without removing any entries
- Every entry in the catalog has a `classification` field after running
- Classification counts match: ~16 public_lifecycle, ~8 alias, ~2 internal_runtime, 0 deprecated, rest public_utility
</acceptance_criteria>

### Task 2: Add since_version field

<read_first>
- cmd/testdata/command_catalog.json
- scripts/classify_commands.py
</read_first>

<action>
Extend `scripts/classify_commands.py` to:
1. For each command, check git tags `v1.10`, `v1.11`, `v1.12`, `v1.13`, `v1.14`, `v1.17`, `v1.18`, `v1.19`, `v1.20`, `v1.21`, `v5.4.0` to find the earliest tag where the command appears in `cmd/*.go` files
2. Add `since_version` field to each catalog entry with the earliest tag found (or `"current"` if not in any tag)
3. Cache git history results to avoid re-scanning on every run
4. Output the enriched catalog back to `cmd/testdata/command_catalog.json`
</action>

<acceptance_criteria>
- Every catalog entry has a `since_version` field
- `audit-catalog` entry shows `since_version: "v1.17"`
- `feedback` and `redirect` entries show `since_version: "current"`
- Commands present in v5.4.0 show `since_version: "v5.4.0"`
</acceptance_criteria>

## verification

```bash
# Check every entry has classification and since_version
python3 -c "
import json
c = json.load(open('cmd/testdata/command_catalog.json'))
missing_cls = [e['name'] for e in c if 'classification' not in e]
missing_ver = [e['name'] for e in c if 'since_version' not in e]
print(f'Missing classification: {len(missing_cls)}')
print(f'Missing since_version: {len(missing_ver)}')
assert len(missing_cls) == 0 and len(missing_ver) == 0
"
```

## risks

- Classification disagreements: resolved by documented heuristics in the script
- Git tag scraping is slow: mitigated by caching
