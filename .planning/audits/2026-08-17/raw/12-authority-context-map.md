## Task 2 — Context flow (interactive build path)

**EAGER — every worker regardless of task.** Prompt = context_capsule + brief + skill_section (build.md:272).
- Capsule (once per manifest, CONTEXT-03 dedup — codex_build.go:1893-1902): compact colony-prime, 4,000-char budget, up to 18 sections: state, review depth, charter, pheromones, instincts, ALL key decisions, ALL phase learnings, handoffs (5), hive wisdom (5), learned memory (20), global QUEEN.md, user preferences, local QUEEN wisdom, clarified intent, blockers (never trimmed), medic health, activity tail (colony_prime_context.go:434-974).
- Brief (per dispatch): assignment, objective, deps/constraints/hints/criteria, codegraph (2,200), survey pointers, phase research (3,500), colony research (3,000), **pheromones again** (8 signals), per-caste baseline, **handoffs again** (5 records), expected output, verification commands.
- Skill section: 8,000-char budget PLUS references appended after it (up to 5 docs, codex_build.go:3050-3051, references.go:227-233) — references sit OUTSIDE the 8K budget.

**Eager mass:** the runtime's own derived ceiling is 23,700 chars (~6K tokens)/worker (build_print_brief.go:295-301). Colony research's named 3,000 budget is NOT summed into that ceiling — a small under-count. build.md:259 reports real inline briefs of 6-22KB.

**LAZY:** survey files, plan artifacts, phase-research files delivered as paths; referenced docs likewise.

**DUPLICATED — confirmed, worse than pheromones alone:**
1. Pheromones ×2 every path: capsule "Active Signals" + brief "## Pheromone Signals" (codex_build.go:3114-3124); ×3 on the subprocess path (separate PheromoneSection prompt part, :1711; pkg/codex/worker.go:381).
2. Handoffs ×2: capsule worker_handoffs (colony_prime_context.go:695-706) + per-dispatch HandoffSection embedded in the brief (:3094-3095, 3135-3139) — same renderer (codex_dispatch_contract.go:704, cap 5, store cap 100).
3. Hive ×2 on the TS-host path (capsule hive_wisdom + TS hive_section).

**Other-repo leakage (post-Phase-180):** references_scope_test.go locks only docs tagged `scope: aether-internal` excluded outside the Aether source repo (references.go:191-300). NOT scoped: untagged hub references, global QUEEN.md wisdom, hive entries (domain-tagged but content can be Aether-flavored), learned memory. **Biggest single irrelevancy risk:** the always-on cross-colony wisdom trio (global QUEEN.md + hive + learned memory, up to ~25 entries) injected into every worker in every repo with no task-relevance filter — the CalVault failure class, one scoping tag from recurring.

**Measurement without mutation — yes:** `aether build … --print-brief` (build_print_brief.go) deliberately does NOT reuse the plan-only path because that path mutates (opens a build attempt); it calls only readers and prints a per-section composition table + budget checklist (:21-26, 143-183, 356-426). Only side effect: session-cache housekeeping (context.go:461-462). Running with --full on a live mid-project colony turns every estimate into a measurement.

**Bottom line:** five genuine split-brains — (1) three build executors with two finalize routes and three retry models, (2) opt-in-guard state-mutate vs duplicated continue advance blocks (one missing the supersession check), (3) TS host as a second hive/context composer, (4) resume's force-GC vs recover's dirty-worktree evidence with no enforced order (data-loss class), (5) six unledgered retry budgets. Model routing, caste selection, ceremonies, and state-write ownership are genuinely single-authority; model-routing.yaml is a stale orphan worth deleting.
