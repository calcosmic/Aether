<objective>
Make the program greet the owner with where things stand when a new chat opens,
and delete the instruction that asked the assistant to remember to do it.

Purpose: today CLAUDE.md, AGENTS.md, README.md and both copies of the colony
rules file each ask the assistant to check a session file on the first message
of a conversation and report what it finds. That is a request, not a mechanism —
it runs only when it is noticed. Criterion 4 replaces it with a hook the runtime
owns, rendering the same card every other command will render.
Output: the session-start hook, its wiring, the removal of the five requests,
and a widened reachability scan that lets the tolerated-orphan list shrink.
</objective>

The hook renders plan 197-02's card from plan 197-01's resolver. It composes
nothing of its own. If the card is missing something the greeting needs, add it
to the card, not to the hook — a second greeting renderer is the drift this
phase exists to end.

The hook is read-only. `hook-pre-compact` in the same file writes a session
summary; this one must not. The repository shipped two inspection commands that
wrote to state despite documenting that they did not, and both are now locked by
named tests; this plan adds the third such lock rather than the third such
defect.

repositories that are not running a colony, and a greeting there is noise. Use
the loader's no-colony signal from plan 197-01 rather than treating an empty
state as a fresh project.

196 added one subcommand and broke all of them; a targeted test run missed it.
Refresh `command_catalog.json`, `parity_snapshot.json` and `regression_snapshot.json`
with the repository's own `-update-golden` flag, and check the severity audit and
the visual-writer discipline test explicitly in this plan's verification.

The reachability scanner's shipped-hook corpus currently covers a hooks
directory and a scripts directory but not `.claude/settings.json`, which is why
the three existing hook commands sit on the tolerated-orphan list. Widen the
corpus to read the command strings out of that settings file. Then regenerate
the live allowlist with the flag that already exists for it. The frozen baseline
must not be touched — the repository's own escape-hatch test asserts that, and
the allowlist's rule is that it may only shrink.

make the build pass. The only sanctioned alternative is the on-the-record

worktree-reap precedent recorded in that test's own comment. Take that route only
after recording why the scan could not be widened.
