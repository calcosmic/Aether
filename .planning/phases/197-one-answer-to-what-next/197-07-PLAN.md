<objective>
Lock the two things this phase changed so neither can quietly come undone: every
lifecycle command must keep ending with the shared card, and the count of places
still hand-typing a command name may only fall.

Purpose: the previous six plans moved thirteen surfaces onto one answer. Nothing
yet stops the fourteenth from being written by hand tomorrow, and nothing yet
records how far the hand-typing has actually been reduced. This plan measures the
real number, freezes it, and puts both guards where the repository's CI already
holds its other guards to account.
Output: criterion 2's named coverage test, criterion 3's measured ratchet, and
both of them registered and running.
</objective>

<interfaces>
Both guards are full-rigour work under the proportionality clause. They are what
decides whether the owner keeps being told the right thing, and being wrong in
either would be invisible until an owner typed a dead command. Prove each by
breaking it.

The coverage test's list of lifecycle commands is a decision, not a derivation:
the roadmap's criterion 2 names them. Quote that list in the test with the
criterion beside it, so a reader can see where the set came from. What must be
derived is the other direction — that no command outside the list is quietly
hand-writing advice — and that is the ratchet's job, not the coverage test's.

The ratchet keys its entries on file, enclosing function, and the literal text,
not on line numbers. A line-keyed baseline would go stale on the next unrelated
edit above it, and a ratchet that has to be regenerated for unrelated reasons
stops being read.

Two files, exactly as the tolerated-orphan list does it: a live file the scanner
regenerates through a flag, and a frozen baseline the flag must never touch. The
comparison is set membership so a one-out-one-in swap fails. Follow that file's
conventions rather than inventing new ones — the repository already has this
pattern working three times.

Registering a guard means the named CI step's filter must name every test in it,
or the coverage test in the wiring inventory fails. Raising the inventory's
anti-vacuity floor is part of registering, not an afterthought.

Editing the workflow file may be refused by this machine's permission layer. If
it is, land that one file through the worktree path rather than dropping the
registration. An unregistered guard is the exact outcome both of these guards
exist to prevent, and this repository's inventory comments record it happening
before.
</interfaces>
