<objective>
Finish criterion 2: the six remaining lifecycle surfaces end with the shared
card, and the last private decider goes.

Purpose: these six are where the owner arrives when something has gone sideways
or when they are stopping for the day, which is exactly when wrong advice costs
most. They are also where the drift is already visible: the pause card offers the
same command twice and calls one of them a different view. This lands after the
short pause command exists, so the card can recommend the name the owner should
actually be typing.
Output: six migrated closings, six matching envelopes, and the last hand-rolled
next-step function repointed.
</objective>

<interfaces>
Same contract as plan 197-04: replace only the closing what-next block, keep
every section above it, add the structured fields beside each result map's
existing `next` key, and keep every renderer signature unchanged.

An override is information, not a decision. Three of these surfaces currently
compute their own advice on top of the shared one: status when guided actions
exist or workers are in flight, the recovery view from its own findings, and the
update run from its own outcome. Each of those genuinely knows something the
saved state does not. Feed that knowledge into the resolver's input as a fact and
let one answer come out. An override applied after the answer is produced puts
the screen and the envelope out of step, which is the split criterion 2 forbids.

The in-flight-workers case must survive intact. Telling the owner to wait while
a command is still running is correct and specific, and losing it would be a real
regression dressed as consolidation.

The pause card recommends the short command name now that it exists. Do not
hand-write either name — take the command from the resolver, which resolves it
through the live command tree, so the name in the card cannot outlive the
command.

S-05 applies with particular force here. Sealing a project is the word this
repository invented for finishing it, and a card that says to seal without saying
what that does is a defect. Same for archiving.

Do NOT change what any of these six commands does. Pausing must still write the
handoff; recovering must still repair. This phase changes what they say at the
end.
</interfaces>
