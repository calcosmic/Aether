<objective>
Make the short command the real one, the older long name an alias declared in a
single place, and give updating a project the job of repairing a missing copy
out loud.

Purpose: the owner has been typing a long name for a command whose short name
would be obvious, and the repository's answer to "two names for one thing" has
so far been two definition files kept in step by hand. The project already does
this once — the resume command has both names — and it is maintained as a
duplicate rather than as a declaration. Criterion 5 asks for the declaration.
Output: one definition carrying an alias list, both names on all three
platforms, one command behind both, and an update run that says what it fixed.
</objective>

<interfaces>
The existing resume pair is the shape to follow on the runtime side and the shape
to improve on the definition side. Its Cobra command carries the short name as an
alias of the long one, and that half is right. Its two definition files are the
half this plan replaces: one file, an alias list, and the platform copies derived
from that list.

Direction matters. The short name becomes the command's own name and the long
name becomes the alias, because the short name is what the owner should be typing
and what the resolver will recommend. That means the runtime command's primary
name changes, which is what moves the goldens.

S-04 is absolute here. There are three hand-maintained copies of every wrapper —
the nested claude copy, the flat claude copy, and the opencode copy — with no
generator and a parity test that fails if they diverge. Every file this plan adds
goes into all three in this one change, byte-identical where the existing pairs
are byte-identical.

The definition checker currently treats a wrapper with no matching definition
file as an error. Teach it that an alias declared by a canonical definition
legitimises the alias wrapper, so deleting the second definition file does not
make the checker complain about the wrapper that file used to justify.

The name-mapping table used by the parity snapshot records only the cases where a
platform-facing name differs from the runtime's own. The long name becomes such a
case and must be added; the short name becomes a direct match and must not.

Adding or renaming a command breaks four checks at once. Phase 196 added one and
broke all four, and a targeted run missed them. This plan's verification names
them: the command catalogue golden, the platform parity golden, the regression
snapshot, and the severity audit, plus the visual-writer discipline test.

Do NOT touch `cmd/codex_visuals.go`. The pause card is plan 197-06's, in the next
wave, after this command exists to be recommended.

The message the stop hook prints names the long form today. Update it to the
short form here, since this plan owns that file in this wave.
</interfaces>
