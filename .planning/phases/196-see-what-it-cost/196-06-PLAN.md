<interfaces>
New cobra command `spend`, registered on the root command in its own file's
init, following the pattern used by the existing ledger and listing commands.

It reads through the ledger's own load and total entry points from plan 196-01.
It must not construct a row, recompute a total, or derive a figure of its own.

Reachability is enforced by the orphan ratchet in
`cmd/subcommand_reachability_ratchet_test.go`: a registered subcommand must be
named by a Go call site, a wrapper the runtime loads, or a shipped hook or
script. The allowlist may only shrink, so adding an entry for this command is
not an option — the wrapper mention is the wiring.

The six wrapper files are three byte-identical pairs plus their OpenCode mirrors
and must change identically in this one plan.
</interfaces>

test: snapshot the content hashes of every file under the store before running,
run the command twice, and assert the snapshot is unchanged both times and the
two outputs are byte-identical. Reuse the existing snapshot helpers rather than
writing a second mechanism — this repository has shipped a mutating inspection
path twice, and the second time the flag's own documentation said it would not.

Implement the command as a pure read: load the phase's rows through the ledger's
load entry point, take totals from the ledger's totals entry point, and render.
Do not construct a row, do not recompute a total, do not touch the store.

tool reported nothing — rather than leaving a bare label.

values and asserting the rendered figures equal those literals, and by seeding an
empty ledger and asserting the command shows no figure at all.
