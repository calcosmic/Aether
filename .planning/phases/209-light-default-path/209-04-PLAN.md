<objective>
Make the default path actually short: one sentence in, and the program reaches a running planning pass and then built work without the owner typing anything in between. Clarifying intent, hand-drafting a specification, approving one by hand and deeper planning rounds all remain available — they stop being compulsory.

Purpose: UED-17 and the phase goal's own words — "ordinary work takes goal, one planning pass, build, check". Today the planning route stops dead without an approved specification, which is exactly the kind of strict rule this milestone exists to remove: the program should derive what it needs from what the owner already said, and carry on.
Output: `ensureGoPlanningSpecification`, the big route wired to it, the wrapper routing that runs one planning pass without a depth question, and a real-flow test from goal to built work.
</objective>

<planner_assumptions>
**UED-17 flagged assumption (the probe left this row `unclassified`):** nothing in the source artifacts settles what "one planning pass by default" means mechanically. This plan **assumes** it means two things and no more — (a) the owner is never asked to approve a specification or clarify intent before planning can start, and (b) the planning pass is asked for at the shallowest named depth without putting a depth question to the owner. It does **not** reduce the planner's own internal iteration, which is the program's business rather than an owner step.

**A second, load-bearing assumption, flagged deliberately:** this plan assumes the specification machinery's approval token is a binding checksum over an exact revision — derivable by the program from that revision — rather than a proof that a person was present. That is how `specificationApprovalToken` is computed today. If the executor finds any existing test asserting that approval requires something only a person can supply, this plan's approach is wrong; the executor must stop, record it in `.planning/WINDOWS.md`, and report it rather than weakening that test.
</planner_assumptions>
