# Phase 191.1 Plan 02: Continue Checker Field Fix + Pause-Race Preservation Summary

**Fixed a one-line verdict-reporting bug that made a downstream colony's embedded continue checker report its own shell command as the finding, and added a shared preserve/replay mechanism so a completed, passing continue verification that loses a race to a colony pause survives for cheap re-application instead of being thrown away.**

## Accomplishments

- `evaluateCriterionCheck`'s default-case PASS branch now reports `step.Summary` (the actual verified outcome, e.g. "tests passed") instead of `step.Command` (the raw configured shell command) -- the exact bug a downstream colony's field report traced to `cmd/criterion_evidence.go:618`, where 2 of 5 continue runs came back with the check's own command/description text as the "finding."
- A shared preserve/replay mechanism (`cmd/advance_phase.go`) durably preserves an already-computed, already-passing continue verification when it loses the race to a colony pause, and replays it -- skipping fresh verification entirely -- the next time continue runs against the same still-current phase and build.
- A preserved record whose identity (phase + build start time) no longer matches current state is discarded, never blindly replayed.
- Both the native (`runCodexContinue`) and wrapper-external (`runCodexContinueFinalize`/`advanceExternalContinue`) continue paths share the exact same preserve and replay functions -- no per-caller duplication.

## Decisions Made

- **Replay scope is deliberately narrow.** `replayPendingContinueAdvance` calls `advancePhase` (the actual state commit) using the preserved identity, and constructs a result map from the preserved verification/assessment/gates/review payload -- but does NOT re-run the surrounding pipeline's housekeeping, learning capture, phase-commit git commit, or worker-flow bookkeeping. Those are non-blocking, comparatively cheap side effects; the mechanism's entire purpose is to avoid re-running the expensive ~10-minute verification, which it does. This is within the plan's explicit executor discretion ("the caller decides the payload shape").
- **Reused `runtimeStartedAtMatches`** (already defined in `cmd/codex_build.go` for `advancePhase`'s own identity check) for the pending-record identity comparison, instead of writing a second nil-safe time-comparison function that could silently diverge from `advancePhase`'s own notion of "same build."
- **Pause-vs-other-reason distinguished by reloading state and reading `Paused` directly** (never string-matching the supersession error text), exactly as instructed in the plan.
