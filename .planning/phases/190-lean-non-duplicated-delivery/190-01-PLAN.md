<objective>
Make `brief_path` real for the ONE dispatch path the wrapper actually calls (`aether build <phase>
--plan-only`), so the manifest carries a path to a file on disk instead of shipping the full composed
brief inline -- and never both at once. Give `--print-brief` a mechanism that FAILS when a context
section (or the handoff schema) is delivered twice, instead of silently mis-attributing or ignoring
the repeat. Bring the six prose surfaces that describe this delivery mechanism (the build.md wrapper
triplet, the YAML source, the Codex command guide, the Codex skill) up to date with the new reality.

Today `runCodexBuildPlanOnlyWithOptions` (`cmd/codex_build.go:207`) -- the function behind the ONLY
command `.claude/commands/ant/build.md` instructs the wrapper to run -- calls
`attachBuildDispatchContext` (sets `.Brief` only) and never `writeCodexBuildArtifacts` (the only
function that sets `.BriefPath`). A passing test,
`TestBuildPlanOnlyPrintsDispatchManifestWithoutMutatingState`
(`cmd/codex_build_test.go:568-569`), currently asserts the opposite of what this plan delivers:
"plan-only manifest should not write worker briefs." Separately, `cmd/build_print_brief.go`'s
`briefOwnedSections`/`splitBriefSections` machinery attributes headings but never counts occurrences,
so a duplicated section would render as two silent rows, never a failure.

Purpose: ROADMAP criteria 1 ("plan-only manifests carry `brief_path` to files on disk and the wrapper
passes paths (build.md prose updated to match)"), 2 (build's half: "`--print-brief` asserts zero
duplicated sections"), and 4 ("orchestrator-relay byte count measurably drops" -- mechanically the
same fix as criterion 1, proven by the same invariant test).

Output: `writeBuildWorkerBriefFiles` (the shared, flag-distinguished brief-writing helper),
`duplicatedBriefSections` (the new duplication detector), inverted/new tests proving both by
invariant, and six prose surfaces brought into agreement with the new delivery contract.
</objective>
