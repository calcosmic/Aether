<objective>
Answer, by running it, the one question the rest of SPAWN-04 rests on: does Claude Code's
`PreToolUse` hook fire when a *subagent* calls the Task tool, and what identifying fields does
the payload carry?

Purpose: RESEARCH.md rates this MEDIUM confidence and names a direct contradiction — current
official Anthropic documentation says hooks fire in subagent contexts and carry
`agent_id`/`agent_type`; closed GitHub issue anthropics/claude-code#34692 reports the opposite.
Both cannot be true for the runtime this repo ships against. Building the deny path on the wrong
answer produces a guard that either never fires (useless) or denies every legitimate depth-1 to
depth-2 helper spawn that D-01 explicitly permits (over-denial). CLAUDE.md's Definition of Done
forbids settling this by reading.

Output: a dated verdict file with the raw captured payloads, plus the two prerequisites that
capture needs — the hook matcher registration and an opt-in payload recorder.

**This plan builds no guard.** It registers a matcher that only observes. The deny path is
plan 07, which depends on this plan's verdict.
</objective>

(a) Extend `claudeHookInput` with three additional string fields, all plain strings so an absent

sites in this file (`hookPreToolUseCmd`, `hookStopCmd`, `hookPreCompactCmd`) to accept and, where

`func captureRawHookPayload(raw []byte)`: it reads the environment variable
`AETHER_HOOK_CAPTURE_FILE`; if that value is empty it returns immediately; otherwise it opens
the named path with `os.OpenFile` using flags `os.O_APPEND|os.O_CREATE|os.O_WRONLY` and mode

reading input, before any tool-name branching. Do not call it from `hookStopCmd` or
`hookPreCompactCmd`.

existing `Write|Edit` entry, with `"matcher": "Agent|Task"` and the identical hooks body

string is `Agent|Task` because that is the wording ROADMAP criterion 4 uses; Task 3's capture
confirms which of the two tool names Claude Code actually emits. `hookPreToolUseCmd` returns
`nil` (allow) for any tool name it does not recognise, so this entry observes and allows —

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Claude Code platform → `aether hook-pre-tool-use` stdin | Untrusted JSON of unverified shape crosses here; field presence and naming are the platform's choice, not Aether's |
| `AETHER_HOOK_CAPTURE_FILE` environment value → local filesystem write | An operator-supplied path becomes a file the hook appends to on every tool call |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-173-01 | Information Disclosure | `captureRawHookPayload` writing full tool payloads to disk | mitigate | Capture is off unless `AETHER_HOOK_CAPTURE_FILE` is explicitly set; file is created mode `0o600`; the capture path is required to sit outside the repository working tree and Task 3's verify command asserts no capture artifact appears in `git status` |
| T-173-02 | Denial of Service | Hook execution blocked by a failing capture write (full disk, unwritable path) | mitigate | Every error path in `captureRawHookPayload` returns silently; the unit test asserts the hook produces no block decision in both env-set and env-unset branches |
| T-173-03 | Tampering | `AETHER_HOOK_CAPTURE_FILE` pointed at a sensitive file to append attacker-chosen content | accept | The environment variable is set by the operator in their own shell; an operator who can set it can already write the file directly. No privilege boundary is crossed |
| T-173-04 | Spoofing | Trusting `agent_id`/`agent_type` as an authenticated identity | mitigate | This plan only records the fields; the `## Named residue` section explicitly states they are not an identity lookup, so plan 07 cannot inherit an unstated assumption |
| T-173-05 | Elevation of Privilege | The new `Agent|Task` matcher silently allowing dispatches it was expected to guard | accept | Deliberate and bounded: this plan's matcher observes only. The deny path is plan 07, which `depends_on` this plan's verdict. Stated in the objective so no later reader mistakes registration for enforcement |
</threat_model>
