<objective>
Make the recorder the authority on depth. `spawn-log` stops trusting the `--depth` integer its
caller types and derives depth from the parent's own recorded entry. Then correct
`.aether/workers.md`, which currently instructs the wrong number in two places and publishes a
behaviour table permitting a third level of delegation that D-01 forbids.

Purpose: this is the chokepoint an LLM cannot route around. A worker can lie to a checker about
how deep it is; it cannot avoid being recorded. SPAWN-06's ruling (D-05: coordinator 0, workers
1, helpers 2) only becomes real when the recorder enforces it, and only stays real when the
document workers read agrees with it.

Output: derived depth at the recording call, a corrected instruction file, and named tests that
go red if either regresses.
</objective>

recorded at depth 1. Add `func spawnParentIsRoot(parent string) bool` performing that
case-insensitive membership test.

Add `func deriveSpawnDepth(st *agent.SpawnTree, parent string) (int, string)` returning the depth
to record and a deny reason. Its rules, in order:

1. If `spawnParentIsRoot(parent)` — return `1, ""`. The coordinator is never itself recorded in
   the tree, so its absence is expected and is the one legitimate not-found case.
2. Otherwise call `latestSpawnEntryByName(st, parent)`. If it returns a non-nil entry, return
   `entry.Depth + 1, ""`.
3. Otherwise return `0` and a deny reason of the form
   `unknown parent %q: not a recorded spawn and not a coordinator sentinel (%s)` where the second
   verb lists `spawnRootParentNames` joined by `, `. This is the D-19 fail-closed branch —
   an unresolvable parent denies, it does not default to zero.

In `spawnLogCmd.RunE`, keep reading the `--depth` flag into a variable named `claimedDepth` (the
flag stays registered and stays accepted, for backward compatibility with every existing caller),
then call `deriveSpawnDepth`. When the deny reason is non-empty, call
`outputError(1, reason, nil)` and return `nil` **before** calling `RecordSpawn` — nothing is
written to `spawn-tree.txt` and nothing is published to the event bus. Otherwise pass the derived
value, not `claimedDepth`, into `st.RecordSpawn`.

Extend the success payload: keep the existing `depth` key set to the derived value (so every
existing reader keeps working and starts seeing the truth), and add two new keys —
`claimed_depth` set to the flag value, and `depth_source` set to the string `derived`. Update the

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Worker-supplied `--parent`, `--name`, `--depth` flags → `spawn-log` → `spawn-tree.txt` | An LLM chooses these values; the recorded tree is the security-relevant artifact every later guard reads |
| `.aether/workers.md` → worker behaviour | The instruction file is the only thing telling a worker what depth it is at; a wrong instruction is a runtime defect, not a documentation defect |
