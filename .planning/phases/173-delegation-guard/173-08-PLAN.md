<objective>
Let the operator watch the delegation tree while it grows, so a runaway subtree is visible before
the run ends rather than discovered on the bill.

Purpose: `spawn-tree-active` already gathers exactly the data needed — name, parent, caste, task,
depth, status, spawn time — and already reads through the shared, lock-safe path, so it is already
safe to run while workers are writing. What it does not do is render it. It emits a flat JSON
array. D-14 makes readability a hard requirement, not a nicety: the operator is non-technical, and
a view they cannot read is a view that does not exist.

Output: a depth-indented, parent-attributed, English rendering in visual output mode, with the
JSON mode untouched.

Scope boundary: no live-refreshing dashboard, no second terminal, no polling, no background
process. D-13 deliberately ships an on-demand view plus the single threshold line plan 05 already
added. A real-time view is a plausible later phase and is explicitly deferred.
</objective>

`spawnTreeActiveCmd` today (`cmd/spawn.go:248-294`): builds
`agent.NewSpawnTree(store, "spawn-tree.txt")`, calls `st.Active()`, maps each entry into an
anonymous `entryJSON` struct with fields `name`, `parent`, `caste`, `task`, `depth`, `status`,

writing. Do not add a second locking scheme.

- `func casteLabel(caste string) string`
- `func casteIdentity(caste string) string` — composes `casteEmoji(caste) + " " + colorizeCaste(caste, casteLabel(caste))`, e.g. a hammer emoji followed by a coloured "Builder".
Do not add a second caste-name or emoji map in `cmd/spawn.go`.

Output-mode convention: `AETHER_OUTPUT_MODE=json` selects the JSON envelope; visual mode is the
runtime-rendered view. Inspect how sibling commands in `cmd/` branch on output mode and follow
that existing convention rather than inventing one.

From plan 05, in `cmd/spawn_budget.go`: `spawnTreeBudgetState() (spawnTreeBudget, error)` with
fields `Max`, `Consumed`, `Remaining`, `Reason`.

CLAUDE.md corollary that governs this command: *an inspection or `--dry-run` command must not

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `spawn-tree.txt` being written by live workers → a concurrent read by the view command | The whole point of this command is to run while other processes are writing the file it reads |
| Worker-supplied task text and agent names → terminal output | Free text chosen by an LLM is rendered directly to the operator's terminal |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-173-40 | Tampering | An inspection command mutating the state it inspects | mitigate | The path adds no write, create, publish or update; `TestSpawnTreeActiveMutatesNothing` hashes every file before and after two runs. This repo has already shipped this exact defect in `consolidation-phase-end --dry-run` |
| T-173-41 | Denial of Service | The view interfering with a running build by taking an exclusive lock or blocking writers | mitigate | Reading goes through `Active()` and `Store.ReadFile`, which take a shared read lock; no new locking scheme is introduced |
| T-173-42 | Information Disclosure | Worker task text rendered verbatim to the terminal, potentially carrying secrets a worker was handed | accept | Task text is already stored in plain text in `spawn-tree.txt` and already rendered by existing ceremony output; this command adds no new exposure surface |
| T-173-43 | Tampering | Terminal escape sequences embedded in a worker-chosen agent name or task, corrupting the operator's display | mitigate | `sanitizeSpawnField` already strips carriage returns, newlines and pipes on write; colouring goes through `colorizeCaste`, which emits only the repo's own known ANSI codes for a fixed caste set |
| T-173-44 | Repudiation | A runaway subtree invisible because its parent already completed and dropped out of the active set | mitigate | Entries whose parent is no longer active are still rendered attributed to that parent name rather than reparented to the root or dropped |
</threat_model>
