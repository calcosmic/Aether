<objective>
Add the one guard that can stop a delegation *before* the platform acts on it, and make it deny
when it cannot tell who is asking.

Purpose: every other guard in this phase runs inside the child's own turn — `spawn-can-spawn` and
`spawn-log` are commands the child executes after it already exists. The `PreToolUse` hook is the
only chokepoint that sits in front of the Task tool call itself. D-20 requires it to deny when the
requester's depth cannot be resolved, and PATTERNS.md flags the trap: the obvious analog,
`protectedHookWriteReason`, has an unresolvable-input branch that fails *open*. That branch must
be inverted, not copied.

Output: a `Task`/`Agent` branch on the existing hook, whose deny reason is resolved by whatever
identifying fields plan 01 actually observed, with the residue written into the code's own
comments so the next reader cannot mistake a heuristic for an identity lookup.

**Read `173-HOOK-FINDINGS.md` first.** Its `VERDICT:` line governs this plan's scope. If the
verdict is `INCONCLUSIVE`, stop and surface it — do not implement on assumption.
</objective>

   number here would be a second policy.
