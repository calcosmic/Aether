# Phase 198.1 Plan 06: Feed the Memory (memory-details + status heading) Summary

**`/ant-memory-details` now renders real wisdom sentences, pending/deferred lessons with observation counts, and recent failures instead of a bare-count JSON alias; the status screen's instinct list is honestly labelled "Strongest Instincts" and ordered by `memory.InstinctUsefulnessScore`, not recency.**

## Performance

- **Duration:** ~60 min (estimated; start time was not captured at session start)
- **Completed:** 2026-08-30
- **Tasks:** 3
- **Files modified:** 15 (2 created, 13 modified across commits)

## Accomplishments

- `buildMemoryDetails` assembles the drill-down's real content: QUEEN.md wisdom grouped by section (`readQueenEntriesByCategory`, a deliberate second reader alongside `readQUEENMd`'s flattened map), promotion-eligible-but-not-yet-promoted observations, deferred observations, and the five most recent unacknowledged midden failures — reusing `loadMemoryHealthSummary` for the instinct counts rather than recomputing them.
- `queenMarkdownUpdatedAt` returns a real timestamp: the METADATA block's `last_evolved` value when present, the file's own modification time otherwise, empty string only if the file doesn't exist.
- `aether memory-details` is now its own registered command (`memoryDetailsCmd`), no longer an alias of `memory-metrics`. It renders the drill-down visually by default and exposes `--json` for the machine envelope; `AETHER_OUTPUT_MODE=json` still forces the envelope too. `memory-metrics` keeps its original bare-count behaviour, verified by a byte-for-byte directory snapshot proving the command writes nothing.
- `cmd/status.go`'s ranked instinct list is renamed end to end — `loadRecentRuntimeInstincts` → `loadStrongestRuntimeInstincts`, `renderRecentInstincts` → `renderStrongestInstincts`, heading "Recent Instincts" → "Strongest Instincts" — and a test proves an older, higher-confidence, applied instinct outranks a newer, low-confidence, never-applied one, deriving the expected order from `memory.InstinctUsefulnessScore` itself rather than a hand-typed literal.
- Three wrapper surfaces (`.aether/commands/memory-details.yaml`, both markdown wrappers, `.codex/CODEX.md`) now describe what the drill-down actually shows in plain English, with the two markdown wrappers verified byte-identical.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] First-run welcome banner and unlocked-file writes needed accounting for in the write-nothing test**
- **Found during:** Task 2 (`TestMemoryDetailsWritesNothing`, `TestMemoryDetailsJSONFlagStillReturnsTheEnvelope`)
- **Issue:** A fresh test store with no `COLONY_STATE.json` and no `.welcomed` marker triggers `checkAndEmitFirstRun`'s welcome banner ahead of command output (breaking the JSON-envelope test), and `pkg/storage.FileLocker` creates a persistent `.lock` file the first time any path is locked — including a plain read of a JSON file the fixture never wrote to (breaking the naive whole-directory write-nothing comparison).
- **Fix:** The fixture now pre-seeds a `.welcomed` marker so no command in this test file triggers the first-run banner; `snapshotDirFiles` skips `.aether/locks/` with a comment explaining why a first-touch lock file is storage-layer concurrency bookkeeping, not colony memory content, and counting it as a "write" would fail this test for any command reading a JSON file it has never read before.
- **Files modified:** cmd/memory_details_render_test.go
- **Verification:** All four Task 2 tests pass; the full `cmd` package suite is green.
- **Committed in:** e24e7728

**2. [Rule 3 - Blocking] New command surface drifted golden fixtures and a flat wrapper mirror**
