## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `renderSpawnTeamExplanation`'s "Queen"/"castes" sentences had no plain-English cue**
- **Found during:** Task 1
- **Issue:** "The Queen chose this team..." and "Safety castes a risky phase needs..." render unconditionally whenever the build screen has any dispatches (required by the plan's own fixture spec of "at least two dispatches"), and neither sentence carried the cue word CLAUDE.md's translation table requires for "queen"/"caste".
- **Fix:** Added "(the coordinator that decides which helpers a phase needs)" and reworded to "Safety-critical helpers (the castes a risky phase needs)".
- **Files modified:** `cmd/codex_visuals.go`
- **Verification:** `TestVoicedScreensSpeakPlainEnglish/build` passes; no dependent test asserted the old literal verbatim.
- **Committed in:** `1a26c188` (Task 1 commit)

**2. [Rule 1 - Bug] The continue screen's "Workers"/"Continue Worker Flow" headers and `renderProjectComplete`'s closing line had no plain-English cue**
- **Found during:** Task 2
- **Issue:** These four lines render unconditionally on any continue screen with closed workers, and none carried the required cue for "worker"/"colony".
- **Fix:** Reworded each to add a same-sentence explanation ("(the helpers this phase used)", "(the helpers who worked this phase)", "The project (this colony) rests").
- **Files modified:** `cmd/codex_visuals.go`
- **Verification:** `TestVoicedScreensSpeakPlainEnglish/continue-midphase` and `/continue-final` pass; `ceremony_restoration_test.go` and `run_autopilot_test.go` widened to the new "colony rests" wording (no dependent asserted the "Workers"/"Continue Worker Flow" literals).
- **Committed in:** `a8ab1c68` (Task 2 commit)

**3. [Rule 1 - Bug] The continue screen's own "Colony Complete"/"Colony State" stage markers had no plain-English cue**
- **Found during:** Task 2
- **Issue:** Unlike the build screen (whose final-phase variant was deliberately kept out of the plain-English-scanned corpus, Task 1), the plan requires `continue-final` to join the corpus — exposing that the shared marker title "Colony Complete" (and the footer's "Colony State") carry no cue.
- **Fix:** Renamed both markers, scoped to the two `renderStageMarker` call sites inside `renderContinueVisual` only, to "Project Complete (Colony)" / "Project State (Colony)". The build screen's identical marker text (a separate call site) is untouched.
- **Files modified:** `cmd/codex_visuals.go`, `cmd/codex_visuals_test.go` (one dependent literal widened)
- **Verification:** `TestVoicedScreensSpeakPlainEnglish/continue-final` passes; `TestContinueVisualOutputShowsColonyCompleteStageMarker` and the four build-screen tests asserting the unchanged "Colony Complete" literal all still pass.
- **Committed in:** `a8ab1c68` (Task 2 commit)

**4. [Rule 1 - Bug] The seal screen's sealed-at/closing sentences and the QUEEN.md line had no usable plain-English cue**
- **Found during:** Task 3
- **Issue:** "Colony sealed at Crowned Anthill.", "The colony stands crowned and sealed." and "Its wisdom lives on in QUEEN.md." carried "colony"/"seal"/"queen" without their required cues; a first QUEEN.md rewording placed the cue AFTER the literal period inside "QUEEN.md", which the plain-English scanner treats as a sentence boundary, so the cue landed in a different "sentence" than the word it was meant to explain.
- **Fix:** Reworded the sealed-at and closing sentences to name "project"/"finished" beside "colony"/"sealed", and reordered the QUEEN.md line so "coordinator"/"decides" precede the filename's own period.
- **Files modified:** `cmd/codex_visuals.go`, `cmd/ceremony_restoration_test.go`, `cmd/lifecycle_card_endgame_test.go` (widened literals)
- **Verification:** `TestVoicedScreensSpeakPlainEnglish/seal` passes; `TestSealRendersCrownedAnthill`, `TestSealEndsWithTheCard`, `TestSealCardExplainsFinishingAndArchiving` all still pass.
- **Committed in:** `4bffa384` (Task 3 commit)

**5. [Rule 1 - Bug] `next_action.go`'s "last thing you ran" sentence embeds a repo-invented command name with no cue**
- **Found during:** Task 3
- **Issue:** `changedFromInput` unconditionally renders "The last thing you ran was {command}." When `command` is "seal" — simultaneously a command name and a CLAUDE.md vocabulary word — the bare command name can never carry its own explanatory cue, and this had never been exercised with `lastCommand="seal"` in the plain-English-scanned corpus before.
- **Fix:** Added `lastCommandPlainEnglish`, a narrow switch that adds "(marking the project finished)" only for "seal", leaving every other command name (including "build" and "continue", already tested) unchanged.
- **Files modified:** `cmd/next_action.go`
- **Verification:** `TestVoicedScreensSpeakPlainEnglish/seal` passes; `TestNextActionCardSpeaksPlainEnglish` and `TestNextActionCardTranslatesOnlyOnTheWayOut` (which exercise other command names) unaffected.
- **Committed in:** `4bffa384` (Task 3 commit)
