# Phase 202.1 Plan 02: Status Card Voice Summary

**The full and compact `aether status` cards now speak in the restored Classic voice — every content line glyph-led, an active helper's line carries the same `casteIdentity()` rendering the live cockpit already gives it, Recent History reads as sentences instead of raw bookkeeping records, and the compact card's width-fitting is now provably safe against splitting a multi-rune symbol.**

## Performance

- **Duration:** ~33 min
- **Completed:** 2026-09-12
- **Tasks:** 3
- **Files modified:** 3 (1 created, 2 modified)

## Accomplishments

- **Task 1:** Rewrote `renderLifecycleStatusFull` so every content line — including every section title — routes through `voiceLine` with the semantic glyph the plan's mapping specifies (`colony`, `goal`, `phase`, `task`, `focus`, `artifact`, `learning`, `flag`, `elapsed`, `cost`, `history`, `warning`, `blocked`, `question`, `done`, `next`, `alternative`). Rewrote `lifecycleStatusActorLine` to open with `casteIdentity(caste)` — the exact rendering `renderSpawnEntry` (`cmd/status.go`) and the live cockpit (`cmd/watch_dashboard.go`) already use — falling back to `voiceLine("colony", …)` when no caste is recorded, replacing the old bare `Active: Name (caste)` parenthetical form entirely. Created `cmd/classic_voice_status_test.go`, registering `status-full` into the shared voice corpus with a fully populated `LifecycleProjection` fixture (an active builder, a terminal watcher, a lineage row, an active FOCUS signal, a gate, evidence, a warning, a blocker, an owner decision, and a non-empty history) and added `TestStatusScreenMeetsTheReferenceDensity`, `TestStatusHelperLineCarriesTheSharedIdentity`, and `TestStatusUnchangedFacts`.
- **Task 2:** Added `lifecycleStatusHistoryLines`, which renders each stored event through the existing `nextActionEventSentence` reader (`cmd/next_action.go`) rather than the old `"• " + event` bookkeeping literal, skipping an event whose derived sentence is empty and falling back to the existing no-history line only when every event skips. Added `TestStatusHistoryShowsASentenceNotTheStoredRecord`, proving a well-formed four-field record renders as its message alone, an empty-message record contributes no line, and a bare delimiter-free string renders verbatim, with no pipe or timestamp surviving in the rendered history block.
- **Task 3:** Applied the same `voiceLine`/`casteIdentity` treatment to `renderLifecycleStatusCompact`. Discovered and fixed a real (not merely hypothetical) selector-splitting defect in `lifecycleStatusFitLine`: its raw-rune mid-line truncation could separate a glyph's base rune from its trailing variation selector (U+FE0F) — proven by temporarily reverting the fix and watching the new test fail, then restoring it. The fix adds `lifecycleStatusGlyphTokens`, which pairs a base rune with an immediately following selector into one atomic token before any width-fitting math runs. Registered `status-compact` into the corpus and added `TestCompactStatusAgreesWithTheFullCard`, `TestCompactStatusNeverSplitsASymbol`, and `TestLifecycleStatusFitLineNeverSplitsAVariationSelector` (the last exercising widths 1–30, well below the public 24-column floor, against both a stopwatch-glyph line and an eye-glyph caste-identity line).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The plain-English scan flagged the bare "Colony" heading, the "Memory: N instincts" line, and a lineage row naming "Queen" — none named in the plan's own action text**
- **Found during:** Task 1, running `TestVoicedScreensSpeakPlainEnglish` for the first time against the newly registered `status-full` screen
- **Issue:** The plan explicitly named only the "Pheromones" section title and the "No active pheromones recorded" line as needing rewording. Once the screen was actually registered and scanned, three further untranslated repo-invented words surfaced: the bare "Colony" section title (cue "project" absent), "Memory: N instincts" (cue "learned"/"lesson" absent), and "Queen" as a lineage actor name (cue "coordinator"/"decides" absent) — the last of which is not fixture-specific; `Queen` is the real, literal root-parent name in every production spawn tree (`pkg/agent/spawn.go`'s `spawnRootParentNames`).
- **Fix:** Reworded the Colony title to `"This Project (Colony)"`, the Memory line to `"Memory: %d instincts (lessons learned) | %d observations"`, and added `lifecycleStatusLineageActorLabel`, which translates a lineage actor named `"Queen"` to `"Coordinator (Queen)"` (case-insensitive), leaving every other actor name untouched.
- **Files modified:** `cmd/lifecycle_status_render.go`, `cmd/lifecycle_status_199_test.go` (widened the "Queen → Mason-1" want-string to match)
- **Verification:** `TestVoicedScreensSpeakPlainEnglish` passes for both `status-full` and `status-compact`; `TestLifecycleStatus199FullOrder` re-verified with the updated want-string.
- **Committed in:** `ba0f0a44` (single plan commit)

**2. [Rule 1 - Bug] `lifecycleStatusFitLine`'s raw-rune truncation could split a variation-selector glyph**
- **Found during:** Task 3, investigating the plan's explicit instruction to "check `lifecycleStatusJoin`'s width handling against multi-rune symbols"
- **Issue:** The existing mid-line ellipsis truncation sliced on raw `[]rune`, so at sufficiently narrow widths (never reachable via the public `renderLifecycleStatus` entry point's 24-column floor, but directly reachable by calling `lifecycleStatusFitLine` at width 1–4) a glyph's base rune (e.g. the stopwatch, U+23F1) could be kept while its trailing variation selector (U+FE0F) was dropped, or vice versa.
- **Fix:** Added `lifecycleStatusGlyphTokens`, which pairs a base rune with an immediately following selector as one atomic token, and rewrote `lifecycleStatusFitLine` to slice on tokens instead of raw runes.
- **Files modified:** `cmd/lifecycle_status_render.go`
- **Verification:** `TestLifecycleStatusFitLineNeverSplitsAVariationSelector` reverts-and-restores tested: fails against the old raw-rune implementation (confirmed manually before restoring the fix), passes against the new tokenized one, across widths 1–30 on two selector-bearing glyph lines.
- **Committed in:** `ba0f0a44` (single plan commit)
