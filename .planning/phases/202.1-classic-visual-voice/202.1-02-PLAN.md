<objective>
Bring the screen the owner lands on most — `aether status`, full and compact — up to the reference voice, and stop it printing the raw stored event record as history.

Purpose: RESEARCH.md's audit puts the sharpest example of the whole phase here. `lifecycleStatusActorLine` formats an active helper as `Active: Mason-42 (builder) — running: ...` while `renderSpawnEntry`, in the same package, formats the identical fact as `✓ 🔨🐜 Builder Mason-42 — running: ... [active]` using a `casteIdentity()` call the first function simply never makes. Nothing needs inventing; the call is one line away. The second problem is larger than the audit recorded: the Recent History section renders `projection.History.Value` — which is `state.Events` verbatim — as `"• " + event`, so a saved record's timestamp, its internal event code and its bookkeeping field all land on an owner-facing line exactly as CEC-09's fourth clause forbids.
Output: a full and compact status card whose lines are glyph-led, whose helper lines carry the cockpit's own identity rendering, and whose history reads as sentences.
</objective>
