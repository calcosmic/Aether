    1. `HiveInjectorOptions` interface: goBinaryPath (string), cwd (string), domains (string[]), minConfidence (number, default 0.5), maxEntries (number, default 10), budgetChars (number, default 2500).
    
    2. `readHiveWisdom(opts: HiveInjectorOptions): Promise<string>` — async function that:
       - Calls `aether hive-read` via `callGoJSON<HiveReadResult>` with NO `--domain` flag (fetch all entries, per RESEARCH.md Q1 resolution: Option B).
       - Uses `--min-confidence` flag with opts.minConfidence.
       - If callGoJSON throws (corrupted wisdom, missing binary, etc.), catch the error, write a warning to stderr using `process.stderr.write(`Warning: hive-read failed: ${msg}\n`)`, and return empty string. Do NOT re-throw.

       - Apply relevance scoring: for each entry, if entry.domain is in opts.domains, use full confidence. If not, apply confidence * 0.5 discount (HIVE-07). Sort by discounted confidence descending.
       - Take top opts.maxEntries.
       - Call `formatHiveWisdomSection` with the filtered entries.
       - Enforce budget: if the formatted section exceeds opts.budgetChars, remove oldest entries (by created_at) until it fits. If a single entry exceeds budget, truncate its text to fit (preserve the header).
    
    3. `formatHiveWisdomSection(entries: HiveWisdomEntry[]): string` — pure function that:
       - Returns empty string if entries array is empty.
       - Produces markdown with header exactly `## HIVE WISDOM (Cross-Colony Patterns)\n\n`.
       - Each entry rendered as `({domain}, {confidence.toFixed(2)}) {text}` on its own line.
       - Entries separated by single newlines.
    
    4. `resolveDomainTags(opts: GoBridgeOptions): Promise<string[]>` — async function that:
       - Calls `aether registry-list` via `callGoJSON<{ colonies: RegistryEntry[] }>`.
       - Finds the colony matching opts.cwd by comparing repo_path (normalize paths with `path.resolve`).
       - Returns the matching colony's domains array, or empty array if no match.
       - If callGoJSON throws, catch and return empty array (no warning needed — this is a best-effort resolution).
    
    Import from `./go-bridge.js` (callGoJSON, GoBridgeOptions) and `./types.js` (HiveWisdomEntry, HiveReadResult, RegistryEntry).
    
    Document the D-01 ordering note in a code comment: "Hive wisdom is injected after the skill section. The current prompt order (skills before pheromones) is preserved; hive is added after skills."

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-137-01 | Tampering | wisdom.json | accept | Go owns file integrity; TS reads via Go CLI which validates JSON |
| T-137-02 | Denial of Service | hive-read subprocess | mitigate | Try/catch around callGoJSON; failure returns empty string, does not block dispatch (HIVE-04) |
| T-137-03 | Information Disclosure | Worker prompts containing wisdom | mitigate | Wisdom is read-only cross-colony patterns; no secrets stored in hive. Redaction already handled by sanitizeBridgeMessage in go-bridge.ts |
| T-137-04 | Spoofing | Malicious wisdom entry in prompt | mitigate | Wisdom text is displayed as-is with source domain; workers are instructed to treat it as advisory, not authoritative. No executable content |
</threat_model>
