<objective>
Close verification gap CR-02: a recovery decision fired during an active build or check currently hijacks `aether watch` away from the real running episode and its workers, onto an empty synthetic `recovery-phase-N` episode that is itself never open — so the cockpit falls into replay mode and shows almost nothing at exactly the moment the owner most wants to see what is happening.

Two independent defects produce that outcome, and both are fixed here:

1. `cmd/recovery_orchestrator.go:215` builds a synthetic episode ID from `ctx.Phase` instead of reusing the real open episode the same package already exposes through `currentLiveBuildEpisode()` / `currentLiveContinueEpisode()` (cmd/live_events.go).
2. `latestLiveEpisodeID` (cmd/watch_live.go:168-185) selects whichever episode owns the chronologically newest single event, with no concept of "still open" — unlike `mostRecentlyStartedLiveEpisode` (cmd/watch_replay.go:53), which already solves exactly this for the replay path.

Purpose: restore D-01's promise that the live dashboard shows active workers *and* recovery state together, and D-02's promise that the current wave and its workers are what the default view is in depth. Recovery is a detail of the episode it happened inside, never a screen of its own.

Output: an episode selector that follows the most recently started still-open episode, a recovery emitter that speaks on the owning episode, one shared open/close rule, and a regression test that fires a real recovery decision mid-build and fails if the cockpit looks away.
</objective>

<assumption_delta_decision>
Before this plan, "which episode is live" had exactly one candidate — the episode owning the newest event — so the question was singular by construction. Routing recovery onto the owning episode makes the population plural in principle (a build episode, a check episode, and any episode a recovery touched can all be candidates at once).

Decision recorded: the primary noun for live selection is promoted to **"the most recently started still-open episode"**. Recovery is demoted from an episode-producing lane to a **detail layered onto the episode that owns it** — it contributes `RecoveryState` to an existing episode's snapshot and mints an episode ID of its own only when no live episode is open at all. The synthetic `recovery-phase-N` identifier survives solely as that no-open-episode fallback, so a standalone recovery decision is still recorded rather than dropped.
</assumption_delta_decision>
