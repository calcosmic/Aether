<objective>
Close verification gap CR-01: no Oracle run, however actively it is iterating, can ever be classified live by `aether watch`. `cmd/oracle_live.go` emits round, confidence, contradiction and gap events but never opens or closes an episode boundary, so `foldColonyLiveEvents`'s start/end balance (cmd/live_projection.go:352-367,436) never goes positive for Oracle, `snapshot.Open` is always false, and `resolveWatchMode` (cmd/watch_live.go:44) always returns replay mode. That directly contradicts `.aether/commands/oracle.yaml`'s shipped promise that a running Oracle round is visible in the live colony dashboard exactly like any other worker, and 202-11's own SUMMARY.md.

A second, less visible half of the same gap: even with a boundary emitted, `resolveWatchMode` consults the latest durable spawn-run record to decide whether an open episode was abandoned. Oracle never registers a spawn run — its owning process is its own controller PID — so in any real colony where an earlier build already finished, that terminal build run would demote a genuinely live Oracle round back to replay. Fixing only the boundary would produce a test that passes on an empty fixture while the real case still fails, which is exactly the false certificate CLAUDE.md's Definition of Done exists to prevent. Both halves are fixed here.

Purpose: deliver D-08's promise that Oracle's rounds, confidence movement and contradictions are visible in the live view while it runs autonomously, and make the shipped documentation's Oracle claim true rather than aspirational.

Output: an episode boundary around the round-based run (covering completion, external stop, and controller death), episode-kind-aware abandonment evidence, and tests that assert the resolved mode instead of discarding it.
</objective>
