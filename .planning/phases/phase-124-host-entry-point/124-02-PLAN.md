    In `cmd/publish_cmd.go`:
    1. Add a new flag `--skip-ts-build` (bool, default false) to `publishCmd` in `init()`.
    2. In `runPublish`, after validating the package directory and before building the Go binary:
       - Check if `.aether/ts-host/package.json` exists in the packageDir.

         a. Check if `npm` is in PATH using exec.LookPath("npm"). If not, return an error: "npm not found in PATH; install Node.js or use --skip-ts-build".

         c. Capture stdout/stderr. If the command fails (exit code != 0), return an error: "TS host build failed: <stderr>".
         d. Print a success message: "TS host built successfully" (via outputWorkflow or fmt.Fprintf to stderr).
       - If `--skip-ts-build` is true, print: "Skipping TS host build (--skip-ts-build)".
    3. After the binary build and hub sync, verify that `.aether/ts-host/dist/host.js` exists. If it does not exist, print a warning (not fatal): "Warning: TS host dist not found after publish. Run `npm run build` in .aether/ts-host/".
    4. Ensure the existing `setupInstallHub` call will naturally sync `ts-host/` because it syncs all of `.aether/` to the hub (confirm `hubExcludeDirs` does not exclude `ts-host`).
  </action>
  <verify>

  </verify>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Go CLI -> npm child process | Publish invokes npm, which runs arbitrary code from package.json scripts |
| Hub -> downstream repo | Synced files could be tampered if hub is compromised |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-124-05 | Tampering | npm run build | accept | npm is a trusted build tool in this context; the repo controls package.json |
| T-124-06 | Denial of Service | Stale dist warning | accept | Warning only, does not block publish; user can override with --skip-ts-build |
| T-124-07 | Information Disclosure | hub path in warnings | accept | Hub path is already known to the user running the command |
</threat_model>
