    Scoring constants, declared as named module-level constants exactly like
    `confidence-evaluator.ts` does, so the formula is inspectable and a test can
    assert an exact number:
      RESEARCH_BASE_SCORE = 20
      SECTION_BONUS_MAX = 30
      CITATION_BONUS_MAX = 25
      FILES_BONUS_MAX = 15
      SELF_ASSESSMENT_BONUS = 10
      GAP_PENALTY = 5
      GAP_PENALTY_CAP = 20

    Formula:
    - Sections: the six required headings listed in the interfaces block. A
      section counts as filled when its heading is present AND its body has at
      least 20 non-whitespace characters after stripping template placeholders
      (any `{...}` span). Add `SECTION_BONUS_MAX * (filled / 6)`.
    - Citations: collect the bullet lines under "## Key Patterns" and
      "## Gotchas". A bullet is cited when it contains `(Source:` followed by
      either a path-like token (contains `/` and a `.` extension) or a URL
      (starts with `http://` or `https://`). Add
      `CITATION_BONUS_MAX * (cited / total)`; add 0 when there are no bullets.
    - Files: collect bullet paths under "## Files to Study". A path is verified
      when it exists on disk relative to `repoRoot` (use `fs.existsSync` from
      `node:fs`). Add `FILES_BONUS_MAX * (verified / total)`; add 0 when the
      list is empty.
    - Self-check blend (D-11): add `SELF_ASSESSMENT_BONUS` when

      `Math.min(selfAssessedGaps * GAP_PENALTY, GAP_PENALTY_CAP)`. The
      researcher's own gap assessment adjusts the evidence score; it never
      replaces it.
    - Clamp to [0, 100] with `Math.round`, matching `confidence-evaluator.ts`.

    Reproducibility is a hard requirement (D-11 and the project's Definition of

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker-authored markdown -> scorer | `phase-N-research.md` is written by an LLM worker and parsed here |
| cited path -> filesystem check | Paths extracted from worker prose are passed to `fs.existsSync` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-164-07 | Tampering | worker inflating its own confidence | mitigate | The score is dominated by checkable evidence (sections 30, citations 25, files 15 = 70 of the range); the self-assessment contributes at most a 10-point bonus and only ever subtracts beyond that, so a worker cannot self-declare its way to target (D-11) |
| T-164-08 | Information Disclosure | `fs.existsSync` on a worker-supplied path | mitigate | Resolve every Files-to-Study path against `repoRoot` with `path.resolve` and skip any path that escapes `repoRoot` after resolution; the check returns only a boolean and never reads file contents |
| T-164-09 | Denial of Service | pathological research markdown (very large or deeply repeated) | mitigate | The scorer is single-pass over the markdown with no backtracking-prone regex; cap the Files-to-Study existence checks at the first 50 paths so a runaway bullet list cannot stall the loop |
</threat_model>
