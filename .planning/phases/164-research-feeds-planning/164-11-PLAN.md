<objective>
Close CR-03 from `164-VERIFICATION.md`: `plan-research-escalate` resolves phases
from `state.Plan.Phases`, which is empty during a fresh colony's mid-loop
planning — the exact and only situation in which research dispatches exist. The
command exits non-zero via `outputError`, `execFileSync` in `go-bridge.ts`
throws, and the unwrapped call in `runResearchConfidenceLoop` propagates that
exception all the way out, crashing the entire plan run. The one safety net for
a stalled research phase is a guaranteed whole-run crash, directly contradicting
D-08 ("research is enrichment, never a gate").

Purpose: this is the compounding third defect behind Success Criterion 4. Two
independent fixes are needed, because either alone leaves a hole — the Go
command must resolve the right phase set, and the host must survive any future
escalation failure regardless of cause.

Output: an escalate command seeded from the same planning iteration state the
plan-only path uses, a host that logs and continues when escalation fails, and
two tests that exercise the real failure conditions rather than pre-arranged
happy state.
</objective>
