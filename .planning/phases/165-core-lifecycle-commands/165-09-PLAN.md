<objective>
Close the Phase 165 blocker (Truth 8 / review CR-01) on the runtime side, plus
the two warnings the verification asked to close alongside it (WR-02, WR-05)
and the two low-risk ones that live in the same files (WR-03, WR-04).

The blocker: `init.md`'s Shelf Backlog stage calls `aether shelf-promote-batch`
"before colony state creation" — well before the Approval stage where the user
is actually asked to proceed, revise the goal, or cancel. `promoteShelfEntry`
(cmd/shelf_init.go:124) flips `Status` to `promoted` and writes `shelf.json` the
moment that command runs, and `loadActiveShelf` filters to `Status == shelved`,
so a cancel, a goal revision, or a failed `aether init` removes those entries
from the backlog with no colony to carry them forward. `promotedShelfTodos`
matches strictly on `PromotedTo == goal`, so a revised goal silently produces an
empty todo list while the entries sit stranded under the old goal string.

This plan takes the review's **preferred** fix, not the minimum-viable one:
move the mutation into the runtime. `aether init` gains `--promote-shelf` and
`--dismiss-shelf`, and performs the promotion itself, with the actual init goal,
after `COLONY_STATE.json` is written. Then:

- there is no window in which a promotion exists without a colony,
- the promotion goal and the colony goal are literally the same variable, so the
  exact-string match in `promotedShelfTodos` cannot mismatch,
- and the wrapper (plan 165-10) no longer has any shelf-mutating command to
  place before consent — the hazard becomes unrepresentable in the prose.

Purpose: init.md's own `<failure_modes>` claim ("Write nothing — no charter
call, no pheromone writes, nothing persisted") becomes literally true again, and
a test fails if it stops being true.
Output: atomic shelf promotion inside `aether init`, both colony-creation paths
wired, shelf todos visible in the recovery documents, and batch commands that
stop reporting total failure as success.
</objective>
