<objective>
Teach the repo's one markdown/YAML invocation extractor to see calls written as command
substitutions, before anything else in this phase depends on what that extractor reports.

`tokenizeShellLike` emits `result=$(aether` as a single token, and both places that locate
the binary test `f == "aether" || strings.HasSuffix(f, "/aether")`. So every invocation
written `x=$(aether …)` is invisible — including `.aether/workers.md:292`, the exact line
this phase exists to catch. Measured across the corpora this audit already claims to cover:
29 distinct command names are invoked this way and not one of them is currently audited.

This plan lands in wave 1, ahead of both the orphan ratchet (172-02) and the corpus
extension (172-03), so that neither is built on top of a blind extractor. 172-02 reuses
these exact functions to decide which commands have callers; a baseline seeded by a
substitution-blind scan would record commands as orphans that in fact have real callers,
and because that list may only ever shrink, the mistake would be permanent rather than
self-correcting.

Purpose: WIRE-03 directly, and WIRE-01 as a precondition — an honest baseline requires an
extractor that is not blind to a whole calling convention.
Output: One shared normalisation helper, command-substitution-aware extraction, redirection-
aware operator detection, and unit cases pinning all three.
</objective>

  <action>
Three changes to the extraction layer, all inside `cmd/command_call_audit_test.go`. Each one
is required for the target line to be seen and correctly validated; none of them is
cosmetic.

**1. Recognise the `aether` token when it is preceded by command-substitution syntax.**
Both `parseFencedInvocation` and the backtick branch of `extractDocumentedCalls` locate the
binary by testing `f == "aether" || strings.HasSuffix(f, "/aether")`. `tokenizeShellLike`
emits `result=$(aether` as a single token because none of `=`, `$` or `(` is a split point.

Add one package-level helper, named exactly `normalizeShellToken`, which strips a leading
assignment-and-substitution prefix matching `^[A-Za-z_][A-Za-z0-9_]*=` and then any leading
run of `$(`, backtick, or `(` characters, and returns the remainder. Apply it to every
candidate token before the binary test, in BOTH call sites, and also inside the `idx > 0`
guard that inspects the preceding token, so a genuinely nested pipeline is still rejected.

Use the one shared helper at both call sites rather than duplicating the logic — the two
branches drifting apart is how the `$(` case survived in the first place. The backtick branch
already tests `prev != "$("`, a token `tokenizeShellLike` can never produce; that dead
comparison is the fossil of the drift. Replace it with the shared helper rather than leaving
it alongside.

**2. Strip the closing parenthesis of a command substitution from the final token.**
`--enforce)` must be reported as `--enforce`, not `--enforce)`. Trim a single trailing `)`
from the last token of an invocation when the raw text contained an opening `$(` before the
`aether` token. Getting this wrong still names the flag but with a stray character, which
reads as a typo rather than as a wiring failure to a non-technical operator.

**3. Treat shell redirections as invocation terminators.**
`isShellOperator` covers `|`, `||`, `&&`, `;`, `>`, `>>`, `<`, `&`, `2>&1` and a trailing
backslash, but not the attached form `2>/dev/null`, which `tokenizeShellLike` emits as one
token. Once change 1 lands, calls such as `$(aether skill-index 2>/dev/null)` and
`$(aether state-read '.build_synthesis.watcher' 2>/dev/null || echo "{}")` become visible,
and `2>/dev/null` would be passed to the command's `Args` validator as a positional —
producing a confident, wrong failure on a correct call. Extend `isShellOperator` to return
true for tokens matching `^[0-9]*[<>]` (covering `2>/dev/null`, `>out.txt`, `>>log`, `<in`),
and keep the existing exact-match cases. Anchor the pattern exactly as written; a looser
match would silently swallow real arguments and turn violations into passes.
`validateCallAgainstCobra` already truncates at the first operator, so nothing downstream
changes.

Do not touch `auditedCorpora` in this plan. Extending the corpus is 172-03's job and it must
not happen until the extractor can see what is in the new files.
  </action>
