<why_this_runs_after_172_00>
This plan seeds a list that can never grow. Every name it records is a permanent exemption
until some later phase deletes it. So the scan that produces it must not be blind to any
calling convention.

Before 172-00, `extractDocumentedCalls` could not see an invocation written
`result=$(aether cmd …)` at all: `tokenizeShellLike` emits `result=$(aether` as one token and
the binary test compares against the bare string `aether`. A scan with that blind spot would
record a command whose only caller is a command substitution as an orphan, and the shrink-only
rule would then make that wrong entry permanent rather than self-correcting.

Measured against the working tree at planning time: 29 distinct command names are invoked as
`$(aether …)` across this repo's markdown, but **every one of those occurrences lives in
`.aether/docs/command-playbooks/` or `.aether/workers.md`**, which are never caller evidence.
The three permitted wrapper corpora plus `.aether/utils/hooks` and `scripts/` contain zero
`$(aether …)` invocations today — the only `$(` there are arithmetic expansions
(`files=$((files + 1))` in `lay-eggs.md`) and prose parentheses inside YAML strings.

So the expected effect of 172-00 on today's seeded count is **none**. Run the scan anyway and
report what you find. If the count differs from a substitution-blind run, that is a real
finding and belongs in the SUMMARY. The ordering exists so the baseline is correct by
construction rather than by coincidence, and `TestCallerEvidenceCreditsCommandSubstitution`
below keeps it correct as the corpora change.
</why_this_runs_after_172_00>

**`TestDeletingACallerMakesTheRatchetNameIt` (success criterion 4's behavioural half,
