<objective>
Close CR-04 and CR-05 — the two defects that make "the allowlist may only shrink" false
today.

CR-04: `TestPathMigrationDidNotWidenTolerance` anchors the whole shrink-only guarantee, and
it compares **bare last words**. 14 of the 278 tolerated last words are generic single
English words (`get`, `set`, `setup`, `export`, `archive`, `registry`, …). A contributor
adding a brand-new, genuinely unwired command plus its allowlist entry in one commit — the
ordinary shape of a feature commit — passes every guard including the ratchet named in the
criterion itself. The verifier reproduced this with a real registered command, not a
hypothetical. The fix is a key-format fix: compare **full command paths** against an
explicit accounting of what the 172-09 migration legitimately produced.

CR-05: that migration's frozen anchor file has no integrity pin. A hand-added line to it
passed all 30 named guard tests. Every shrink-only claim rests on a mutable file plus human
review — the exact standard CLAUDE.md's Definition of Done exists to replace. The fix is a
SHA-256 constant in Go source, asserted at test time.

Scope note — one round-3 warning is folded in deliberately because it is inseparable from
CR-04: **WR-06**, the policy document's description of this exact mechanism. The document
tells the reader the rule is "the last word of every new entry must have already appeared
somewhere in the frozen copy" (line 101). Fixing CR-04 makes that sentence describe a rule
that no longer exists, and its arithmetic sentence ("the remaining 278 are carried forward
unchanged... just renamed", lines 141-144) is already wrong — 284 paths carry forward,
because 4 collapsed last words split into 10 real commands. Under CLAUDE.md's rule that a
documentation claim about runtime behaviour must be testable or removed, leaving it would
ship a false description of the very fix this plan makes. Nothing else from WR-01..WR-14 is
in scope.

Output: an explicit 272 + 12 + 9 = 293 accounting that a same-leaf newcomer cannot slip
into, a by-construction proof that it is rejected, a hash pin on the anchor, and a policy
document that matches.
