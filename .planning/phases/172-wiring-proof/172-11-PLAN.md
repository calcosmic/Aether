<objective>
Close the workflow-level half of GAP A — the disabling routes that executing the gate
command cannot possibly see.

Plan 172-10 proves the gate's COMMAND still fails when it should. That proof is silent
about four things, because none of them changes the command: a step wearing `if:` or
`continue-on-error`, a step that is entirely commented out (`# - name: Run Go tests`) and
therefore never runs, a workflow whose `on:` triggers no longer fire on pull requests, and
a job carrying `if: false`. Each of those leaves a perfectly healthy command that CI never
executes.

Purpose: these checks are complements to the execution proof, never substitutes for it.
The plan states that in the source so a future reader cannot mistake a structural check
for the criterion's proof again — that mistake is exactly what produced two failed
attempts. The one text assertion this plan adds (the blanket run line must EQUAL the
pinned command) is a whitelist, not a blocklist of known-bad spellings, and it is safe to
keep precisely because 172-10's execution proof catches a weakened pin.

Output: a structural step locator that a comment cannot satisfy, one shared
failing-capability check applied to both gate steps, honest `-run` extraction, and a guard
that the workflow reaches the gate at all.
</objective>
