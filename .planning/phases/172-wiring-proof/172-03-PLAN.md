the binary does not register fails CI with the file, the line and the flag.

Two things stand between here and that. First, `.aether/workers.md` is not in

a permanent fixture test that reproduces the pre-fix command shape on every CI run.

`.aether/*.md` files, and a `.aether/workers.md` whose every documented invocation actually
works.

  <action>
Three changes to the extraction layer, all inside `cmd/command_call_audit_test.go`. Each one
is required for the target line to be seen and correctly validated; none of them is
cosmetic.

**1. Recognise the `aether` token when it is preceded by command-substitution syntax.**
Both `parseFencedInvocation` and the backtick branch of `extractDocumentedCalls` locate the
binary by testing `f == "aether" || strings.HasSuffix(f, "/aether")`. `tokenizeShellLike`
emits `result=$(aether` as a single token because none of `=`, `$` or `(` is a split point.
Normalise each token before that test: strip a leading assignment-and-substitution prefix
matching `^[A-Za-z_][A-Za-z0-9_]*=` and then any leading run of `$(`, backtick, or `(`
characters. Apply the same normalisation in the `idx > 0` guard that inspects the preceding
token, so a genuinely nested pipeline is still rejected. Do the normalisation in one shared
helper used by both call sites rather than duplicating it — the two branches drifting apart
is how the `$(` case survived in the first place (the backtick branch already tests
`prev != "$("`, a token `tokenizeShellLike` can never produce).

**2. Strip the closing parenthesis of a command substitution from the final token.**
`--enforce)` must be reported as `--enforce`, not `--enforce)`. Trim a single trailing `)`
from the last token of an invocation when the raw text contained an opening `$(` before the
`aether` token. Getting this wrong still names the flag but with a stray character, which
reads as a typo rather than as a wiring failure to a non-technical operator.

**3. Treat shell redirections as invocation terminators.**
`isShellOperator` covers `|`, `||`, `&&`, `;`, `>`, `>>`, `<`, `&`, `2>&1` and a trailing
backslash, but not the attached form `2>/dev/null`, which `tokenizeShellLike` emits as one
token. Once change 1 lands, calls such as `$(aether skill-index 2>/dev/null)` and
`$(aether state-read '.build_synthesis.watcher' 2>/dev/null || echo "{}")` become visible,
and `2>/dev/null` would be passed to the command's `Args` validator as a positional —
producing a confident, wrong failure on a correct call. Extend `isShellOperator` to return
true for tokens matching `^[0-9]*[<>]` (covering `2>/dev/null`, `>out.txt`, `>>log`, `<in`),
and keep the existing exact-match cases. `validateCallAgainstCobra` already truncates at the
first operator, so nothing downstream changes.

Add cases to `TestCommandCallExtractorSeesRealInvocationsAndSkipsProse` covering all three:
a `NAME=$(aether cmd --flag)` line inside a fence, a `` `x=$(aether cmd)` `` backticked
line, a call ending in `2>/dev/null`, and a negative case proving prose still does not
count. The extractor is the part most likely to rot into vacuous success; this test is
already the file's stated defence against that.
  </action>
