  <action>
Change `spawnCanSpawnCmd` in `cmd/spawn.go` so that both documented calling conventions
resolve and execute.

1. Change `Args:` from `cobra.NoArgs` to `cobra.MaximumNArgs(1)`. This accepts the
   positional depth `.aether/workers.md:292` sends AND the zero-positional flag form the
   build playbooks send. Per D-14, `workers.md` is not to be rewritten to use `--depth`;
   the criterion is pinned to the string the manual actually contains.

2. In `RunE`, resolve the depth from both sources: start from `mustGetInt(cmd, "depth")`,
   then if `len(args) == 1` parse `args[0]` with `strconv.Atoi` and let the positional win
   when it parses cleanly. If the positional is present but does not parse as an integer,
   call `outputError(1, ...)` with a message naming the offending value and return nil —
   silently ignoring an unparseable depth is the class of quiet failure this milestone is
   named after. Add `strconv` to the file's import block.

3. Register the flag in `init()`, immediately after the existing
   `spawnCanSpawnCmd.Flags().Int("depth", ...)` line:
   `spawnCanSpawnCmd.Flags().Bool("enforce", false, "Exit non-zero when spawning is denied")`.

4. Wire the deny path with REAL semantics (D-13, explicitly rejecting an inert
   accepted-but-ignored flag). In `RunE`, read the bool with `cmd.Flags().GetBool("enforce")`.
   Compute `canSpawn` into a named local variable — keep the value `true` and put a comment
   on that line naming Phase 173 / SPAWN-01 as the owner of making it a real decision. When
   `enforce` is true and `canSpawn` is false, call
   `outputError(1, fmt.Sprintf("spawn denied at depth %d", depth), nil)` and `return nil`.
   Do NOT call `os.Exit` and do NOT return a Go `error` from `RunE` — `outputError` routes
   through `markRenderedCommandError`, which is this repo's only sanctioned non-zero-exit
   path and is what `spawnLogCmd` four cases up already uses.

5. Keep the success payload shape unchanged: `outputOK` with `can_spawn` and `depth` keys.
   Include the resolved depth (positional or flag), not the raw flag value.

Structure the deny decision so a test can drive it without waiting for Phase 173 — extract
the decision into a small package-level function in `cmd/spawn.go`, for example
`spawnCanSpawnDecision(depth int) (bool, string)` returning the allow/deny answer and a
reason, called by `RunE`. Today it returns `(true, "")` for every input. This is what makes
`--enforce`'s deny path reachable by a test instead of being an unverifiable claim, and it
is the single seam Phase 173 replaces.
  </action>
