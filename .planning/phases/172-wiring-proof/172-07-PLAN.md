**1. Generalise the step locator into `stepBlock(workflow, stepName string) (string, error)`

It must locate the step whose `- name:` value is **exactly** `stepName`, matched to the end of
the line — the marker to search for is `- name: ` plus `stepName` plus a newline, not a bare
prefix. This is load-bearing: `Run Go tests` is a prefix of `Run Go tests with race detection`,
so an unanchored lookup resolves to the race step the moment the real gate is deleted, and the
fix would reproduce the very bug it is closing. Return the block text from the matched name line

line 67 with a pure function `blanketReleaseGateProblem(workflow string) error`.**

`nil` means the blanket release gate is present *and capable of failing the build*. It must
return a distinct, named error for each of these conditions:

  - No step named exactly `Run Go tests` exists. The error must contain the string

  - The `Run Go tests` step's `run:` line does not contain `go test ./... -count=1 -timeout 900s`.

    that means the locator resolved to the race-detection step and the anchoring is broken.
  - The step block contains any line whose trimmed form begins with `if:` — a conditional step
    can be arranged not to run, so it cannot be relied on to gate. The error must quote the
    condition found.
  - The step block contains `continue-on-error` — a step whose failure does not fail the job.
  - The step's `run:` line routes its exit status through a fallback that cannot fail: it

  - **The happy case.** A synthetic workflow whose `Run Go tests` step has the real run line, no
