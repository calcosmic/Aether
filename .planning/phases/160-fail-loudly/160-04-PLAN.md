anywhere produces a gate result named `anti_pattern`. This plan writes the missing
producer.

integration test that fails if the call site is removed.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker-modified files → repository | Files a dispatched worker created or modified are untrusted content entering the codebase; this is the boundary the antipattern scan guards |
| worker claims → gate input | The changed-file list comes from worker-reported claims, not from git; a worker that under-reports narrows the scan surface |
| gate result → continue outcome | The gate report drives whether the phase advances; a gate that cannot run must not read as a pass |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-160-01 | Information Disclosure | Hardcoded credential in a worker-modified file, never scanned because the scanning gate has no live caller | mitigate | `checkAntiPatternGate` is called from `runCodexContinueGates` on every continue at every verification depth; `TestContinueAntiPatternGateIsWiredIntoThePipeline` fails if the call site is removed |
| T-160-10 | Spoofing | A scan that ran over zero files reporting as clean, indistinguishable from a scan that ran over everything | mitigate | The pass `Detail` must state the number of files scanned; `TestContinueAntiPatternGateRunsEvenWhenNoFilesChanged` asserts the zero-file case is stated explicitly |
| T-160-11 | Elevation of Privilege | A scan failure (unreadable file, nil store) being swallowed so a phase advances without its security gate having executed | mitigate | `anti_pattern_executed` is classified `hardBlock` and listed in `alwaysRunGates`; `autoResolveSoftBlockGates` excludes hardBlock tiers, asserted by `TestAntiPatternScanFailureHardBlocks` |
| T-160-12 | Tampering | Two divergent scanner implementations, so the CLI and the gate disagree about what counts as critical | mitigate | Single `scanFileForAntipatterns` used by both; the doc comment prohibits a second scanner; `cmd/security_gate_drift_test.go` passes unmodified |
| T-160-13 | Information Disclosure | A worker under-reporting `files_modified` so a file with a credential is never scanned | accept | Same trust model already used by claim verification elsewhere in continue (RESEARCH.md assumption A2); introducing a second git-derived file list would create a competing notion of what changed.
