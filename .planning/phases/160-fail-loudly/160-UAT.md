## Issue found and fixed during UAT

### Absent files were counted as successfully scanned

**Severity:** major — a security gate reporting success without running is this phase's
own headline failure mode, rediscovered inside the fix for it.

**How it surfaced:** probing what a *failure* looks like — the phase is called "Fail
Loudly", so the meaningful question was whether a broken call is legible. Passing a
nonexistent path to the scanner returned `clean: true`, exit 0.

**Root cause:** `scanFileForAntipatterns` deliberately returns clean `(nil,nil,nil)` for a
file that does not exist. That is correct for the CLI — a phase may legitimately have
deleted the file. But `checkAntiPatternGate` inherited it and counted absent files in
`scannedFiles`, so a gate that read nothing reported:

```
anti_pattern_executed: passed — "antipattern scan executed successfully across 1 file(s)"
anti_pattern:          passed — "scanned 1 changed file(s), no critical patterns"
```

A phase whose claims name files that never landed, or whose paths fail to resolve against
the colony root, would have received a confident all-clear from a scan that never ran.

**Why the plan's own tests missed it:** every test fed the gate files that existed. The
gate's author had even anticipated the adjacent concern — there is a comment in `gate.go`
saying a pass detail must state the number scanned so that *"scanned nothing"* is
distinguishable from *"scanned everything and found nothing"* — but the count itself was
wrong, so the safeguard reported a reassuring number.

**Fix** (`cmd/gate.go`):
- absent files are tracked separately and never counted as scanned
- if files were claimed and **none** could be read, `anti_pattern_executed` **fails**
  (hard block) — per D-01, a phase must not pass with its safety gate unexecuted
- partial scans name the absent files: `"executed across 1 of 2 claimed file(s); 1 absent
  (deleted or wrong path): gone/missing.go"`
- the findings detail now reads `"scanned 1 of 2 claimed file(s)"`, so scanned and
  claimed can never again be conflated

**Pinned by:** `TestAntiPatternGateDoesNotCountAbsentFilesAsScanned` (two subtests:
all-absent hard-blocks; partial scan reports both counts).

**Verified after fix:**
```
executed=false "antipattern scan executed against 0 of 1 claimed file(s);
                none could be read (absent: totally/absent/file.go)"
```

## Side effect disclosed

While probing failure output, `aether gate-results-write --name "test_gate"` was run
without `--passed`. It succeeded and **wrote a real gate entry into COLONY_STATE.json** —
a probe that mutated state. The entry was removed and colony state verified clean.

Two things worth noting from that accident:
1. `gate-results-write` silently defaults `--passed` to false rather than requiring it.
2. `--fixer-mode banana` was not rejected as an invalid mode.

Neither is in Phase 160's scope. Both are recorded here rather than fixed.
