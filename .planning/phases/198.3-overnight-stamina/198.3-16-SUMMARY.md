### Auto-fixed Issues

**1. [Rule 1 - Bug] Preserved rapid failures after a recovery boundary**

- **Found during:** Task 2 (public fresh-epoch re-escalation test)
- **Issue:** Ordinary direct and external swarm results used second-precision timestamps while recovery rows used nanoseconds. Several fast failures in the same second sorted before the recovery and were incorrectly cleared.
- **Fix:** Switched both terminal outcome lanes to `time.RFC3339Nano` so durable ordering reflects the real event sequence.
- **Files modified:** `cmd/swarm_cmd.go`
- **Verification:** The public recovery test now records three immediate new failures, recreates one stable escalation, and refuses the next attempt; all 63 swarm tests pass.
- **Committed in:** `d7603037`
