| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Validate after writes | `swarm_id` is rejected only after earlier files and state can already be changed. | blocking | Validate at the public boundary before `beginRuntimeSpawnRun`, `initializeSwarmRun`, or any store access. Assert byte-for-byte zero mutation. |
| Trust self-supplied proof | Plan-only does not register a manifest, while finalization trusts the manifest bundled with the result and overwrites `result.json`. | blocking | Persist an immutable issuance digest or one-time capability; consume it once; compare completion digests for replay. |
| Treat unreadable as empty | Seal's legacy fallback ignores load errors and can convert unavailable blocker truth into "no blockers." | blocking | Use one canonical error-aware blocker reader everywhere and distinguish only genuine not-found from corrupt/unreadable. |
| Validate only the new schema | Structured reviewer artifacts validate severity, but the legacy branch checks only body text. | blocking | Normalize both schemas through one severity allowlist and emit an evidence blocker on invalid input. |
| Hash mutable evidence | Checkpoint code hashes whatever currently occupies `claims_path`, even when it differs from the built attempt. | blocking | Commit claims or a canonical digest at the built transition and compare before path derivation or decision writes. |
| Project unscoped history | Cadence filters by revision but not session/goal, so stale decisions can suppress current replanning. | blocking | Apply `pendingDecisionMatchesScope` before cadence projection and test identical revisions across scopes. |

## Critical Anti-Patterns (do NOT repeat these)

- LATE VALIDATION: rejecting untrusted identity only after a path or state write → validate at the command boundary and prove zero mutation.
- SELF-ASSERTED AUTHORITY: treating evidence and its authority as trustworthy because both arrived in the same file → bind it to prior runtime issuance and immutable digests.
- FAIL-OPEN COMPATIBILITY: protecting the new storage/schema while a legacy branch silently bypasses it → route all variants through one canonical validator.
- MUTABLE PROVENANCE: calling a path immutable while rereading changeable bytes from it → compare against attempt-committed content.
- UNSCOPED DURABLE HISTORY: using persisted decisions without session/goal filters → require full scope identity at every projection.
- PARITY BY INVENTORY: declaring the colony restored because commands or data fields exist somewhere → verify complete user journeys, live presentation, behavior, and owner confidence.
- SIDEWAYS EXPANSION: adding more agents or biology vocabulary without making the existing colony loop observable and causally real → restore closed-loop behavior and measurable influence first.
