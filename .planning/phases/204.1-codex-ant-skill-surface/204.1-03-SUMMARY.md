# Phase 204.1 Plan 03: Published Codex skill delivery Summary

**Publish, install, and ordinary update now consume one validated hub payload, with skill migration and ownership included in update's existing transaction.**

In plain English: updating Aether delivers the same skill files as a fresh installation, keeps custom files safe, and reports invalid inputs instead of claiming a successful update.

## Accomplishments

- Publish atomically writes the manifest, nine public skills, and three support files. Install consumes those exact published bytes. Generic cleanup preserves the generated subtree; incomplete, corrupt, incompatible, or unsafe payloads fail validation before home synchronization.
- Normal and forced registered updates plan skill writes, bounded legacy removal, and ownership alongside existing update targets. Dry run creates no lock or journal; replay leaves skill bytes, modes, and ownership unchanged. Custom skill/document preservation and restart inputs are reported with the shared `Skills (codex shims)` label.
- Compatible later payloads supply their own inventory, including unfamiliar entries. Downgrades and incompatible payloads are refused. Stable/dev isolation and existing explicit opt-in/refusal behavior remain covered.

- **Commits:** `3338c3c0`, `4d05d190`.

**2. [Rule 1 — Bug] Version comparison treated a numeric patch with a prerelease suffix as zero.**

- **Found during:** Task 2 registered stable publish/update regression with `1.0.99-test`.
- **Issue:** The existing comparison incorrectly placed that newer runtime below `1.0.79`, preventing a valid payload update.
- **Fix:** Compare numeric core versions before prerelease identifiers, ignoring build metadata; cover release/prerelease and numeric/text ordering.
- **Files:** `cmd/update_cmd.go`, `cmd/codex_skill_update_test.go`.
- **Verification:** A separate RED run exited 1 and exposed three incorrect comparisons. Its slash-filtered discovery reports zero names because `go test -list` does not enumerate subtests; raw execution records one parent and one failing subtest. The complete parent is discovered and passes in final normal/race runs.
- **Commit:** `4d05d190`.

**Total deviations:** two bounded fixes, one blocker and one bug. Both were necessary to preserve the strict payload contract and pass the required production regressions.
