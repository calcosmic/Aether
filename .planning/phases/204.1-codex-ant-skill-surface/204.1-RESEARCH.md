### Selected distribution contract

1. **Public inventory:** exactly init, discuss, oracle, colonize, plan, build, continue, swarm, seal. Public directory and frontmatter names are ant-<command>. Identifiers use exact lower-case ASCII bytes; invalid, duplicate or missing definitions fail generation instead of silently shipping fewer entries. Runtime routes still come from commandGuideCatalog.
2. **Discovery destination:** retain the currently observed user path .codex/skills/aether under the selected home as the initial supported destination. Plan 01 qualifies it with a fresh real client before expansion. This is an explicit assumption until that receipt exists. Failure to discover there stops the tracer; it must produce a narrowly revised destination/root plan, not silently declare success or write through ../.agents. Adopting .agents/skills would require an explicit typed transaction root and corresponding containment tests. No whole-home root is authorized.
3. **Private support:** stop emitting the five helper SKILL.md entries. Three detailed source helpers are copied as ordinary support/aether-colony-creation.md, support/aether-colony-research.md and support/aether-colony-build-cycle.md beside the public directories. Public skills resolve these relative to their own installed SKILL.md, never the working directory. The two short command-guide/skill-loader explanations are folded into the generated public instructions. These support files have no SKILL.md leaf and are not public commands.
4. **Versioned desired payload:** publish system/codex-skills/manifest.json and the nine skills plus support files. Manifest schema codex-skill-payload/v1 records source_version, generator identity when available, min_runtime_version, inventory IDs, relative paths, modes and SHA-256 content digests. Contents and manifest must agree before consumers plan any mutation. Unknown schema, incompatible minimum runtime, missing/empty/partial payload or digest mismatch refuses skill synchronization. Payloads may carry a later inventory under a supported schema; consumers do not regenerate or prune it using an older compiled nine-entry list. A source checkout publish generates from the executing candidate; release proof records both candidate and payload identities. Older pre-feature binaries are outside the new upgrade contract and require bootstrapping the current source/binary before using this route.
5. **Ownership:** persist .aether-owned.json in the installed grouping directory, schema codex-skill-ownership/v1, with payload identity and each owned relative path's exact digest and mode. An owned file is writable/removable only while its current bytes and mode still match its recorded baseline. New absent targets are creatable; unowned existing destinations are collisions even when their names or source frontmatter resemble shipped files. A frozen, source-cited legacy v1.0.79 digest fixture permits adoption/removal of the original fourteen unmodified shipped SKILL.md files; arbitrary older versions stay preserved and reported until their exact evidence is supplied. No recursive directory removal. Empty owned directories may remain harmlessly.
6. **Retirement and collision behavior:** explicit legacy retirement records identify exact files and accepted prior digests. An edited or unknown old-name file is preserved and reported; it is not relabelled managed. A colliding canonical destination or modified owned support file prevents the skill-set transaction from applying and reports the path/reason, including under --force. Unrelated custom files and unknown newer entries survive. A lower-version desired payload cannot overwrite a newer installed ownership manifest. A missing/corrupt ownership manifest is not replaced over existing files on trust.
7. **One mutation policy:** install and publish use the same skill target planner as normal update. Install/publish may retain their existing unrelated companion-file behavior, but the Codex skill set and its ownership record commit together through LifecycleTransaction. Normal update appends the exact targets to its existing all-target plan before prepare/commit; no after-transaction writer. Ownership classification freezes existence/absence, digest and mode from the same readLifecycleFileState snapshot for every planned skill, support, retirement and ownership-manifest target, including absent and unchanged targets. ExpectedDigest always carries that digest or the existing lifecycleTransactionMissingDigest sentinel; new ExpectedMode *os.FileMode carries an immutable copy of Mode.Perm(), with nonnil zero for absence. Unrelated maintenance callers retain optional digest/nil-mode behavior. The common commit acquires the shared Codex-target lock before re-preparing, validates every original expectation before any target write or journaled mutation, and retains original expectations when checking declarations. A fresh preview cannot replace that authorization baseline. Locking serializes installers but does not stop user edits: newly created custom canonical files and chmod-only edits must refuse without changing any user bytes/modes or ownership state. Preview creates neither lock files nor journals. Interrupted/unverified recovery uses existing transaction receipts and preserves intervening user edits as recovery-required. Verified updates are not downgraded through Rollback.
8. **Channels:** stable updates target stable home skills. Dev install/publish preserve their existing default no-home-sync and explicit opt-in policy; dev update retains its current refusal of --sync-platform-homes. Explicit dev install/publish opts into the existing stable-home behavior and must report that scope; default dev operations leave it byte-identical. No new automatic cross-channel writes.
9. **Guidance:** format only those nine Codex display commands as $ant-*. CLI/raw/exact invocations, environment-prefixed shell lines, finalizers, machine identities and other 55 actions retain their existing CLI spelling. Update managed templates and installation restart reporting; preserved custom project instructions are reported. Removal-only changes require a fresh session, unchanged updates do not.

The payload/ownership format is a versioned internal distribution contract, rated costly but recoverable: it has a strict reader, records source bytes, refuses unknown formats and retains prior transaction images. It creates no colony-data migration or new public service contract. The public naming choice is already the owner's decision, so no repeated approval is required.

**Targeted source correction (revision 1):** cmd/platform_sync.go currently checks ExpectedDigest only when nonempty, and commitMaintenanceMutation re-prepares before comparing declaration modes to the refreshed preview. Thus a digest-only contract loses expected absence and an ownership-time chmod baseline. Plan 02 adds the optional expected-mode field and complete immutable expectations above, with named common-boundary refusal tests. Plan 06 repeats both cases through normal registered update using the default-real maintenanceCodexSkillLocker seam; this proves update carries the original contract. This is a bounded correction to PATTERNS' digest-only guidance, not a new distribution design or implementation evidence.

### Proof boundaries and plan grouping

Plans 01–03 deliver clean installation, content-proven migration and published ordinary updates. Plan 04 can follow 01 in parallel with 02 because its display/guide files do not overlap migration files. Plan 05 updates generated and source guidance after 04, in parallel with 03; 03 owns update-result plumbing while 05 owns the existing restart aggregator. Plan 06 exercises interrupted/conflicting updates, source validation and break-the-wiring controls. Plan 07 captures all nine in fresh real sessions before/after a supported upgrade, records the narrow capability contract and writes the required standard 204.1-VERIFICATION.md.

Each plan begins with a production tracer for its own slice or explicitly consumes the successful Plan 01 tracer. A failed/unavailable paid host stays unverified. The live proof deliberately stops after loading the selected skill, reading private support where applicable, executing its real command-guide and reporting the next runtime route. This proves discovery and entry routing, not native-worker or complete lifecycle parity. Full normal/race release qualification belongs to 204.5; this phase runs focused affected checks with discovered/executed counts and meaningful negative controls.

No source change, product test, installation, live provider session or owner walkthrough was performed during planning. Original Phase 205 evidence and the prepared owner project remain outside these plans.
