## Contract selected for implementation

NEW internal CLI: `codex-native-worker reserve|bind|record|stage|inspect|observe|context|question --request <absolute-regular-file>`. Mutations return typed JSON through the existing output envelope. `inspect` and `context` are read-only. `stage` projects only saved journal results through stageBuildAttemptCompletionFromWorkerRuns; it never launches or credits work. There is no public skill for this internal command.

NEW `codexNativeWorkerRequest` has schema_version, operation-specific required fields, phase, the existing `codex.ExecutionBinding`, worker_name, task_id and a Go-issued launch_id. Bind/record/observe also require exact host_session_id, child_id, dispatch_sha256 and prompt_sha256. Submitted prompt, caste, permission, workspace or covered task IDs never replace the saved manifest. Requests are bounded to 2 MiB, strict-decoded, and follow the adapter's regular-file/non-symlink/approved-temporary-root rules.

NEW optional `buildAttemptWorkerRun.Native *codexNativeWorkerBinding` retains schema_version, launch_state, host_session_id, child_id, dispatch_sha256, prompt_sha256, requested permission, canonical workspace, source-event identity/digest and acknowledged context-delivery IDs. Existing ProviderRunID is the launch_id; existing attempt binding is still authoritative. No ProcessID is invented. Old records omit Native and keep the subprocess behavior.

State sequence: reserved -> bound -> running -> terminal. A reservation is written before spawn. The child initially waits for the runtime-issued release message; binding the returned child ID must succeed before the host releases it. A crash after reserve/spawn but before bind is `launch_unresolved` on recovery. Inspection cannot turn it into a new launch permission. Reconciliation uses saved real host events or reconnects to the same child; otherwise report unavailable and keep the assignment incomplete. Terminal statuses preserve completed, failed, blocked, timeout and confirmed cancellation; unknown is not terminal. Repeat identical requests return the original receipt with no timestamp/write churn; conflicting repeats refuse. Retry of failed work uses the existing append-only attempt/retry path, never a replacement launch under the old reservation.

The host records each observed terminal response before waiting on another child or staging a packet. It retains raw host events so a fresh session can recover a genuine terminal response that arrived before the parent's journal write. If the host cannot expose that response, no result is invented. Per-worker records may exist with no aggregate; after all required results exist the existing staging and finalizer paths are used.

NEW native questions extend existing `PendingDecision` with optional exact native scope (goal/session/attempt/launch/worker/child/question ID). `decision-answer` gains a bound request-file route for those questions, preserving its checkpoint/waiver capability paths. An unbound text answer cannot resolve or leak a protected native question. Native answers are excluded from general all-worker clarification rendering and delivered only to the intended child/current dispatch.

All additive contracts use `omitempty` for backward-compatible absent fields. They remain internal and confined to disposable proof until later qualification. Reversibility: costly, because journal readers must stay aligned; no published external contract or shared-store migration is performed here.

## Evidence contract and bounded execution

Each real scenario writes under a new durable root such as `~/.aether-backups/phase204-2-execution-evidence-<date>/`, with checked-in receipts in this phase's `evidence/`. Use task-specific isolation variables and subprocess environment dictionaries; never reassign the developer's HOME/CODEX_HOME.
