## Current call graph and execution boundaries

### Existing skill-led path

1. Installed `$ant-build` reads installed private support and the runtime command guide.
2. `command_guide.go:387` requests `aether build <phase> --plan-only`.
3. `runCodexBuildPlanOnlyWithOptions` (`codex_build.go:636`) prepares assignments; `newBuildStartRequest` and `commitBuildStart` (`858-874`) authorize a durable attempt, followed by brief persistence and manifest reload (`887-905`). It does not invoke helpers.
4. Current skill source `294-310` instructs the host to spawn and log native helpers. `command_guide.go:404` waits until **all** terminal results are accepted before calling `build-completion-stage`; there is no per-child native run binding in that instruction.
5. `build-completion-stage` reaches `stageBuildAttemptCompletion` (`build_attempt.go:971`). `build-finalize` reaches `runCodexBuildFinalize` (`codex_build_finalize.go:428`).

**Planning consequence:** add per-helper native admission/binding/terminal recording before aggregate staging. Merely retaining the existing all-workers packet step leaves the requested one-helper-finished interruption window exposed.

### Existing Go-owned provider path

`internal-worker-adapter` → `runInternalWorkerAdapterForPhase` → request/binding/permission validation → `beginBuildAttemptWorkerRun` → `invokeInternalWorker` → selected provider → validate/map result → `recordBuildAttemptWorkerTerminal` → `stageBuildAttemptCompletionFromWorkerRuns`.

The actual Codex provider is a subprocess. `pkg/codex/worker.go:385` calls `AssemblePrompt`; `427-445` creates:


`exec.CommandContext` then assigns `cmd.Dir = config.Root` and sends the prompt on stdin. `ShouldUseAgentDelegatePath` (`pkg/codex/platform_dispatch.go:318-327`) returns true only for Claude/OpenCode delegate sessions. Naming a function/test “native” in this repo frequently means this direct Go lane; it does not establish a host `spawn_agent` call.

`buildExecutionOwner` (`cmd/codex_build.go:3040-3053`) currently maps real/simulated to `runtime-worker-dispatch`, external-task to `platform-wrapper`, and queen-led/plan-only to `host-queen`. The adapter response separately reports `go-adapter`. Preserve the distinction between attempt owner and response implementation label; do not silently change a bound attempt's owner or infer native ownership from either string alone.

### Recommended synthesis decision, subject to the early host experiment

Use one **host launcher** for the native lane and a **non-launching Go bridge** for admission, child binding, terminal receipts, and recovery projection. Compose existing journal/finalizer functions. Do not call `internal-worker-adapter` to execute a job and also call the native spawn tool for that job.

Use the existing provider lane explicitly when a requested sandbox/workspace capability is unsupported. A subprocess fallback cannot count as the required native Builder/Watcher evidence. Native worktree allocation and shared recruited-child integration remain 204.4 seams; this phase can prove shared-root native work and refuse or select an explicit supported lane for unsupported workspaces.

## Pattern Assignments

### `cmd/codex_native_worker.go` — validation and launch ownership

**Primary analog:** `cmd/internal_worker_adapter.go:28-45,94-120,180-255,325-379,448-484`.

Follow `package cmd`, standard library imports first, then `github.com/calcosmic/Aether/pkg/codex` and `github.com/spf13/cobra` (`3-15`). Use a bounded typed request, a Cobra `RunE`, typed response, `%w` wrapping, and sanitized errors. The existing handler pattern is (`105-111`):

```go

if err != nil {
	outputError(1, sanitizeInternalWorkerAdapterError(err.Error()), nil)
	return renderedErrorExit(1)
}
outputOK(response)
```

Copy the boundary shape, not the invocation. `loadInternalWorkerRequest` restricts request files to approved temporary directories, regular non-symlink files, 2 MiB, and `decoder.DisallowUnknownFields()` (`325-378`). Native endpoints must use runtime-loaded assignment data and validate submitted IDs/digests rather than trusting a caller-supplied prompt, role, or permission profile.

The adapter validates its execution binding before config resolution (`180-195`) and caches finished work before provider invocation (`208-216`). Its result validation checks worker name/caste/task and forbids successful status with invocation error (`448-483`). Use equivalent checks at the native boundary, including host child identity, immutable prompt/assignment identity, and exact workspace.

**Important gap:** the internal request has no native child/session identifier. `beginBuildAttemptWorkerRun` checks membership by name/task/caste, not the complete submitted prompt/profile. The new bridge must not turn that partial check into a claim that arbitrary submitted native launch data was authorized.

- `recordBuildAttemptWorkerTerminal` (`138-189`) relies on its caller for result identity validation; the native endpoint must perform that validation before this write. Its allowed status set and cancellation representation are not identical to every finalizer status spelling.
- A crash between host spawn and durable child binding must leave an honest unresolved launch, not automatic permission to spawn again. Plan an explicit reservation/bind/terminal handshake and real-host recovery evidence for that window.


This is desirable: one finished helper can be durable while the aggregate is not ready. `buildCompletionFromWorkerRuns` (`344-388`) derives manifest-owned fields from the retained plan and requires a terminal result per dispatch. It must remain distinguishable from completion credit.

## Shared Patterns

1. **Authorization is data binding.** Reuse `ExecutionBinding` and runtime-issued dispatches. Check currency both before work and under the atomic write. Native host IDs extend provenance; they do not replace run/attempt/workspace identity.
2. **The journal is the terminal boundary.** Persist one validated result as soon as it arrives. Only assemble the aggregate when the required records exist; only the finalizer grants credit. Do not conflate admitted task receipts with completed tasks.
3. **Errors preserve evidence.** Use typed contract violations and `%w` errors. Rejected launch/result requests must leave saved work and accepted identities intact. Unknown native status must not fabricate cancellation or success.
