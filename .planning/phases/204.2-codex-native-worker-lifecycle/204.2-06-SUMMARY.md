# Phase 204.2 Plan 06: Honest Native Recovery Summary

**Native recovery preserves saved helper results, names unfinished and unresolved assignments, and keeps pause/cancellation pending until the host supplies matching terminal evidence.**

In plain English, a fresh chat can see which work survived without starting the same helper again. A helper that cannot be located remains uncertain; its missing process ID is never treated as proof that it stopped.

## Interface handoff

- `buildCodexNativeRecovery(state colony.ColonyState) *codexNativeRecovery` is read-only. It grants no launch, cancellation or credit.
- `native_recovery` returns `attempt_id`, `phase`, `valid`, `finished`, `unfinished`, `unresolved`, `active`, `next`, `summary`, `why` and optional diagnostic `error`. Worker facts retain name/caste/task, original launch/host-session/child identity, result digest and actual observation time.
- `unfinished` contains only assignments without a saved worker run. `active` means last-observed running or cancellation pending, not a fresh liveness check. `last_host_status` preserves an unavailable observation even while `host_status` keeps cancellation pending. `context_delivered` events are excluded when selecting host activity status and observation time.
- Partial or unknown work names `aether codex-native-worker inspect --phase N`; all-terminal work without an aggregate names `stage --phase N`; an aggregate retains `buildFinalizeRecoveryCommand`. A valid paused attempt names `aether resume`; conflicts name `aether status`. Plan 03 implements the phase-only routes at `de76511c`. No recovery read creates request files or stages results.
- Plan 05's `validateCodexNativeAttemptState(record, state) error`, tested at `faf681ce452652f11d78ca7e335d7ab831474956`, is the shared current-colony authority. It rejects changed goal/plan/run identity, including before first launch, and validates genuine pause/resume drift through the existing committed receipt and original-state preimage. No local state-mask authority was added.
- Public unpaused native resume returns a read-only recovery outcome with no new run/session or credit. Existing pending pause and resume transactions are repaired first, and retained handoff evidence is validated before advisory projection. A real paused handoff still uses ordinary validated resume writes.
- Pause retains the Plan 02 repository session from first read through transaction and all five captured targets: COLONY_STATE, session, pause-handoff, CONTEXT and HANDOFF. Active, unresolved or invalid native facts keep pause pending. Pending native pause output itself writes no handoff or lifecycle closeout.
- `host_action` names the original host session and exact child/launch. Stopping requires the host's actual interruption/cancellation tool and matching terminal acknowledgement. Capability unavailable stays pending.
- `renderCodexNativeWorkerActivity` is pure inline rendering. The Plan 02 bridge remains the source of accepted bind/observe/record start/running/finish emissions. Snapshot rendering and replay emit no duplicate transitions and create no spawn ledger.
