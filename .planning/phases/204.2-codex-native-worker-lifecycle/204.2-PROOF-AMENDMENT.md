# Phase 204.2 proof correction — owner approved

Approved 2026-09-18 by the owner's explicit selection `1`, after the two
alternatives and their consequences were explained in plain English.

The selected alternative: test behavior we can establish, retain correctness
checks, and refuse an operation when safe cancellation or recovery cannot be
established. This enables further work; it does not declare the phase passed.

## Authority and reason

Original ANT-04–06 require governed native workers, durable recovery and complete
helper context. ANT-07 explicitly allows unavailable abilities to be refused.
The original Claude comparison is a minimal real build/check journey
(`204.2-07-PLAN.md`, `204.2-SYNTHESIS.md`). Later gap plans expanded this into
complete internal tools/settings exports and complete host-authored post-cancel
write coverage, separately on both hosts. That expanded conjunction blocked all
progress even when the missing capability could honestly remain unsupported.

This decision prospectively supersedes the later owner's earlier selection to
preserve all twelve acquisition obligations. It supersedes conflicting admission
and success predicates in Plans 21–26, GAP2/GAP3 guidance and the collector design.
Original ANT requirements remain unchanged. Historical evidence, blocked verdicts,
and reports retain their meaning under the contract used when recorded.

## Acceptance boundaries

| Subject | Required prospective result |
|---|---|
| Real ordinary work | Installed ant-build launches a real bound Builder; edits/checks, durable result and exact credit are independently checked. Parent implementation cannot substitute. |
| Requested review | A genuinely requested separate Watcher returns attributable findings. Ordinary work remains proportionate. |
| Complete context | Runtime capsule, matched skills, steering and handoffs reach the intended child, retaining exact bytes, Unicode/whitespace and existing size bounds. Expected files or fabricated acknowledgements do not prove delivery. |
| Scoped answers | Current-question/current-assignment delivery, actual child acknowledgement and subsequent work. Wrong-child, stale, duplicate and pre-question answers reject. |
| Recovery | Completed work survives fresh-session resume without repeat writes/credit. Unfinished or ambiguously active work is identified; unsafe resume or redispatch refuses. Core recovery is mandatory, not an optional capability. |
| Host settings/tools | Record observed actual version, invocation and supported settings/behavior with provenance. Unavailable complete internal settings/tool definitions remain explicitly unavailable. They no longer block unrelated proved behavior. |
| Cancellation | A supported claim still requires actual correlated cancellation evidence. Otherwise the public/runtime path must explicitly refuse unsafe cancellation-dependent completion, recovery or redispatch. A request, timeout or quiet interval cannot become terminal credit or a no-write guarantee. |
| Other host capabilities | Record actual measured support or an attributable refusal for permissions, workspace and nesting. Unknown values stay absent; no inferred usage/cost. |
| Claude comparison | One comparable real build/check journey, with actual helper work and durable outcomes. It does not need all six Codex evidence obligations. |

No universal `NoPostAckWrites=true` predicate is required. Where the coverage
cannot be established, that value remains false/unproved and no such guarantee
is advertised. A refusal qualifies only the claim that the unavailable operation
is refused safely; it never qualifies successful cancellation.

## Evidence and implementation

- Retain the same eleven scenario names and exercise their required behavior.
  Only host-capability outcomes may use supported/refused dispositions. Ordinary,
  requested review, context/question, core recovery and exactly-once credit cannot
  be relabelled unsupported to bypass failure.
- Preserve strict original-file inventory, candidate/client identity, immutable
  raw capture, malformed/substituted evidence rejection and independent replay.
  Synthetic controls establish validator behavior only, never live qualification.
- Source discovery for mandatory behavior remains required. An unavailable optional
  host export no longer gates every live scenario. New adapter methods still need
  source-grounded mappings; no invented exporter, interception or replacement
  launcher is authorized.
- Preserve the native launcher and Go's assignment, journal, decision and result
  authority. Use fresh prospective receipts explicitly naming this amendment;
  never rewrite old blocked receipts into successful results.
- An unsupported-operation test must exercise the real public/runtime guard and
  check absence of new work/credit. A JSON flag written by the test is insufficient.
- Resource admission, isolated disposable fixtures, final exact focused/full
  normal/race checks and standard verification remain required. No broad suite
  before the final qualification step.
- The installed CalVault hotfix, shared homes, credentials, real CalVault data and
  Phase 205 owner acceptance remain outside this execution scope.

## Immediate sequence

Record the amendment and revise Plans 21–26; review their dependency/claim
boundaries. Then implement prospective evidence dispositions and real refusal
checks, run focused controls, and attempt the smallest admitted actual worker
cases. Preserve any remaining mandatory-behavior failure as a real blocker with
its specific evidence. Successful planning or offline tests cannot complete the
phase. Requirement credit follows the final qualification and verification.
