## What changed

`validateCodexNativeCompletion` checks the saved attempt's native journal before considering caller compatibility. It requires a current bound manifest, exactly one native terminal per dispatch, immutable assignment/prompt identity, canonical accepted result digest, matching bound child/release and exact whole-packet equality with the journal projection. Dropped binding, changed results, duplicates, extra workers, damaged saved evidence and unknown host fields fail before staging or credit.

Staging establishes one existing repository mutation session, then the worker mutex and attempt lock. It checks current native goal/plan/run state before writing a packet. Final credit repeats native journal and normalized state currency inside the existing atomic state boundary, under repository session → worker mutex → attempt lock → state lock. A read-only sentinel exits the attempt callback without rewriting journal bytes. No second native credit writer was introduced: structural/semantic checks, receipt resolution, coherent/worktree receipts and `commitBuildFinalizeState` remain authoritative.

Native cancelled and no-launch results project as the existing `interrupted` completion status; their saved native results and digests stay unchanged. No-launch carries no child, files or task receipts. A cancelled or failed grouped job can retain independently proven completed task receipts, while unfinished tasks remain pending. Unknown/unconfirmed native work remains incomplete. Artifacts, scout findings and handoffs survive projection. Host identity and usage stay outside the completion wire; no measurements are invented.

Equal staging replays return the existing bytes, digest and path without timestamp churn. Finalizer replay preserves task credit and events. Reversed independent terminal arrival orders retain manifest order and identical credited task identities.

## Shared state validator and session provenance

The frozen shared signature is:

```go
func validateCodexNativeAttemptState(record buildAttemptRecord, state colony.ColonyState) error
```

It is an explicit native-call identity validator and validates accepted state even before the first native worker exists. Callers retain their existing lane, current-pointer and binding validation. Launch and final credit keep separate paused-state refusal; authenticated paused state may be inspected or stage saved terminal evidence.

A real pause/resume changes session metadata. The validator accepts those changes only with the existing matching handoff, exact committed pause/resume transaction receipt, validated transaction evidence, and a normalized pause preimage whose hash equals the attempt's OriginalStateSHA. Remaining goal, plan and task state must match exactly. The allowed session fields are those written by the existing lifecycle transaction; the ordinary EXECUTING → READY transition is allowed. A forged pause, changed run, damaged receipt or goal/plan/task drift alongside otherwise valid pause/resume provenance fails closed.

Plan-only attempts have no original build checkpoint, so this uses the existing transaction's hash-checked state preimage; it creates no new ledger or checkpoint exception. Session-provenance eligibility requires either actual saved native workers or accepted Codex host-queen plan-only intent. The generic bound-manifest exception remains restricted to actual native workers.
