## Acquisition is a real prerequisite

Plan 24 is bounded technical discovery inside execution, not another broad research phase or a repeat of CLI help. It must inspect supported installed interfaces/protocol/source and, where needed, official version-applicable documentation. A generated app-server protocol schema helps locate an API; it does not prove the model-facing tools of a running session. A prompt reconstruction does not prove what a particular child received. Source citations alone do not replace the required small actual probe.

The required evidence rows cover actual effective settings/full tools for each required host, exact delivered context and answer with child acknowledgement, correlated cancelled terminal and complete observation interval. Each demonstrated method must specify exact raw fields, binding and coverage semantics. No method or wire shape is invented by these plans.

A Plan 24 success requires all needed methods to be demonstrated, including the Claude comparison source; missing availability produces status blocked and ready_for_adapter=false. Do not create a successful SUMMARY when blocked: execute-phase skips SUMMARY filenames without inspecting semantic success. Save a BLOCKED report/continuity and stop instead. Plans 25–26 independently check the acquisition evidence, so a stale or erroneous SUMMARY alone cannot release them.

If supported source discovery fails, the next result is a precise external capability dependency or concrete requirement/architecture decision for the owner. No permission is sought in advance of that result. Changing required proof, adding an interception/control-plane architecture, patching vendor clients, or substituting behavior for plaintext is not authorized by gap planning. Existing requirements and verification remain intact.
