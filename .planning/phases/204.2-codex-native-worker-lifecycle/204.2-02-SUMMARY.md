# Phase 204.2 Plan 02: Atomic Native Admission and Durable Outcomes Summary

**Native reservations bind the accepted assignment exactly once, terminal responses replay without writes, and pause cannot carry an idle decision across a newly admitted helper.**

In plain English, a retry gets the saved receipt for the same helper. An uncertain launch stays uncertain, and pausing cannot quietly authorize another helper or erase a returned answer.

## What changed

Every native mutation repeats full ExecutionBinding validation, checks the actual saved manifest digest and canonical workspace, and rejects a superseded latest-attempt pointer. The saved dispatch, prompt bytes/digest and resolved permission remain immutable. Caller-supplied reserve hashes cannot authorize caller-authored work. Identical reserve/bind/result calls return a typed replay disposition and immutable transition receipt without updating journal timestamps or bytes.

The existing file lock is reentrant for one Store, so worker journal mutations also share one package-wide mutex. Native mutations acquire the existing repository mutation session first. Pause now holds that same session from its first facts/baseline reads through its transaction, preventing both an admission that overtakes a paused state and a stale idle pause that overtakes admission. The lock order is repository session → worker mutation mutex → attempt file lock; pause follows repository session → lifecycle transaction mutex. There is no second native state ledger or new lock marker.

A normalized deep copy of the terminal result is hashed and saved. Completed, failed, blocked, timeout and confirmed native cancelled preserve their files, task receipts, handoffs, blockers and error details. Wrong/duplicate task-receipt membership is refused before persistence. Equal terminal replay returns before filesystem-dependent completion preview checks, so later file changes do not invalidate an already accepted receipt. A paused current attempt can still save an already-returned terminal; a superseded attempt cannot.

Native records are excluded from PID/30-second death inference and ordinary bulk cancellation. Host observations retain source event identity, SHA-256, timestamp, child and status in an append-only history. Repeated identical observations are byte-stable, conflicting or older observations refuse, cancellation stays pending until confirmed, and unknown launch/connection state never grants relaunch. Confirmed no-launch closes the reservation without work credit. The existing new-attempt/retry route is required for further work.

## Interface handoff to Plans 03, 05 and 06

**Native binding:** schema version remains 1, with additive `workspace_root`, `context_delivery_ids`, `bound_at` and `observations`. Existing `workspace` remains for compatibility. Retained fields are `launch_state`, `host_session_id`, `child_id`, `dispatch_sha256`, `prompt_sha256`, resolved `permission_profile`, exact `prompt`, `release`, terminal `source_event_id/source_event_sha256` and `raw_result`. Existing worker `Result` and `ResultSHA256` remain the canonical terminal authority.

**States:** launch_state is reserved, bound, launch_unresolved, terminal or no_launch. Worker status stays dispatching for nonterminal observations. `codexNativeWorkerIsTerminal` requires terminal/no_launch plus a saved result and digest. `buildWorkerRunStillActive` means native termination is unconfirmed; it does not assert actual host activity.

**Observe wire:** use the registered hidden `codex-native-worker observe --request <file>` route with full execution binding, worker/task/launch/session/dispatch/prompt identities, exact bound child, `observation_status`, actual RFC3339Nano `observed_at`, optional `observation_detail`, and source event ID/SHA-256. Statuses: running, cancel_requested, cancelled, unavailable, launch_unresolved, no_launch. An unbound child may be omitted only for unresolved/unavailable/no_launch observations. Cancelled can carry an exact cancelled Result; without one, Go saves a minimal host-confirmed cancellation with no work claims. no_launch rejects a supplied result or bound child.

**Observe persistence:** each versioned history entry carries status/child/time/detail/source ID/hash. Terminal source fields remain separate from nonterminal observations. `projectCodexNativeWorkerState` supplies read-only inspect states including host_status, terminal, cancel_requested and result digest. Later events cannot resurrect a terminal. Cancellation intent stays visible across unavailable-host observations.

**Receipts/replay:** response disposition is accepted/replay. `codexNativeWorkerReceipt` identifies the operation, launch/child, original time, dispatch/prompt digests and applicable terminal event/result digests. `recordCodexNativeTerminal` is the narrow validated terminal helper used inside the native attempt mutation; `normalizedBuildWorkerResult` copies before normalization/hashing. `latestTerminalBuildWorkerRun` now recognizes native cancelled outcomes. Plan 05 owns final cancellation-to-completion vocabulary mapping; only the terminal semantic preview maps cancelled to interrupted here.

**Progress:** reserve emits no started line. First accepted bind calls `emitCodexDispatchWorkerStarted`; accepted running observation calls `emitCodexDispatchWorkerRunning`; accepted terminal record or terminal observation calls `emitCodexDispatchWorkerFinished`. These happen after persistence, never on replay. No usage/tool measurements are fabricated. Instance-local hooks `BeforeWrite`, `AfterCurrencyCheck`, and `AfterTransition` support bounded tests without global bridge callbacks.
