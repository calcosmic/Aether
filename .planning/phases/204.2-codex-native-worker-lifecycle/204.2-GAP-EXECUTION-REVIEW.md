## Critical Issues

### CR-01: Untracked build inputs escape the frozen regression candidate

**Classification:** BLOCKER

**File:** `/Users/callumcowie/repos/Aether/scripts/qualify-native-gap-regression.py:102-110`

**Issue:** `inventory()` enumerates only tracked files. `prepare()` records untracked status at line 182 but never rejects it, and copies only the committed checkout plus `git diff --binary HEAD` into the lanes (lines 187–189 and 229–235). Consequently an untracked `cmd/new_feature.go` or `cmd/new_feature_test.go` in the submitted source is omitted from both prepared clones while all inventory comparisons still pass. Adding an untracked implementation file to a prepared lane after preparation also leaves `validate()`'s inventory comparison unchanged, although Go will compile it. The script can therefore run a different candidate from the one it claims to freeze. This is distinct from the deliberately unrelated `.gsd/` directory.

**Fix:** Define the complete build-input inventory, including nonignored untracked source, tests and relevant embedded assets, and use it in preparation and every later validation. Either copy those files into both clones with recorded hashes or reject their presence before preparation. Explicitly allow unrelated non-build metadata rather than excluding all untracked paths. Add controls for an untracked production file and an untracked test before preparation, and an untracked file introduced into a lane afterward; each must be preserved and pinned or rejected before any suite launches.

### CR-02: Arbitrary artifacts satisfy the required host tool-schema proof

**Classification:** BLOCKER

**File:** `/Users/callumcowie/repos/Aether/cmd/codex_native_gap_evidence_test.go:113-125`

**Issue:** `nativeGapHostIdentity()` checks only that `Configuration` and `ToolSchema` point to hash-matching files in the original artifact map. It never inspects their contents or establishes that they are a configuration capture and full tool definitions. `nativeEvidenceBytes()` also accepts an empty file. Pointing both references at an already captured empty stderr file, a prompt, or a list of observed tool names satisfies this new provenance predicate. No original artifact needs to be rewritten. The positive control at lines 249–258 explicitly uses the same arbitrary `synthetic host evidence` bytes as executable, schema and configuration and expects acceptance. Thus the gate does not enforce its stated distinction between unavailable full schema and a substitute artifact.

**Fix:** Validate a source-owned, versioned capture envelope for the configuration and tool schema, including actual invocation identity, export provenance and nonempty tool definitions with parameter schemas. Reject empty files, unrelated artifacts, tool-name-only lists and explicit unavailable-export records. Cross-check the configuration's measured model/effort/argv against the receipt. Keep an unavailable supported export as a qualification gap instead of accepting an arbitrary hashed file. Positive controls should use minimally valid captures; add the above substitution controls.

### CR-03: Corrupt child records can disappear from cancellation's no-write proof

**Classification:** BLOCKER

**File:** `/Users/callumcowie/repos/Aether/cmd/codex_native_gap_controls_test.go:123-143`

**Issue:** The cancellation checker silently skips every child-log line that fails JSON decoding. After one valid post-acknowledgement event sets `observedAfter`, a malformed or truncated subsequent command/file-change record is ignored and `NoPostAckWrites` remains true. A direct counterexample is the existing passing cancellation fixture followed by a truncated JSON `FileChange` record: the new bytes do not set `unknownTime` or `PostAckActivity`, so the same cancellation predicates still qualify. An original capture can contain a truncated final line after interruption; hashing those bytes establishes integrity, not completeness. `nativeValidateInterruptedHostScenario()` consumes this result without requiring the child log to parse completely.

**Fix:** Reject any nonblank malformed record in the relevant child capture and mark unknown or unattributable activity as unproved instead of dropping it. Require an explicit, validated end of the observed cancellation interval. Add negative controls for a truncated final record, malformed activity between valid records, and incomplete/unrecognized activity after acknowledgement; all must leave `Qualified` false.

## Warnings

### WR-01: Recovery replay validates spawn identity but not the retained cut point

**Classification:** WARNING

**File:** `/Users/callumcowie/repos/Aether/cmd/codex_native_gap_recovery_test.go:48-96`

**Issue:** `nativeGapCheckpointRetained()` verifies the hashes of at least four arbitrary files, then re-derives only the spawn identity. It does not require or parse the retained attempt/state snapshots, verify their attempt/run/launch binding, or re-establish the scenario's terminal-before-stage / spawn-before-bind predicate. Its positive test at lines 429–436 accepts literal `proof` as `attempt.json`, has no state snapshot, and still passes. The live controller checks the boundary separately, so this is a replay robustness gap rather than evidence that the current capture used the wrong boundary. However, replay currently cannot detect a correctly hashed but semantically wrong checkpoint, despite using this predicate to accept a killed parent's exit.

**Fix:** Require the exact checkpoint artifact set and decode the saved attempt and state. Re-derive the scenario-specific boundary from those snapshots and the captured host events, including absence of aggregate/credit, required terminal or absent binding, and consistency with the saved source and worker identity. Replace the junk positive fixture with a valid minimal checkpoint and add wrong-state, wrong-attempt, already-finalized and missing-snapshot controls.
