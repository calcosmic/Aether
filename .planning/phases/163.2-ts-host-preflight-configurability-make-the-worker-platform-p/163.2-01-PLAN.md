      `available`, `category` (omitempty), `checked_at` (RFC3339 string).
    - `preflightCacheFile` with JSON fields `schema_version` (int) and
      `entries` (map keyed by platform string -> preflightCacheEntry). A map,
      not a single entry: switching AETHER_WORKER_PLATFORM back and forth must
      not destroy the other platform's window, and a lookup for platform X must
      never see platform Y's entry (D-03 "keyed per platform").

    a miss / nil error, never panic, never dereference a nil store; several
    existing cmd tests construct dispatch flows without initialising a store):
    - `resolvedPreflightCacheTTL() time.Duration` — copy the exact shape of
      `resolvedPreflightTimeout`: trim the env value; empty -> default;
      `time.ParseDuration` error or non-positive -> default. Never errors.
    - `preflightSkipRequested() bool` — reads AETHER_SKIP_PREFLIGHT, trims and
      lowercases; true only for "1", "true", "yes", "on". Anything else,
      including "0", "false", "banana" and empty, is false.
    - `preflightCacheEntryIsFresh(entry preflightCacheEntry, now time.Time, ttl time.Duration) bool`
      — false when `checked_at` is empty or unparseable, false when the
      timestamp is more than one minute in the future (clock-skew guard copied
      from `sealFinalReviewIsFresh`), false when `!entry.Available` (only
      successes are ever trusted), otherwise `now.Sub(parsed) <= ttl`.
    - `loadFreshPreflightCache(platform codex.Platform, now time.Time) (preflightCacheEntry, time.Duration, bool)`
      — LoadJSON into `preflightCacheFile`; any read/unmarshal error is a miss
      (not a failure); a `schema_version` other than
      `preflightCacheSchemaVersion` is a miss; look up the entry under the
      normalised platform string; require `entry.Platform` to equal the
      requested platform; require freshness. On a hit return the entry and the
      remaining window (ttl minus elapsed, floored at zero).
    - `recordPreflightSuccess(status codex.AvailabilityStatus, now time.Time) error`
      — no-op returning nil when `!status.Available` or the platform is empty
      or `codex.PlatformUnknown`; otherwise load-merge-save so other platforms'
      entries survive, stamping `checked_at` with `now.UTC().Format(time.RFC3339)`
      and `schema_version`.
    - `clearPreflightCache(platform codex.Platform) error` — delete just that
      platform's entry and save; a missing file or missing entry is success,
      not an error. Used by D-03 in plan 05.
    - `emitPreflightSkipNotice(w io.Writer)` — writes exactly one line, styled
      after `warnTsHostBuildSkipped` in cmd/publish_cmd.go:191:
      "Warning: preflight skipped via AETHER_SKIP_PREFLIGHT — provider auth and model config were NOT verified before dispatch"
      followed by a newline. This is D-06's never-silent requirement.
    - `emitPreflightCacheHitNotice(w io.Writer, platform codex.Platform, remaining time.Duration)`
      — writes one line of the form
      "preflight: cached OK for <platform>, <N>m left in trust window"
      where <N> is the remaining window rounded down to whole minutes (use 0m
      rather than a negative value).

    add any model-selection logic. Do not hand-create
    `.aether/data/preflight-cache.json` in the repo — it is a protected runtime
    path written only by the running binary.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem -> runtime | `.aether/data/preflight-cache.json` is read back as an authorisation-ish fact ("auth was verified recently"). Anything able to write the repo data dir can assert it. |
| environment -> runtime | `AETHER_PREFLIGHT_CACHE_TTL` and `AETHER_SKIP_PREFLIGHT` are attacker-influenceable in a hostile CI. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-163.2-01 | Spoofing | preflight-cache.json | mitigate | Only `available:true` entries are honoured, the entry's own `platform` must equal the requested platform, `schema_version` must match, and freshness is TTL-bounded — a forged entry expires and cannot grant a permanent bypass. |
| T-163.2-02 | Tampering | preflight-cache.json (future timestamp) | mitigate | Timestamps more than one minute ahead of now are rejected outright, so a far-future `checked_at` cannot create an unbounded trust window. |
| T-163.2-03 | Elevation of privilege | AETHER_PREFLIGHT_CACHE_TTL | mitigate | Value is parsed with `time.ParseDuration` only — never shelled out, never used in a path. Non-positive and unparseable values fall back to the 1h default rather than to "infinite". |
| T-163.2-04 | Repudiation | AETHER_SKIP_PREFLIGHT | mitigate | The skip switch is never silent: `emitPreflightSkipNotice` states that auth was NOT verified, and Task 2 asserts the wording, so a bypass always leaves a visible trace in command output. |
| T-163.2-05 | Tampering | cache file path handling | accept | The path is a compiled constant resolved through the existing store (no user-supplied path segment), so traversal is not reachable; the repo data dir shares the developer's own trust domain, as COLONY_STATE.json already does. |
| T-163.2-06 | Information disclosure | cached entry contents | mitigate | Only platform, binary name, availability, category and a timestamp are persisted — no credentials, tokens or provider output are written to the cache file. |
</threat_model>
