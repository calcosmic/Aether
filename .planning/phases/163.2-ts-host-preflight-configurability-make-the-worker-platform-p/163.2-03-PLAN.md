runtime: one shared `AETHER_PREFLIGHT_TIMEOUT` knob (no new `_MS` variable), a
45s default matching Go, a neutral temp working directory for the probe, and a
never-silent skip switch. Rebuild `dist/` so downstream repos actually receive
the change.

budget that killed the 27 July M4L `/ant-plan` run, and the folded todo is
explicit that a Go-only fix never reaches downstream repos.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| TS host -> provider CLI subprocess | The compat-path probe spawns a provider binary; its cwd decides which repo config that binary loads. |
| Go adapter -> TS host | `preflight.notice` crosses the JSON boundary and is written to the user's terminal. |
| environment -> TS host | `AETHER_PREFLIGHT_TIMEOUT` and `AETHER_SKIP_PREFLIGHT` are read from the process environment. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-163.2-12 | Elevation of privilege | TS probe working directory | mitigate | The probe runs in a fresh `mkdtempSync` directory rather than the target repo, so a hostile repo's provider config, hooks and MCP servers are not loaded during a liveness check. |
| T-163.2-13 | Repudiation | AETHER_SKIP_PREFLIGHT | mitigate | The skip path always writes its notice to stderr before returning, and Task 3 asserts the exact wording, so a bypass cannot be silent on either host. |
| T-163.2-14 | Spoofing | `preflight.notice` from the Go adapter | mitigate | The notice is produced by the Go runtime the host already trusts as the execution owner, is written to stderr only (never interpreted as a command or a status), and an absent/empty field simply prints nothing. |
| T-163.2-15 | Denial of service | AETHER_PREFLIGHT_TIMEOUT parsing | mitigate | Only a positive decimal with a ms/s/m unit is accepted; every other value falls back to 45000 ms, so no env value can produce an infinite or zero-length probe budget. |
| T-163.2-16 | Information disclosure | probe failure text | mitigate | `sanitizeDiagnostic` on the probe failure path is left untouched, and the existing secret-leak assertions in platform-dispatcher.test.ts continue to run. |
| T-163.2-17 | Tampering | temp directory cleanup | mitigate | The probe directory is removed in a `finally` block with `rmSync(..., { recursive: true, force: true })`, so probe scratch state does not accumulate in the system temp dir. |
| T-163.2-19 | Denial of service | TS temp-dir creation failure | mitigate | A `mkdtempSync` throw is caught and degrades to the passed `cwd` instead of failing the preflight, so an exhausted or read-only `TMPDIR` cannot block dispatch; Task 3 test 5 forces the throw through `__setMakePreflightTempDir` and asserts the probe still completes. |
</threat_model>
