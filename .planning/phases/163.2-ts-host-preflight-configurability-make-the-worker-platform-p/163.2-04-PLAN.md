<objective>
Wire the plan 01 cost-policy layer into the two places the provider probe is
actually invoked, so the paid round-trip stops running on every dispatch.

dispatch batch on the direct-Go path, and the `--preflight` branch of
`cmd/internal_worker_adapter.go:137` runs once per TS-hosted dispatch. Both must
consult ONE cache, or a `/ant-build` through the TS host and a direct-Go
dispatch would each keep their own trust window and the cost would only half
disappear.
Output: one shared gate, both chokepoints on it, and an outcome the TS host can
print.
</objective>

    `func gatedProviderPreflight(ctx context.Context, preflighter codex.WorkerProviderPreflighter, platform codex.Platform, root string, now time.Time) (codex.AvailabilityStatus, preflightOutcome)`

    plus the outcome type used by both the CLI notice and the JSON response:

    `type preflightOutcome struct { Source string `json:"source"`; Notice string `json:"notice,omitempty"` }`
    with source constants `preflightSourceProbe = "probe"`,
    `preflightSourceCache = "cache"`, `preflightSourceSkipped = "skipped"`.

    Decision order (a skip must short-circuit everything, including the cache
    read):
    1. `preflightSkipRequested()` -> return an Available status with
       `Category: codex.AvailabilityCategoryProbeSkipped`, a Reason naming
       AETHER_SKIP_PREFLIGHT, the given platform and outcome
       `{Source: skipped, Notice: <the exact skip notice line from plan 01>}`.
       Do not touch the cache: skipping must not write a trust window.
    2. If the platform is empty or `codex.PlatformUnknown`, bypass the cache
       entirely and go straight to the probe (source "probe", no notice) —
       an unkeyable platform must never share another platform's window, and
       several existing tests drive fake invokers with no real platform.
    3. `loadFreshPreflightCache(platform, now)` hit -> return an Available
       status rebuilt from the entry (platform, binary, Available true,
       `Category: codex.AvailabilityCategoryAvailable`) and outcome
       `{Source: cache, Notice: <the cache-hit line from plan 01>}`. No probe
       is invoked — assert this with a probe counter in Task 3.
    4. Otherwise call `preflighter.Preflight(ctx, root)`. On success call
       `recordPreflightSuccess(status, now)` and ignore a write error beyond a
       best-effort path (a cache write failure must not fail dispatch). On
       failure do NOT write the cache and do NOT clear an existing entry here —
       return the failing status with source "probe".

    Have the gate build its notice strings via the plan 01 emit helpers (refactor
    them into `preflightSkipNoticeLine() string` /
    `preflightCacheHitNoticeLine(platform, remaining) string` returning the text,
    with the emit functions writing those lines) so the CLI notice and the JSON
    `notice` field are the same bytes and cannot drift.

    A nil `preflighter` returns the zero status with source "probe" and no
    notice; callers already guard for this.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cache file -> dispatch gate | A cache hit substitutes for a live auth check before expensive workers are spawned. |
| Go adapter -> TS host (JSON) | The `preflight` outcome field crosses the adapter boundary into host output. |
| environment -> gate | `AETHER_SKIP_PREFLIGHT` can bypass the probe entirely. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-163.2-18 | Spoofing | cache hit substituting for auth | mitigate | Only `available:true`, schema-matched, platform-matched, TTL-fresh entries are honoured (plan 01), failures are never written, and an unknown platform bypasses the cache entirely — so the longest possible unearned trust window is one TTL. |
| T-163.2-19 | Repudiation | silent bypass | mitigate | Both the cache path and the skip path emit a notice (stderr on the direct-Go path, `preflight.notice` on the adapter path), asserted by Tasks 3.2 and 3.5. |
| T-163.2-20 | Elevation of privilege | AETHER_SKIP_PREFLIGHT ordering | mitigate | The skip branch runs before the cache read and never writes an entry, so a one-off skip in CI cannot leave a persistent trust window behind for later commands. |
| T-163.2-21 | Tampering | adapter JSON contract | mitigate | The `preflight` field is additive and omitted when empty; `internalWorkerAdapterSchemaVersion` stays 1 and the TS host's `schema_version === 1` guard is asserted intact, so a malformed or absent field degrades to today's behaviour. |
| T-163.2-22 | Denial of service | cache write failure | mitigate | A `SaveJSON` error is best-effort only: the probe result is still returned and dispatch proceeds, so a read-only or full data dir cannot block builds. |
| T-163.2-23 | Information disclosure | notice contents | mitigate | Notices carry only the platform name and remaining minutes — no provider output, credentials or diagnostics are placed in the cached entry or the notice. |
</threat_model>
