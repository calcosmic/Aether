# Phase 163.2: ts-host preflight configurability - Context

**Gathered:** 2026-08-01
**Status:** Ready for planning

<domain>
## Phase Boundary

Before spawning expensive workers, the runtime runs a provider preflight — a
real model round-trip ("Return exactly OK.") that proves auth AND model config
work. Today that probe runs on every build/plan/continue dispatch (~$0.59 per
dispatch attributable to preflight in the M4L colony), the TypeScript host
hardcodes its timeout at 20s (`platform-dispatcher.ts:155`) while the Go side
already honors `AETHER_PREFLIGHT_TIMEOUT` with a 45s default (commit 4d9dae9a),
and the probe runs in the repo working directory where repo config can slow or
break it. This phase: make the timeout configurable everywhere the probe
exists, cache preflight success so the paid probe stops running per-dispatch,
add a loud skip switch, and isolate the probe's working directory. Sourced from
the 2026-07-31 M4L residual diagnosis item P1 (folded todo below) plus the
163.1 deferred cwd-isolation item.

</domain>

<decisions>
## Implementation Decisions

### Re-check frequency (caching)
- **D-01: Time-based success cache in a state file.** Preflight success is
  recorded per-platform in a small runtime-owned state file (each CLI command
  is a fresh process, so in-memory caching cannot work). While the entry is
  fresh, dispatch skips the paid probe entirely — no cost, no wait. This is
  the primary fix for the per-dispatch cost.
- **D-02: TTL default is Claude's discretion (exercised: 1 hour), tunable.**
  Default trust window 1 hour; overridable via env var (naming at Claude's
  discretion, e.g. `AETHER_PREFLIGHT_CACHE_TTL`, same Go-duration syntax as
  D-05). Invalid values fall back to the default — a broken env var must not
  brick dispatch (matches `resolvedPreflightTimeout` behavior).
- **D-03: Auto-invalidation on provider failure.** A worker dispatch that
  later fails with a provider/auth-classified error clears the cached entry so
  the next command re-probes. Cache is keyed per platform; switching
  `AETHER_WORKER_PLATFORM` never reuses another platform's entry.

### Probe design
- **D-04: The probe stays a real model round-trip.** No cheap non-AI
  replacement, no two-tier scheme. "Return exactly OK." is the only check that
  proves auth and model config actually work; with D-01 its cost drops to
  roughly once per TTL window, which the user accepted. Do NOT change the
  probe's model or add model auto-selection (standing user rule: no automatic
  model selection, ever).

### Control knobs
- **D-05: One shared timeout var, both hosts.** The TS host honors the same
  `AETHER_PREFLIGHT_TIMEOUT` (Go-duration syntax, e.g. "90s") the Go side
  shipped in commit 4d9dae9a — NOT a new `_MS` variable. The TS host's
  hardcoded 20_000 is replaced and its default aligns to the Go side's 45s.
  One knob, documented once, works everywhere.
- **D-06: Skip switch with a loud notice.** An env switch (e.g.
  `AETHER_SKIP_PREFLIGHT=1`) skips the probe entirely for trusted setups/CI,
  printing one clear line that the check was skipped. Never silent — per
  Phase 160 fail-loudly (gates halt, enrichment warns; a deliberately skipped
  gate announces itself).

### Probe working directory
- **D-07: Probe runs in a neutral temp directory, not the repo.** Applies to
  both the Go probe (`runHostedProviderPreflight` sets `cmd.Dir = root` today)
  and the TS probe path. The probe tests "is the provider alive and
  configured"; repo-specific config (e.g. MCP servers the probe doesn't need)
  only adds delay and false failures. This closes the 163.1 deferred item
  ("preflight cwd isolation … fold into any nearby phase touching
  platform_dispatch.go").

### Claude's Discretion
- Exact TTL default env-var name and the cache file's location, name, and
  schema (runtime-owned state; follow existing `.aether/data/` conventions).
- How a "provider/auth-classified" worker failure is detected for D-03
  (existing `AvailabilityCategory` values are the natural vocabulary).
- Whether the TS host reads `AETHER_PREFLIGHT_TIMEOUT` itself or receives the
  resolved value across the Go adapter boundary — but the hardcoded 20_000 in
  `platform-dispatcher.ts` must be gone either way, since the compat/test-hook
  path still exercises it.
- Skip-switch exact name and notice wording.
- Whether cache-skip emits a quiet one-liner ("preflight: cached OK, 43m
  left") or is silent; lean toward the one-liner for honesty.

### Folded Todos
- **ts-host preflight timeout hardcoded, not configurable, runs in repo cwd**
  (`.planning/todos/pending/2026-08-01-ts-host-preflight-hardcoded-timeout.md`)
  — this IS the phase: hardcoded 20s at `platform-dispatcher.ts:155`, no TS
  config surface, repo-cwd probe, ~$0.59/dispatch cost. All three complaints
  map to D-05, D-07, and D-01 respectively. Its reminder is binding: ts-host
  changes need a dist rebuild and publish to reach downstream repos (fixes
  need both Go AND ts-host paths).

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `resolvedPreflightTimeout` (pkg/codex/platform_dispatch.go:752-767): the
  exact env-var-with-safe-fallback pattern to copy for the TTL knob and to
  mirror in TS
- `AvailabilityStatus.Category` (AvailabilityCategoryAuthProbeFailed,
  AvailabilityCategoryProviderConfig): existing failure vocabulary for D-03's
  invalidation trigger
- Existing runtime state files under `.aether/data/` (COLONY_STATE.json,
  handoffs/): conventions for the cache file's home; `pkg/storage` has JSON
  store + file locking

### Established Patterns
- Runtime owns truth, wrappers own presentation — the cache and skip logic
  live in Go; the TS host mirrors config, never invents its own policy
- Definition of Done: every decision needs a command/test that fails when the
  requirement is unmet (e.g. a test that fails if the TS bundle still contains
  a hardcoded preflight timeout; TTL/skip/invalidation each get invariant
  tests)
- M4L dispatch postmortem (memory): worker-dispatch fixes need both the Go
  AND ts-host paths, plus a dist rebuild — a Go-only fix silently never
  reaches downstream repos

### Integration Points
- Production preflight flows TS host → `internal-worker-adapter --preflight`
  → `provider.Preflight` — the cache check belongs where `Preflight` is
  invoked so both direct Go dispatch and TS-hosted dispatch benefit
- `preflightWorkerProvider` (cmd/dispatch_runtime.go) is the single Go-side
  chokepoint per dispatch batch

</code_context>

<specifics>
## Specific Ideas

- The acceptance story: a second `/ant-build` within the trust window pays
  zero preflight cost and starts visibly faster; a lapsed login still fails
  loudly before workers spawn once the window expires or a failure clears the
  cache.
- The M4L colony's ~$0.59-per-dispatch preflight line item should effectively
  disappear from steady-state usage.

</specifics>
