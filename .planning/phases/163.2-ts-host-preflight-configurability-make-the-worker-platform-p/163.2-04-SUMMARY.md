# Phase 163.2 Plan 04: Wire the Preflight Cache Into Both Dispatch Chokepoints Summary

**`gatedProviderPreflight` in `cmd/preflight_cache.go` now sits between the plan-01 cache layer and both dispatch chokepoints (`cmd/dispatch_runtime.go` and `cmd/internal_worker_adapter.go`), so a second dispatch inside the trust window pays zero provider probes on either the direct-Go or TS-hosted path -- proven by 8 invariant tests including two manually-confirmed mutation kills.**

## Accomplishments
- Built `gatedProviderPreflight`, the single decision function that both `preflightWorkerProvider` (direct-Go dispatch) and the `internal-worker-adapter --preflight` branch (TS-hosted dispatch) now call, so the two paths share one trust window instead of two.
- Refactored the plan-01 notice emitters into `preflightSkipNoticeLine`/`preflightCacheHitNoticeLine` text-builder functions, so the CLI stderr notice and the JSON `preflight.notice` field are always the exact same bytes.
- Added `Preflight *preflightOutcome \`json:"preflight,omitempty"\`` to `internalWorkerAdapterResponse` -- additive, no schema bump -- populated only when there's an actual source+notice to report, so the ordinary probe-success path emits byte-identical JSON to before this plan.
- Wrote 8 invariant tests (`cmd/preflight_gate_test.go`) covering cold-cache probing, warm-cache skip-the-probe (the direct cost-regression canary), per-platform window isolation, never-caching a failure, the skip switch beating an available cache hit, expired-window re-probing, the adapter's JSON outcome shape on both the skip and ordinary paths, and cross-chokepoint cache sharing in both directions.
- Manually ran and confirmed 3 mutation kills against the acceptance criteria's specified mutations (removing the cache-hit branch, caching a failed status, reordering the skip check after the cache read), then restored the clean file and re-verified green -- the third mutation required strengthening the test beyond its literal cold-cache-only spec (see Deviations).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug in own new test] Strengthened `TestGatedPreflightSkipSwitchBypassesProbeAndCache` to actually exercise skip-before-cache ordering**
- **Found during:** Task 3, while manually running the plan's specified mutation checks
- **Issue:** The test as first written (matching the plan's literal one-line description) called the gate with a cold cache and the skip switch set. Manually reordering the skip check to run *after* the cache read in `gatedProviderPreflight` did not make this test fail, because with a cold cache both orderings produce the same "skipped, probe never ran" outcome -- the test could not distinguish correct behavior from the specific regression the plan's mutation-check bullet says it must catch.
- **Fix:** Rewrote the test to first warm the cache via a real `preflightWorkerProvider` call, confirm the entry is fresh, *then* set the skip switch and assert the skip notice still wins over the available cache hit (probe count stays at 1, stderr still says `AETHER_SKIP_PREFLIGHT`/`NOT verified`, and the pre-existing cache entry's `CheckedAt` is unchanged). Re-ran the reordering mutation against the strengthened test and confirmed it now fails as required, then restored the clean implementation.
- **Files modified:** cmd/preflight_gate_test.go (test-only change, no production code affected)
- **Verification:** `go test ./cmd/ -run TestGatedPreflightSkipSwitchBypassesProbeAndCache -v` passes on the clean implementation; manually reintroducing the reordering mutation makes it fail with `skip stderr = "preflight: cached OK..." want it to contain "AETHER_SKIP_PREFLIGHT"`; file restored byte-identical to the Task 2 commit before this test commit.
