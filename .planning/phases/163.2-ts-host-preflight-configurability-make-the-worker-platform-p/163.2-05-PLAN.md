<objective>
Close the loop: a provider/auth failure after a cached preflight must invalidate
the trust window, and every knob this phase introduced must be documented once
and kept in sync across both hosts by a test.

Purpose: D-03 — without invalidation, a login that lapses mid-window leaves the
colony trusting a stale success for up to an hour. D-05 — "one knob, documented
once, works everywhere" is only true if something fails when it stops being
true.
Output: invalidation wiring, one documentation surface, and the parity test that
guards both.
</objective>

       worker-execution path: when the adapter is about to return a worker
       error that satisfies `providerAuthFailure`, clear the cache entry for the
       adapter's `platform` first, so the TS-hosted path invalidates too.
    5. Do not clear the cache for ordinary worker failures (timeout, blocked,
       non-zero exit with a task-level message) — a broken task must not cost
       the next command a paid probe.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dispatch failure text -> cache invalidation | Error strings from provider subprocesses decide whether a trust window is destroyed. |
| documentation -> operator behaviour | The doc tells operators how to disable an auth gate. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-163.2-24 | Spoofing | stale trust window after credentials lapse | mitigate | Provider/auth-classified dispatch failures clear the platform's entry on both chokepoints, so a lapsed login is re-detected on the next command instead of at TTL expiry. |
| T-163.2-25 | Tampering | attacker-influenced error text forcing invalidation | accept | The worst outcome of a forced clear is one extra paid probe; the classifier deliberately errs toward clearing, and only error values (never worker summaries or raw output) are inspected, so a worker cannot invalidate by writing about auth in its report. |
| T-163.2-26 | Denial of service | over-eager invalidation | mitigate | Ordinary failures (timeout, blocked, non-zero exit, test failures) are asserted NOT to clear the window, so a flaky task cannot restore per-dispatch probe cost. |
| T-163.2-27 | Repudiation | undocumented bypass switch | mitigate | `TestEveryPreflightEnvKnobIsDocumented` fails if any `AETHER_PREFLIGHT_*`/`AETHER_SKIP_PREFLIGHT` knob exists without a documented entry, so no silent bypass can ship. |
| T-163.2-28 | Tampering | host drift reintroducing a short/hardcoded budget | mitigate | `TestHostsAgreeOnPreflightDefaultBudget` and `TestNoHardcodedPreflightBudgetRemains` fail on divergence or on the return of the 20s literal in source or dist. |
</threat_model>
