<objective>
Make every Go-side provider probe share one execution path: one env-configurable
timeout (`AETHER_PREFLIGHT_TIMEOUT`), one retry policy, and a neutral temp
working directory instead of the repo root.

Purpose: D-07 — the probe answers "is the provider alive and configured", so
running it inside the target repo only adds that repo's config startup cost and
false failures. D-05 — the Codex probe in `RealInvoker.Preflight` still has its
own hardcoded `20*time.Second` and its own inline `exec.Command`, so the 45s
default and the retry shipped in 4d9dae9a never applied to it.
Output: one shared probe runner, used by all three Go providers, with invariant
tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| runtime -> provider subprocess | The probe spawns a provider CLI; its working directory determines which repo config, MCP servers, hooks and plugins that CLI loads. |
| environment -> runtime | `AETHER_PREFLIGHT_TIMEOUT` and `AETHER_CODEX_PATH` influence probe execution. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-163.2-07 | Elevation of privilege | probe working directory | mitigate | Moving `cmd.Dir` to a fresh `os.MkdirTemp` directory stops the probe from loading the target repo's MCP servers, hooks and plugins, shrinking what a hostile repo can execute during a liveness check. |
| T-163.2-08 | Information disclosure | temp probe directory | mitigate | The directory is created by `os.MkdirTemp` (0700, unpredictable name) and removed with `defer os.RemoveAll` after each attempt; nothing but the provider's own scratch output ever lands in it. |
| T-163.2-09 | Denial of service | AETHER_PREFLIGHT_TIMEOUT | mitigate | Parsed only through `time.ParseDuration` with non-positive and unparseable values falling back to the 45s compiled default; the timeout remains bounded by `hostedPreflightAttempts`, so no env value can create an unbounded hang. |
| T-163.2-10 | Information disclosure | probe failure diagnostics | mitigate | The unified path keeps `sanitizeWorkerDiagnosticOutput` on all probe output, so the Codex probe's failure text is redacted by the same rule as the other providers instead of its former bespoke handling. |
| T-163.2-11 | Tampering | AETHER_CODEX_PATH stand-in binary | accept | Already-existing behaviour used for testability; an attacker able to set this env var can already run arbitrary code as the user. |
</threat_model>
