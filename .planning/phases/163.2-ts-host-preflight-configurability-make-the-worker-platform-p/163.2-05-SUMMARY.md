## Accomplishments
- Built `providerAuthFailure` (classifies a dispatch error as provider/auth-related via the five relevant `AvailabilityCategory` values or a regex byte-identical in vocabulary to the TS host's `isAuthError`) and `invalidatePreflightCacheOnProviderFailure` (clears the platform's cached trust window when any dispatch result matches).
- Wired the invalidation check into both dispatch chokepoints: `dispatchBatchByWaveWithVisuals` (direct-Go dispatch, after all waves complete) and the `internal-worker-adapter --preflight` worker-execution path (TS-hosted dispatch), so a lapsed login is caught on the very next command instead of surviving up to the full TTL window.
- Wrote 5 invariant tests (`cmd/preflight_invalidation_test.go`) covering classification (5 categories + 6 auth message strings + 4 ordinary-failure false-cases + nil), that an auth failure clears the window while an ordinary failure does not, per-platform isolation, and nil-store safety.
- Wrote `.aether/docs/preflight-configuration.md`, the single documented surface for `AETHER_PREFLIGHT_TIMEOUT`, `AETHER_PREFLIGHT_CACHE_TTL`, and `AETHER_SKIP_PREFLIGHT` — what each does, its default, and its fallback-on-malformed-value behavior — plus the cache file location and what a user sees.
- Wrote 4 parity/coverage tests (`cmd/preflight_docs_test.go`): every knob found in source must appear in the doc, the Go and TS default timeout budgets must agree in milliseconds, the folded todo's stale 20s literal must never reappear in either host's source or dist bundle, and the skip-notice wording must be byte-identical across hosts.

## Decisions Made
- Placed the D-03 invalidation call in `dispatchBatchByWaveWithVisuals` after dispatch, not before — this is the reaction to a completed dispatch, matching the plan's explicit ordering requirement (it can't live inside `preflightWorkerProvider`, which runs before dispatch even starts).
- Used `errors.As` against `*workerProviderPreflightError` for the category-based check, then fell through to the regex check on `err.Error()` regardless of match — so a `workerProviderPreflightError` with a non-auth category (e.g. `binary_missing`) still gets a chance to match the message vocabulary rather than being excluded outright.
- Kept the classifier's own doc comment worded around "self-reported report text" / "captured process output" / "task description" instead of the literal words "Summary"/"RawOutput", since the plan's own acceptance criterion (`grep -n "RawOutput\|Summary" cmd/preflight_cache.go` must return no match) would otherwise be tripped by the explanatory comment itself, not by any actual field access.
