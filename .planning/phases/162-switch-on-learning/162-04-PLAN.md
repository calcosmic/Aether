<objective>
Give `consolidation-seal` its first caller, make the eight ants visible, write the
report the scribe already produces, and stop the same instinct being promoted twice.

Purpose: LEARN-02 and LEARN-03. Two findings drive this plan's shape.

First, `pkg/agent/curation/scribe.go` builds a curation report string and returns
it in a `Summary` map with `"path": ""` — nothing ever writes it. LEARN-02 requires
"scribe report" as an artifact, so the runtime must persist it. Generating a report
into a discarded map is the same class of defect as a subcommand with no caller.

Second, `completeSealRuntime` already promotes instincts to QUEEN.md on its own
terms (confidence >= 0.8 and Action non-empty, into the `## Wisdom` section), while
`pipeline.RunConsolidation` promotes on different terms (confidence >= 0.75 AND at
least three recorded applications, into the `## Instincts` section). After plan 02
both write the same file. Adding a seal-side consolidation call without reconciling
them would double-write the same instinct under two headers.

Output: a non-blocking seal consolidation wrapper, eight named ant beats, a written
report artifact, and a deduplicated single-appearance promotion invariant.
</objective>
