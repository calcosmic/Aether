<objective>
Put the colony's memory pack on the two command lanes the owner actually runs: `/ant-plan` and `/ant-colonize` in Claude Code and OpenCode.

Today `codexPlanManifest` and `codexColonizeManifest` have no capsule field at all. The `ContextCapsule` set at `codex_plan.go:1478` and `codex_colonize.go:690` lives on the in-process `codex.WorkerDispatch` that `ShouldUseAgentDelegatePath()` routes every Claude/OpenCode session away from — so the planner and all four surveyors receive nothing. `codexBuildManifest` already does this correctly (`codex_build.go:160-169`, `:2392-2395`, `:2420`); this plan copies that exact shape twice.

Purpose: the planner and the surveyors are the two helpers that most need to know what the project already learned, and they are the two that currently get least.
Output: a capsule field on both manifests, both platform wrappers told to prepend it, and one delegate-lane table test that fails when any memory source stops arriving.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored memory -> worker prompt | Text written by earlier workers (relay notes, failure-log entries) and by the owner (steering notes, answers) is replayed verbatim into a new worker's instructions. |
| runtime -> wrapper -> spawned worker | The manifest crosses a process boundary into a platform wrapper that composes the actual prompt. |

| T-198.2-02 | Elevation of Privilege | wrapper prompt composition | medium | mitigate | Wrappers are instructed to pass the capsule through verbatim and are explicitly forbidden from assembling or editing memory; the runtime stays the only assembler. |
| T-198.2-03 | Information Disclosure | capsule on a memory-free colony | low | accept | `omitempty` keeps the field absent rather than emitting an empty structure; no secret material is newly exposed because the same payload already ships on the build manifest. |
</threat_model>
