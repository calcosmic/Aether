# Phase 198.2 Plan 01: Memory Capsule on the Plan and Colonize Manifests Summary

**`codexPlanManifest` and `codexColonizeManifest` now carry a `context_capsule` field populated once from the existing colony-prime assembler, and all three copies of each wrapper (plus both YAML sources) are told to prepend it verbatim — closing the gap where the Claude/OpenCode chat lane sent the planner and all four surveyors nothing.**

## Performance

- **Duration:** ~50 min
- **Completed:** 2026-08-30T14:27Z
- **Tasks:** 3
- **Files modified:** 12 (1 created, 11 modified)

## Accomplishments

- `codexPlanManifest.ContextCapsule` (json `context_capsule,omitempty`) added and populated at exactly one call site in `runCodexPlanPlanOnly`, the only function that builds this manifest — reached by both the explicit `--plan-only` flag and the agent-delegate route (`runCodexPlanAgentDelegate`).
- `codexColonizeManifest.ContextCapsule` added the same way; `buildCodexColonizeManifest` takes the capsule as a parameter rather than computing it itself, so the builder stays a pure assembler and there is still exactly one call site (in its sole caller, `runCodexColonizePlanOnly`).
- All three hand-maintained copies of `/ant-plan` (nested Claude, flat `.claude/commands/ant-plan.md` mirror, OpenCode) and all three copies of `/ant-colonize` — plus `.aether/commands/plan.yaml` and `.aether/commands/colonize.yaml` — now instruct the spawner to read the manifest capsule once and prepend it verbatim ahead of the brief, in wording mirrored from `build.md`'s own instruction.
- One new test file (`cmd/wire_capsule_198_2_test.go`) proves, on the real delegate/plan-only lane (never only the in-process dispatch): each of the seven memory sources reaches both commands (14 subtests), the delegate lane and the in-process lane deliver byte-identical capsules (D-03), the steering-notes and relay-note headings never render twice, capsules are stable across repeated runs, and all three wrapper copies per command stay byte-identical with the capsule instruction present in all eight files.

## Decisions Made

- Colonize's capsule is computed once by the caller (`runCodexColonizePlanOnly`) and passed as a parameter into `buildCodexColonizeManifest`, rather than letting the builder call `resolveCodexWorkerContext()` itself — keeps the builder pure and keeps the call-site count verifiable by grep.
- The capsule instruction was folded into each wrapper's existing dispatch-stage bullet/numbered-step language (not a new heading), matching `build.md`'s placement and phrasing exactly, per the plan's explicit instruction to mirror that wording rather than invent new phrasing.
- Both `.aether/commands/*.yaml` sources were edited in the same change so the source of truth and all three rendered copies cannot drift independently.
