<objective>
Close the two dead slots in the memory pack every helper receives, and make it impossible to add a third.

`buildColonyPrimeOutput` (cmd/colony_prime_context.go) builds a "Key Decisions" part from `state.Memory.Decisions` (:656-671) and a "Phase Learnings" part from `state.Memory.PhaseLearnings` (:674-691). Neither field has a writer anywhere in the running program: `aether init` empties them (`init_cmd.go:284`) and archiving clears them (`entomb_cmd.go:680`), and nothing else ever assigns to them. Both parts are therefore permanently empty by construction — headings that can never carry content.

Neither removal loses anything. Owner answers already arrive under "Clarified Intent" (:886), fed by `decision-answer`. Verified phase lessons already arrive under "Learned Memory" (:782), fed by the learn store that continue-finalize writes on every check (`codex_continue_finalize.go:~1607`). Keeping both pairs would make the pack say the same thing twice.

Purpose: a helper's context budget should not be spent on headings that can never say anything.
Output: two dead parts removed, and an invariant test that names any future part without a writer.
</objective>

    Create cmd/capsule_writer_invariant_198_2_test.go with `saveGlobalsCmd(t)` first. Add `TestEveryMemoryPackPartHasALiveWriter`.

    The test does three things. First, it discovers the part names mechanically by walking the AST of cmd/colony_prime_context.go for every `colonyPrimeSection` composite literal and reading its `name:` field — never from a hand-typed list, because a hand-typed list is a second surface that can go stale (the repo's own documented failure mode).
