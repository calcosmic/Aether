<objective>
Join the three measurement sources to the workers a phase actually dispatched, fall back to a
labelled estimate rather than losing a row, attach the parent the spawn tree already recorded, and
write the result at the end of every build and every continue.

Purpose: Plans 01–05 produced parts. This is the plan where the ledger starts existing for real
runs. It is also where Pitfall 3 lives — a ledger with fewer rows than the manifest had dispatches
is the warning sign that a worker's spend was silently dropped, so the row count is asserted
against the dispatch count.

Output: `cmd/spend_resolve.go` with the priority chain and parent join, called from both
finalizers.
</objective>

    - Given three dispatches and a direct-path attempt record holding a provider measurement for the first, the resolver returns three rows; row one is tagged `provider` with the attempt record's exact token counts.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| wrapper session artifacts → ledger rows | Externally-written files whose absence or corruption must degrade to an estimate, never fail a build |
| spawn-tree file → row parent attribution | A colony file whose absence must yield an empty parent, never a fabricated one |
| finalizer control flow → colony state commit | The ordering that decides whether a missing ledger is loud or silent |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-174-21 | Repudiation | dropped worker row | mitigate | Inputs are built from `manifest.Dispatches` rather than returned results, and `codex.EstimateUsage` guarantees a row for every input; asserted by `TestSpendResolverNeverDropsADispatch` and `TestSpendLedgerRowCountMatchesDispatchCount` |
| T-174-22 | Spoofing | fabricated parent attribution | mitigate | `spendParentsByWorker` returns only what the spawn tree recorded and leaves an unknown worker's parent empty; asserted by `TestSpendResolverJoinsParentFromSpawnTree` and a grep proving no `"Queen"` default exists |
| T-174-17 | Spoofing | source tagging | mitigate | The resolver copies a provider tag through from the attempt record but never sets one; asserted by `TestSpendResolverNeverMintsAProviderTag` and a grep returning 0 |
| T-174-02 | Denial of service | repeated transcript parsing | mitigate | Each wrapper-path source is consulted exactly once per invocation with the full worker-name list, not once per worker; asserted by a call-count grep |
| T-174-23 | Repudiation | silent ledger loss | mitigate | The ledger write is placed before `UpdateJSONAtomically("COLONY_STATE.json", ...)` and returns an error through the existing `finishAttempt` pattern; asserted by `TestSpendLedgerWrittenBeforeStateCommit` and an ordering check on the source |
| T-174-24 | Denial of service | wrapper artifact unavailable | accept | A missing hook capture, changed vendor format or absent OpenCode install all fall through to an estimate with a stderr diagnostic — degraded measurement is the intended behaviour, not a build failure |
