<objective>
Close two independent, unrelated silent gaps that both fit the phase's "no silent bypass" theme
but touch entirely different files -- bundled into one plan because each is individually too small
to justify its own plan (see 188-CONTEXT.md, Integration Points).

1. `aether state-mutate --field current_phase --value N` can be run today with no `--guard` at
   all, bypassing every precondition a real phase advance enforces. No live wrapper calls it this
   way (confirmed by repo-wide search — the only two hits are inside `.aether/docs/command-playbooks/`,
   which `CLAUDE.md` states plainly have not been loaded by the runtime since v1.25), so this is a
   pure bypass-closure with no known caller to break.
2. `validateBuildAttemptManifestBinding` already detects a dispatch_manifest with no attempt
   binding at all (`binding.Legacy == true`) but nothing ever reads that field — a legacy manifest
   is silently indistinguishable from a normal fresh completion in the logs. The ROADMAP's own
   Audit Addendum keeps this branch on purpose; this plan adds visibility only.

Purpose: ROADMAP criteria 3 and 6.

Output: a mandatory guard requirement on one CLI field mutation, and a two-channel (stderr +
Events) warning on one existing, deliberately-kept compatibility branch.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI caller (script, rogue automation, human at terminal) -> `state-mutate --field current_phase` | Anything that can invoke the `aether` binary directly can attempt to move the colony's recorded phase without going through the discipline `advancePhase()` (188-02) enforces. |
| External completion packet -> `codex_build_finalize` | A wrapper-submitted completion packet controls whether `dispatch_manifest` carries attempt-binding fields at all; a caller (or a stale/older wrapper version) can omit them and reach the legacy path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-188-07 | Elevation of Privilege | `state-mutate --field current_phase` bypasses every phase-advance precondition when `--guard` is omitted | mitigate | `Changed("guard")` is now required and its target must match the value being written; refusal makes no write, proven by a before/after disk-content test |
| T-188-08 | Spoofing | A completion packet claims phase completion via the legacy no-binding path, which carries weaker provenance guarantees than a properly bound attempt | accept | Explicitly kept by ROADMAP decision (D-10) — this phase adds visibility (loud warning, durable event), not new refusal logic; a future phase may choose to tighten this further, but that is out of scope here |
| T-188-09 | Repudiation | A legacy manifest is accepted with no trace, so nobody can later tell how many builds went through the older, less-verified path | mitigate | The new Events entry (D-11) makes every occurrence queryable via `aether history`/`aether status` after the fact, not just visible in a scrolled-past terminal |
</threat_model>
