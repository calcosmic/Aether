## Context for the Decision

From v1.19 and v1.20 work:
- TS host handles all 7 major workflows (plan, build, continue, oracle, watch, swarm, lifecycle)
- TS host parses all flags and calls Go CLI via JSON
- Go CLI owns state, verification, gating, finalizers
- Wrappers (Claude/OpenCode markdown) currently contain manual Go command chains

## The Two Options

**Option A: Host-Assisted Orchestrators**
- Wrappers add colony framing, narration, pacing
- Wrappers call `aether host` but may also call Go CLI directly for certain steps
- Wrappers can add pre/post-build context

**Option B: Thin Pass-Throughs**
- Wrappers call `aether host <workflow>` and render the result
- All logic (verification, gating, finalizers) lives in TS host or Go CLI
- Wrappers are minimal — just invoke the host and display output

**Recommendation: Option B (Thin Pass-Throughs)**
- Simpler boundary — one call per workflow
- No risk of wrapper/Go CLI flag mismatches
- Easier to test — only the host surface needs coverage
- Matches the v1.19 wrapper cutover goal

1. **Status:** Accepted
2. **Context:** v1.19 cut over wrappers to TS host; v1.20 hardened the surface. Need explicit boundary.
3. **Decision:** Wrappers are thin pass-throughs. They call `aether host <workflow>` and render output. No direct Go CLI calls from wrappers.
4. **Consequences:**
   - Wrappers are simpler and shorter
   - No flag mismatch risk between wrappers and Go CLI
   - All verification/gating lives in Go CLI (runtime authority)
   - TS host is the sole orchestration layer between wrappers and Go
5. **Boundary Rules:**
   - Wrappers MAY: add colony framing, narration, pacing, pre/post context
   - Wrappers MUST NOT: call Go CLI directly, duplicate verification logic, gate advancement, mutate colony state
   - TS host MAY: parse flags, call Go CLI, render output, manage dashboards
   - TS host MUST NOT: write to `.aether/data/` directly (only Go does)
   - Go CLI MAY: own all state mutations, verification, gating, finalizers
6. **Migration Note:** Existing wrapper duplication should be removed over time; this ADR governs new wrapper changes.
  </action>
