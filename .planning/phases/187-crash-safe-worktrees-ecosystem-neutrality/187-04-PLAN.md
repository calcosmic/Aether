<objective>
Make the merge gate that actually runs during a build work outside Go repositories, and
give `mergePhaseWorktrees` its first real-path tests.

Plan 02 fixed `worktree-merge-back` (`cmd/worktree.go`), the manually-invoked CLI command.
This plan fixes the second, duplicate implementation — `mergePhaseWorktrees`
(`cmd/codex_build_worktree.go:1098`) — whose test gate at line 1124 is still
`exec.CommandContext(testCtx, "go", "test", "./...")`. This is the one that matters most:
it is called live from `cmd/codex_build_finalize.go:569`, guarded by
`if effectiveParallelMode(updatedState) == colony.ModeWorktree`, on every worktree-mode
build finalization, and it is that function's only non-test caller. Without this plan, a
worktree-mode build in a Node, Python or Rust project reaches build-finalize, runs
`go test ./...`, fails unconditionally, and the phase's headline promise — worktree merge
works outside Go repos — is false on the path real builds actually take.

The function is also effectively untested. Its only existing test,
`TestMergePhaseWorktreesEmpty` (`cmd/codex_build_worktree_test.go:881`), passes an empty
worktree list, so the loop body never executes: the test gate, the clash gate, the
checkout fallback and the merge are all uncovered.

Purpose: ROADMAP criterion 2, half two ("merge gate ... use `resolveTestCommand()`, not
hard-coded `go test ./...`"), and ROADMAP criterion 3 in full ("`mergePhaseWorktrees`
gains real-path tests"). D-03 governs the empty-resolver case: refuse to merge, say why,
and never destroy the work you declined to merge.

Wave and dependency note: this plan has no compile-time dependency on plans 01, 02 or 03 —
it calls only `resolveTestCommand()`, which already exists at `cmd/gate.go:244`. It is
placed at wave 3 depending on plan 03 purely because plan 03 also writes
`cmd/codex_build_worktree.go` (rewriting `gcOrphanedWorktrees` and extracting
`removeGitWorktree`'s callers). Two plans editing the same Go file in the same wave would
collide. The regions are disjoint — plan 03 works in lines 819-1090, this plan works in
lines 1098-1167 — so if the executor is running these serially in one working tree and
plan 03 has already landed, this plan applies cleanly on top.

Output: `mergePhaseWorktrees`'s test gate rewired to `resolveTestCommand()` with a D-03
refuse-and-preserve branch; new `cmd/merge_phase_worktrees_test.go` with real-git fixtures.
This plan does NOT consolidate the two duplicate merge-gate implementations — CONTEXT.md's
`<deferred>` section assigns that to Phase 190. It fixes the hard-coded command at the
second site and leaves the duplication standing.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Project config (CLAUDE.md, package.json) → executed command | `resolveTestCommand()` reads a command string out of repository files and Aether then executes it inside the worktree. |
| Unverified worktree branch → user's main branch | This gate is the only thing standing between unreviewed worker output and `git merge` into main during build-finalize. |
| Build-finalize control flow → destructive cleanup | An error or a `failed` entry from this function aborts the finalize; a wrong disposition could let a later path treat the branch as disposable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-187-09 | Elevation of Privilege | Test command string from CLAUDE.md executed by `mergePhaseWorktrees` | accept | Pre-existing and unchanged in kind: `resolveTestCommand()` already feeds `checkTestsPass` and the verification section, and plan 02 already routes the CLI merge gate through it. The string comes from the user's own repository, which the user already controls. Splitting with `strings.Fields` into `exec.CommandContext(argv[0], argv[1:]...)` avoids introducing a shell, so this change does not widen the surface. |
| T-187-10 | Tampering | Unverified code merged into main during build-finalize because the gate passed vacuously | mitigate | D-03: an empty resolver result returns an error before the loop rather than skipping the gate. Explicitly does NOT copy `checkTestsPass`'s pass-by-default branch. Asserted by `TestMergePhaseWorktreesRefusesWhenTestCommandUnknown`. |
| T-187-11 | Denial of Service (data loss) | The refusal path reaching a git command that mutates or discards the branch | mitigate | The refusal returns before the entry loop, so no `git checkout`, `git merge` or cleanup is reachable from it. Asserted against real git by `TestMergePhaseWorktreesRefusalPreservesTheWorktree`. |
| T-187-12 | Denial of Service | Every worktree-mode build in a project with no determinable test command now fails at finalize where it previously failed at the test gate | accept | Both outcomes block the merge; this one explains why in plain language instead of surfacing a spurious Go compilation error. D-03 explicitly chooses refuse-and-report over merge-unverified. The remedy is a one-line test command in CLAUDE.md, which the error message states. |
| T-187-13 | Denial of Service | A slow non-Go test suite exceeding the 120s `BuildTimeout` now that non-Go projects are reachable | accept | Flagged and deferred by CONTEXT.md `<deferred>` (`cmd/timeouts.go:11`). Out of scope for this phase; note it in the plan summary so it is not lost. |
