<objective>
Close ROADMAP criterion 1: make the crash-then-resume path non-destructive, and move
destruction to a command someone has to ask for by name.

Today `gcOrphanedWorktrees` (`cmd/codex_build_worktree.go:1048`) selects `Allocated`,
`InProgress` AND `Orphaned` entries, with no phase filter and no dirty check, and calls
`removeGitWorktree` — `worktree remove --force` plus `branch -D`. It runs from three
places: `resume` (`cmd/session_flow_cmds.go:261`), `continue`
(`cmd/codex_continue.go:540`) and `init` (`cmd/init_cmd.go:201`).

Two consequences the owner reacted to directly. First: resuming a crashed run to recover
work is itself what destroys the work. Second: because there is no phase filter, resuming
phase 5 destroys a stalled phase 2 worktree. And the program disagrees with itself —
`recover` classifies a dirty worktree as critical, destructive-to-fix and
confirmation-gated (`cmd/recover_repair.go:148`), while `gcOrphanedWorktrees` silently
force-deletes the same worktree from `resume`. Closing that disagreement is the point.

Purpose: D-01 (preserve and continue; destruction only from a named operator command) and
D-02 (report in plain language on every occurrence).

Output: `gcOrphanedWorktrees` becomes preserve-and-report; three callers surface what was
preserved; a new `worktree-reap` command owns destruction behind `--force`; real-git
fail-then-pass tests prove it.
</objective>

Create `cmd/worktree_reap.go` in package `cmd` defining a new cobra command `worktree-reap`.

Behaviour follows `recover`'s precedent (`cmd/recover.go`) rather than inventing a new
convention:

- Flags: `--force` (bool: "actually delete; without this the command only reports what it
  would delete"), `--include-unmerged` (bool), `--branch` (string, optional — act on exactly
  one branch), `--json` (bool).
- Read-only by default. With no `--force`, list every candidate worktree, its dirty/unmerged
  safety verdict, and what would happen — and delete nothing, mutate nothing. This mirrors
  `recover`'s read-only default and satisfies CLAUDE.md's corollary that an inspection command
  must not mutate state.
- With `--force`, iterate tracked worktrees, call `worktreeDestructionSafety` on each:
  - Safe → call `removeGitWorktree(root, absPath, entry.Branch)` and drop the entry from state.
  - Not safe → call `preserveWorktreeWork` + `reportWorktreePreservation`, keep the entry, skip
    it. Even the explicit destruction command does not throw away unmerged or dirty work on
    `--force` alone; D-01 says such work is "never destroyed".
- `--include-unmerged` is the separate, additional opt-in for an operator who genuinely wants
  dirty or unmerged work gone. It must require `--force` as well; on its own it does nothing.
  When both are set, still run `preserveWorktreeWork` FIRST so the changes land in a stash
  before the worktree goes, then destroy. Report every such destruction on stderr naming the
  branch and how to reach the stash.
- Mutate state through `store.UpdateJSONAtomically("COLONY_STATE.json", ...)`, matching
  `gcOrphanedWorktrees`'s shape rather than the older `LoadJSON`/`SaveJSON` pair used in
  `cmd/worktree.go`, which has a race window between load and save.
- Classify the command as destructive via
  `isDestructiveWorktreeAction(worktreeDestructionCategory)` so it is discoverable as such
  alongside `recover`'s categories.
- Register with `rootCmd.AddCommand` in an `init()` in this file, matching `recoverCmd`.

Critically, `worktree-reap` must have no caller other than a human typing it. It must not be
invoked from `resume`, `continue`, `init`, `build`, `build-finalize`, `run`, or any autopilot
path. Add a comment stating this and stating that plan 04's ratchet test enforces it.

Write `Short` and `Long` help text for a non-technical reader per CLAUDE.md: it removes
finished worker workspaces; it only shows what it would remove unless you pass `--force`; work
that was never merged is kept even then. Describe the action in ordinary words — do not use
"orphan", "GC" or "reap" in the prose body even though the command is named `worktree-reap`.
  </action>

| Recovery command → uncommitted user work | `resume`, `continue` and `init` are the commands a user runs *after* something went wrong. They currently hold delete authority over the work being recovered. |
| Automatic lifecycle path → destructive git operation | Any implicit caller of `removeGitWorktree` is an unattended process deleting user data with no operator present. |
| COLONY_STATE.json entry fields → git argv | `entry.Path` and `entry.Branch` are interpolated into destructive git commands. |
