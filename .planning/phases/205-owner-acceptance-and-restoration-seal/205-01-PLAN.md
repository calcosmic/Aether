Create `cmd/classic_coverage_ratchet_test.go` carrying a generalized, phase-parameterized version of the Phase 199 validator chain, then use it to sign Phase 203's six CAP rows into a new `203-CLASSIC-COVERAGE.json`.

Types and identifiers to create, reusing the Phase 199 json tags verbatim so no second vocabulary appears: `classicCoverageDocument{Version string "version"; Rows []classicCoverageRow "rows"}` and `classicCoverageRow` with fields `Type "type"`, `ID "id"`, `Disposition "disposition"`, `ModernHome "modern_home"`, `PlanTask "plan_task"`, `Artifact "artifact"`, `Proofs "proofs"`, `Status "status"`, `HistoricalEvidence "historical_evidence"`.

Functions to create:
- `classicCoveragePathForPhase(phase string) (string, error)` — resolves the phase directory under `.planning/phases/` by its numeric prefix (so `203` resolves to `203-biological-runtime`) and returns `<dir>/<phase>-CLASSIC-COVERAGE.json`. An absent directory or an absent file is an error naming the phase, never a skip.
- `loadClassicCoverageLedgerRouting(root string) (map[string]classicCoverageLedgerRoute, error)` — parses `.planning/research/v1.28-classic-capability-ledger.md`, section "v1.28 requirement and phase mapping", returning for each CAP id its routed `Disposition`, `Requirement` and `Phase`. Strip backticks and surrounding whitespace from each cell. Parsing must not depend on `awk`/`cut`: split table rows on the pipe character in Go.
- `expectedClassicCoverageCAPIDs(routing, phase string) []string` — the ascending-sorted CAP ids the ledger routes to that phase. This is the ONLY source of the expected set; do not hand-type an id list anywhere in this file.
- `validateClassicCoverageExactCAPSet(document, expected []string) error` — every `type: GOAL` row's id appears exactly once and the set of GOAL ids equals `expected`; a missing id, an extra id, and a duplicate id each produce a distinct error naming the id. Errors for multiple ids are collected and emitted in ascending CAP id order so repeated runs are byte-identical.
- `validateClassicCoverageRequiredFields(document) error` — same rule set as `validateClassicCoverage199RequiredFields`: every one of `id`, `disposition`, `modern_home`, `plan_task`, `artifact`, `status`, `historical_evidence` non-blank and free of placeholder text, `proofs` non-empty, `disposition` one of `keep-current`, `restore-modern`, `replace-better`, `retire-with-proof`. Reuse `containsClassicCoverage199Placeholder` rather than writing a second placeholder detector.
- `validateClassicCoverageProofResolution(document, root string) error` — reuse `buildClassicCoverage199ProofIndex(root)` directly; `artifact` must stat to a real non-directory file, every proof must resolve in the index.
- `validateClassicCoveragePassingStatus(document) error` — every row's status is exactly `PASS`.
- `validateClassicCoverageDispositionMatchesLedger(document, routing) error` — a signed GOAL disposition must equal the ledger's routed disposition for that id, UNLESS the row's `historical_evidence` contains the literal marker for a recorded re-adjudication (use the token `re-adjudicated:` followed by a citation). A differing disposition with no such citation is an error naming the id, the signed value and the ledger value.
- `validateClassicCoverageAudit(document, root, phase string) error` — the companion `<phase>-CLASSIC-COVERAGE.md` must exist and contain a rendered table row pairing each JSON row's id with its disposition, and a `## GOAL` heading.
- `validateClassicCoverage(document, root, phase string) error` — runs the seven validators above in a fixed order.

Tests to create in the same file:
- `TestClassicCoverageLedgerRoutingIsUniqueAndComplete` — the parsed routing covers CAP-001 through CAP-072, each exactly once, with no gaps and no extras. This makes the derived expected set trustworthy.
- `TestClassicCoveragePhase203Signed` — loads `203-CLASSIC-COVERAGE.json` and runs `validateClassicCoverage` for phase `203`, expecting no error.
- `TestClassicCoverageMissingFileFailsByName` — `classicCoveragePathForPhase` on a phase the ledger routes rows to but whose coverage file is absent returns an error naming the phase. Exercise it against a temporary root, not by deleting a real file.

Then author `.planning/phases/203-biological-runtime/203-CLASSIC-COVERAGE.json` as `{"version":"203/classic-coverage/v1","rows":[...]}` with one `type: GOAL` row per CAP id the ledger routes to Phase 203 (CAP-002, CAP-009, CAP-014, CAP-030, CAP-031, CAP-058). Each row's `disposition` comes from the ledger unless Phase 203's own synthesis re-adjudicated it; `modern_home`, `plan_task` and `artifact` come from that phase's CLASSIC-SYNTHESIS.md routing table and its plan/summary files; `proofs` must name test functions that genuinely exist and pass today — confirm each one by running it before writing it into the row, never by pattern-matching a plausible name.

Scope note to record in the SUMMARY: for Phases 200-205 the coverage files carry `type: GOAL` (CAP) rows only. Phase 199's file additionally carries REQ/RESEARCH/CONTEXT rows and its own test stays untouched; PROOF-02's contract is about CAP rows, and mirroring 199's four-type set across five more phases would add ~150 rows of unrelated bookkeeping with no requirement asking for it. State this as a deliberate planner decision, not an omission.
