<objective>
Close the gap where a success criterion can be credited by checks that never covered the specific claim its own wording made.

Purpose: a real run on another project credited a criterion reading "…and the operator suite all pass" from build, type and general test checks alone — the named suite had never been configured and had never run. The existing guard refuses a criterion with no verification at all, but nothing refuses a criterion whose named verification is absent. This decides whether work is complete, so it takes full rigour: a command that fails when the requirement is unmet, and the fix proved by breaking it.

Output: a criterion-crediting path that will not credit a criterion whose own named command never ran.
</objective>

Recognise a command only where it is written as one: inside backticks, or as a recognisable runner invocation of the project's configured test or build runner. Wire both into the existing evaluation so a criterion with a non-empty `missing` list is refused with an error naming the criterion and each missing command. A criterion with an empty `named` list keeps its current path untouched, so nothing about today's behaviour changes for criteria that name no command.
