<objective>
Give a merged build dispatch's worker its full task -- every covered task's constraints, hints and
success criteria, not just the first one merged in -- and tell every wrapper-spawned build worker
the exact handoff/return schema the finalizer validates against, without duplicating that schema
for native-Codex workers who already receive it through a separate channel.

Today `renderCodexBuildWorkerBrief` (`cmd/codex_build.go:2667`) resolves Constraints/Hints/Task
Success Criteria via `findDispatchTask`, which looks up only `dispatch.TaskID` -- the FIRST task of
a chain `mergeDispatchInto` folded together. A worker covering three merged tasks sees all three
tasks' goal text in "## Assignment" but only the first task's constraints and success criteria, then
gets judged by the finalizer against work it was never told about. Separately,
`pkg/codex/worker.go`'s `renderResponseContract` already states the handoff schema the finalizer
enforces (`codex.ValidateWorkerHandoff`) -- but only on the native-Codex dispatch path; the
wrapper-facing brief (`dispatch.Brief`, the ONLY prompt content a Claude-Code- or
OpenCode-spawned worker ever sees) never mentions it.

Purpose: ROADMAP criteria 1 ("the brief for a merged dispatch contains every covered task's
constraints and success criteria") and 2's build half ("the brief contains the handoff/return schema
the finalizer enforces"). Plan 189-02 (reviewer parity) depends on this plan's `codex.HandoffFieldsSummary`
export to apply the identical fix to continue's external reviewer briefs.

Output: `findDispatchTasks` (multi-task resolution, replacing single-task `findDispatchTask`),
`codex.HandoffFieldsSummary` (the one canonical schema constant), `composeBuildManifestBrief`'s new
handoff-schema append, and three new/extended tests proving both fixes by invariant, not by string
presence alone.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Planner-authored task text (`phase.Tasks[].Constraints/Hints/SuccessCriteria`) -> worker prompt | Task content originates from planning (already-trusted, not external/live user input at dispatch time); this phase makes MORE of it reach a merged dispatch's worker, not new content. |
| Compiled schema constant (`codex.HandoffFieldsSummary`) -> worker prompt, both build and continue | A static compiled Go string, never runtime/user input; its wider reach is the entire point of the fix. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-189-01 | Denial of Service | `findDispatchTasks` resolving a covered task ID with no match in `phase.Tasks` | mitigate | Skipped silently (append nothing for that ID), never panics or errors the whole brief -- proven by the defensive case named in Task 2's `<behavior>` block. |
| T-189-02 | Tampering | `composeBuildManifestBrief`'s and (in 189-02) `plannedExternalContinueDispatches`'s handoff-schema append | accept | Appended text is a static compiled constant (`codex.HandoffFieldsSummary`), never runtime user input concatenated in — no injection surface introduced by this change. |
| T-189-03 | Information Disclosure | `codex.HandoffFieldsSummary` reaching every wrapper-spawned build worker | accept | The schema is meant to be known widely — it is already documented in `build.md` prose and enforced by the finalizer today; stating it in the brief is the fix this criterion exists to deliver, not a new exposure. |
