<objective>
Make the child's result a durable fact that lands once, survives interruption and replay, and turns every way it can go wrong into one named recovery with one named next action.

Purpose: this repository has already solved exactly this problem once, for pause and resume, and the solution is recorded in its own decision log: the handoff identifier is the idempotency key, an interrupted commit resumes one journal, and a verified replay returns one existing receipt. The failure mode here is not building a worse version of that; it is building a *different* version of that, so two replay-safety mechanisms exist and neither is the one a future reader expects.
Output: one complete result binding and five named recovery classes.

Flagged planner assumption (unresolved edge probe, BIO-04, category `unclassified`): BIO-04 requires the result to bind "execution generation" without defining it. This plan assumes it is the durable build-run identity the existing execution binding already carries, so a child launched under a superseded run cannot bind over a newer one. If a reviewer intended a per-child retry counter instead, the recovery class names change but the mechanism does not. Surfaced, not resolved.
</objective>
