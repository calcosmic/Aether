<objective>
Give every note a complete, permanent record of what has been done to it and by whom — and make the five actions that do not yet exist real.

Purpose: plan 203-13 turns outcomes into strength changes, which the owner has accepted as a costly decision precisely because learned strengths and owner-set strengths could otherwise become impossible to tell apart. The immutable history is what makes that decision undoable at all, so it has to exist before any automatic tuning starts moving numbers. Three of the eight actions landed with the approval surface; this plan builds the other five and the spine underneath all eight.
Output: eight working actions, one append-only history, and an actor recorded on every entry.

Flagged planner assumption (unresolved edge probe, BIO-08, category `unclassified`): BIO-08 lists eight actions without saying which are owner-only. This plan rules accept, edit, reject, revoke and appeal owner-only, and reinforce, defer and expire performable by the runtime as well as the owner — because the first five change what the owner meant and the last three change only how long or how strongly an existing meaning applies. If a reviewer intended a different split, the actor recording is unchanged and only the permission table moves. Surfaced, not resolved.
</objective>

  <behavior>
    - Appending an action writes a new entry carrying the note identifier, the action, the actor kind, the actor name, the timestamp, the before and after values it changed, and a reason.
    - Rewriting or deleting an existing entry is impossible through any exported path in the package.
    - Reading the history of a note returns entries in append order, and two reads return identical output.
    - An entry naming a note that does not exist is refused and nothing is written.
    - The history file is bounded by a named retention constant that prunes whole notes' histories only after the note itself is gone, never individual entries of a live note.
    - Actor kinds are a declared closed set, and an entry with an undeclared actor kind is refused by name.
  </behavior>
  <action>Create `cmd/pheromone_influence.go` holding `pheromoneInfluenceEntry`, `appendInfluenceHistory` and `readInfluenceHistory`, writing to `pheromones-history.json` through `store.UpdateJSONAtomically`. Declare `pheromoneActorOwner`, `pheromoneActorRuntime` and `pheromoneActorLearning` with a `pheromoneActors()` accessor, and refuse an undeclared actor kind by name.

Make append-only structural rather than conventional: the only exported mutation is an append, the slice is never indexed for assignment, and a named test walks the package's AST for any assignment into a history slice element or any removal of one. Prune only by dropping the complete history of a note that no longer exists, guarded by a named retention constant — the same bounded-history convention `trimSpawnRuns` uses.

Record before and after values on every entry that changes something, so an owner reading the history can see what a change actually did rather than only that a change happened. Sanitise the reason text with the existing signal sanitiser, because a runtime or learning actor's reason is machine-authored text that is replayed to the owner.</action>

    - An entry with an undeclared actor kind is refused with that kind named.

  <behavior>
    - Reinforcing a note raises its strength to the declared ceiling, increments the existing reinforcement count, and appends a history entry.
    - Deferring a note sets a recorded defer-until time; the resolver excludes it with reason `deferred` until that time passes, then includes it again with no further action.
    - Expiring a note sets its expiry to now; it leaves effect immediately and the history records the previous expiry.
    - Revoking a note takes it out of effect permanently, keeps its history, and cannot be undone by the runtime — only by an owner action that is itself recorded.
    - Appealing a rejected note records the appeal and surfaces the note for reconsideration without changing its rejected state.
    - Each of the five refuses when the note does not exist, naming the identifier, and writes nothing.
    - Runtime and learning actors may reinforce, defer and expire; only the owner may revoke or appeal, and a runtime attempt is refused by name.
  </behavior>
  <action>Add `reinforceNote`, `deferNote`, `expireNote`, `revokeNote` and `appealNote` to `cmd/pheromone_influence.go`, each appending to the history and each refusing an unknown note identifier by name. Declare `pheromoneInfluenceActions` as the closed set of all eight action names — the three the approval surface already performs plus these five — with a `pheromoneInfluenceActionNames()` accessor.

Add `DeferredUntil *string` and `RevokedAt *string` as pointer-backed optional fields on `colony.PheromoneSignal`, following the pointer-backed convention the provenance fields already use, and extend `resolveEffectivePheromones` to exclude a deferred note with reason `deferred` and a revoked note with reason `revoked`. A deferred note returns to effect on its own once its window passes; nothing needs to run for that to happen.

Expose the five actions as flags on the existing pheromone management command rather than five new commands: `--reinforce`, `--defer`, `--expire`, `--revoke` and `--appeal`, each taking a note identifier, plus `--reason`. Enforce the actor permission table in one function so the owner-only rule for revoke and appeal is a single check rather than five scattered ones. Preserve the existing dry-run contract: an inspection must not mutate.</action>

    - A runtime actor attempting revoke or appeal is refused and the refusal names the actor kind.
    - `--dry-run` combined with any of the five leaves the store byte-identical, asserted by a write counter of zero.
