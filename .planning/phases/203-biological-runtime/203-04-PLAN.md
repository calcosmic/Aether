<assumption_delta_decision>
The detector fired on this phase with two signals: `pluralization` on the word *fallback* ("binds a native child to the issued capability **or** uses an honest root-mediated fallback") and `chosen` on the word *configurable* ("configurable bounded probes").

**Primary noun:** the **dispatch adapter**. Child dispatch previously had one implicit shape — a subprocess launched by `spawnWorker` — with the native in-session path existing only as narration in `.aether/workers.md`. This phase introduces a genuine second case, so the adapter itself is promoted to the primary identity.

**Decision: `promote`.** `recruitmentAdapterKind` becomes a declared, closed enum, and every dispatch record and every durable result names exactly one member of it. The root-mediated subprocess is demoted from "the way dispatch works" to "one adapter kind", and native binding is the other. The alternative — adding native binding alongside a still-privileged, still-unnamed default — was rejected because a result would then be unable to say which mechanism produced it, and a future third adapter (a remote or containerised child) could be stored but never confirmed as the default.

The `chosen` signal is resolved the same way: the probe's timeout stops being a constant anywhere and becomes part of the probe *result's* identity, so a recorded probe outcome names the budget it ran under. A probe result read back later can therefore be judged rather than merely trusted.

**Companion invariant test (accepted, implemented as Task 3):** every declared `recruitmentAdapterKind` has a real dispatch path, and every durable recruitment result names exactly one declared kind. This goes red the instant a future phase reintroduces an implicit unnamed default.
</assumption_delta_decision>
