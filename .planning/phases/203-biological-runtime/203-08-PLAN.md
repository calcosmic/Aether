<objective>
Put everything that needs the owner's tick in one place: notes the system proposed and notes that arrived from another project, cleared by the same command, with the same accept, edit or reject choice.

Purpose: the owner's standing instruction is one approval surface, not two ceremonies. The mechanism already exists — a pending queue with content-hash deduplication and approve, dismiss and dismiss-all commands — and is currently used by exactly one producer. Extending it is a smaller and more honest change than building a quarantine inbox beside it, and it guarantees the two things can never disagree about what is waiting.
Output: one queue carrying both kinds, one command clearing both, and the only path in the program that can release a quarantined note.

Flagged planner assumptions (unresolved edge probes, category `unclassified`):
- BIO-07: the phrase "starts quarantined" does not say who may release. This plan rules release to be owner-only, per D-10, and makes that a test rather than a convention. Surfaced, not resolved.
- BIO-08: the eight influence actions are named but not scoped to a surface. This plan implements accept, edit and reject here because they are the owner-facing three; reinforce, defer, expire, revoke and appeal are plan 203-11's. If a reviewer expected all eight on one command, the split is wrong but the storage is not. Surfaced, not resolved.
</objective>
