<objective>
Extend the one admission chokepoint with the four dimensions it does not yet check, make the record of an admitted child land atomically before the child runs, and honour the owner's per-run depth flag without letting it become an invisible raise.

Purpose: the existing gate is genuinely good — three ordered checks, each denying by name, each failing closed, already midden-logged and exhaustively tested. The risk here is not designing something new, it is forking it. Four more dimensions must join that function rather than sit beside it, and which caller each dimension applies to must be written down rather than inferred from whichever fields happen to be populated.
Output: a complete atomic admission decision, a declared applicability table, and a manifest amendment that denies on failure to write.

Reversibility: **costly** — making `spawnMaxDelegationDepth` raisable per run contradicts the sibling budget constant's own recorded reasoning that a limit you can raise under pressure is a limit that gets raised. D-11 is a locked owner decision and is honoured. The undo is not a migration but a policy reversal, and what makes it undoable is that every use of the flag is written into the append-only spawn ledger, so the record of when the cap was raised survives the flag.

Flagged planner assumption (unresolved edge probe, BIO-02, category `unclassified`): BIO-02 names "parent authority" as a dimension distinct from depth and permission without defining it. This plan assumes it means the named parent resolves to a recorded, non-terminal spawn-tree entry, and that the depth used in the decision is the one derived from that entry rather than one the caller stated about itself. Surfaced, not resolved.
</objective>
