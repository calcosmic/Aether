# Phase 201 Classic-to-Go Synthesis

This is the mandatory pre-plan mechanism study for Phase 201 (SYNTH-03, gated by SYNTH-07). It treats Classic as evidence about what made the work cycle feel purposeful and proportionate, not as code to restore, and treats the current Go kernel (attempts, receipts, deterministic floor, coherent jobs) as the authority every decision below builds on. [VERIFIED: `.planning/research/v1.28-classic-synthesis-template.md`; `.planning/phases/201-queen-led-work-cycle/201-CONTEXT.md`]

## 1. Outcome under investigation

- **Owner-visible outcome:** the owner watches the Queen choose the smallest capable team and explain why, sees related work land as one coherent job across visible waves, gets exactly one review pass per phase at a boundary the Queen chose and named, reads a closeout that is as considered when work is partial or blocked as when it succeeds, sees what that attempt cost and how long it took, is handed exactly one next action with a reason, and — after a failure — is told what was tried, why it did not work, and that the project was put back exactly where it was. [VERIFIED: `201-CONTEXT.md` D-01..D-16]
- **Operational outcome:** build, continue, and autopilot converge on one Go-owned accept/verify/advance authority operating on one durable attempt/result model; the deterministic floor stays the unskippable pass source at every depth; verification-boundary choice, outcome vocabulary, cost/time, credited/orphan files, and bounded repair all bind to that same attempt identity; per-job telemetry is instrumented honestly (unmeasured segments render as unmeasured, never derived); and three approved speed levers are applied without touching TDD, the deterministic floor, or worker-count ceilings. [VERIFIED: `201-CONTEXT.md` D-01..D-16; `.planning/REQUIREMENTS.md` WORK-01..08, CEC-06]
- **Why this phase owns it:** the roadmap routes `SYNTH-03`, `CEC-06`, and `WORK-01..08` here; the capability ledger routes `CAP-003`, `CAP-004`, `CAP-022`, `CAP-024`, `CAP-029`, `CAP-051`, `CAP-066`, and `CAP-071` here. [VERIFIED: `.planning/ROADMAP.md` Phase 201; `.planning/research/v1.28-classic-capability-ledger.md:136,137,155,157,162,184,199,204`]
- **Non-goals:** substantive live Swarm/Watch/Oracle behavior is Phase 202; causal pheromone delivery and TypeScript-host preflight/timeout work is Phase 203; learning governance and outcome-backed promotion is Phase 204; final acceptance is Phase 205; the iterative planning loop and SPEC lifecycle were already delivered in Phase 200. [VERIFIED: `201-CONTEXT.md` domain boundary and Deferred Ideas]

For dummies: keep the modern engine, the modern brakes, and the modern proportionate-team judgment v1.27 already built — but stop reviewing the same finished work twice, make every outcome (not just success) get the Queen's full attention, say honestly what a job cost and what it touched, and give a failure one careful repair attempt with a real explanation instead of a shrug or a silent retry loop.

### Core data contracts

1. **`verificationBoundaryDecision{Choice, Reason, Source}`** — a small sibling type to `queenCasteJudgement`, never extending it (resolves Open Question 1). `Choice` is `"build_end"` or `"continue"`; `Reason` is required when `Choice == "build_end"` (D-02); `Source` mirrors `"queen"`/`"deterministic"`. Stored as one durable fact both build-time and continue-time dispatch code read — never two independent derivations (Pitfall 2).
2. **Extended `colony.OutcomeKind`** (or a bound mapping from `buildAttemptRecord.Status`) — adds the missing members so D-05's six named outcomes have exactly one home each, without removing any of the current 11.
3. **Attempt-scoped cost/time fields on `buildAttemptRecord`** — new fields following the SAME "set ONLY by function X," `omitempty`-compatible, narrow-setter discipline as `CheckFix`/`FreeChecks` (`TestFixAttemptNeverOverwritesTheFirstResult` precedent), never a parallel envelope type.
4. **Credited/orphan file lists on the unified result card** — generalizing `uncreditedWorktreeReceiptMessage199`'s existing shape into the in-repo direct lane, bound to the same task-ID credit set `allSelectedBuildTasksCredited` already computes.
5. **General bounded-repair record** — extends `checkFixAttemptRecord`'s narrow-setter, one-shot shape and `autopilotRepairLedger`'s budgeted/receipted shape to the phase's own repair story; its checkpoint identity is a `PauseHandoff`-shaped reference (handoff ID as idempotency key), not a new primitive.
6. **Per-job telemetry record** — new type, keyed by `buildAttemptRecord.ID`, with one field per named segment (queue, preflight, model, tool-call, context, work, verification, wait), each either a measured duration or an explicit unmeasured sentinel.

### Stop, failure, and recovery semantics

- A build that finishes before verification has run renders the honest unverified card (`SYN-201-05`) and never advances state — this holds on both the interactive wrapper lane and the autopilot/host lane (RESEARCH.md Integration Points).
- Repair is exactly one checkpointed round: checkpoint (reusing `PauseHandoff`'s idempotency pattern), one repair wave fed same-run failure evidence, one re-verify. Still failing restores the checkpoint and pauses with the complete handback — no second automatic attempt, ever (D-09 literal text, already type-enforced for the narrow cases this generalizes).
- Every outcome — success, no-change, partial, blocker, timeout, interrupted — renders the identical full closeout ceremony; only the verdict and the recommended next action differ (D-05).
- A crash mid-repair recovers via the same `PauseHandoff`-shaped identity: a replayed checkpoint-restore returns the existing receipt rather than re-doing the restore.

### Compatibility and migration

- Decode absent new fields (boundary decision, outcome extension, cost/time, telemetry) as legacy/unmeasured; existing attempts remain readable. [VERIFIED basis: existing `omitempty` compatibility pattern across `buildAttemptRecord`/`colony.go`]
- The two existing narrow repair mechanisms (`checkFixAttemptRecord`, `autopilotRepairLedger`) are generalized, not replaced by a fourth parallel repair type (RESEARCH.md Anti-Pattern).
- Legacy root-level artifact filenames (`CAP-071`) require no migration work — already resolved structurally (`NOW-21`); this phase only needs to confirm and close the row.
- Keep `/ant-*` as the ordinary Claude/OpenCode vocabulary; no Codex-native `$ant-*` surface added in this phase (Phase 199/200 precedent, unchanged).
