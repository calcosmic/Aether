<objective>
Turn this project's own confirmed failures into a versioned bank of regression fixtures that can each fail against the real defect that produced them.

Purpose: this repository has, by its own documented history, shipped the same class of defect repeatedly — a feature declared restored in four separate milestones, a learning pipeline declared repaired four times, eighteen of twenty-five milestones framed around recovering something previously marked done. Every one of those was confirmed at the time and then had nothing standing guard over it. A confirmed incident that does not become a check that fails when the defect returns is a lesson the project has agreed to relearn.

Output: one conversion that refuses anything unconfirmed, one versioned bank seeded from real confirmed incidents, and a retirement rule that names a successor rather than deleting evidence.
</objective>

## Planner Assumptions (no CONTEXT.md — owner may veto)

**Assumption I (Research Open Question 3) — the bank is filled from failures that genuinely happened here, and nothing is invented to reach a number.**
The requirement names a bank of forty-three. Counted this session, this project already holds more than that in genuinely confirmed failures: forty-two findings marked verified in its own whole-system audit, nine entries in its defect register marked fixed, and the failures each phase's own closing report recorded and repaired. The bank is filled from those. If the honest supply had been short of forty-three, the bank would grow toward it over time rather than being padded — it is not short, so it does not need to.
*If the owner disagrees* (wants exactly forty-three immediately regardless of source): that would require inventing incidents, which this project's own rules call a false certificate.

**Assumption J (edge probe, LEARN-04, unclassified — surfaced, not resolved) — "confirmed" means a human or a gate already agreed it was real.**
The requirement does not define confirmed. This plan reads it as: a failure-log entry marked both reviewed and acknowledged; an audit finding marked verified; or a defect-register entry that reached a fixed state. Anything else — an unreviewed failure, an unverified audit claim — is not confirmed and produces nothing.
*If a later reviewer disagrees:* the affected work is this plan and the gate tiers in plan 204-07.

  <action>Add the conversion to `cmd/fixture_conversion.go`.

`confirmedIncident` is the one normalised shape every source is read into before conversion, so the conversion itself has one input type rather than four: the source kind, the identifier within that source, the raw title and detail text, the severity and the timestamp. Declare one reader per source, each returning that shape and each applying its own confirmation gate at the point of reading:

- `confirmedIncidentsFromFailureLog()` — loads through `loadMiddenFile`, keeps entries where the reviewed flag and the acknowledged marker are both set. Read only; do not modify the failure-log type or its writers.
- `confirmedIncidentsFromAuditFindings(path string)` — parses the whole-system audit's JSON, keeps findings whose verified flag is set.
- `confirmedIncidentsFromDefectRegister(path string)` — parses the defect register's table rows, keeps rows whose status is fixed.
- `confirmedIncidentsFromPhaseReports(dir string)` — parses phase closing reports for the rows that record a defect found and repaired at the gate, keeping only those naming a commit.

Each reader returns, alongside its incidents, the count it refused and the reason class for each refusal, so the conversion can report what it declined rather than silently narrowing.

`convertConfirmedIncidentsToFixtures(incidents []confirmedIncident) (regressionFixtureBank, fixtureConversionSummary, error)` is the single conversion. For each incident it runs the title and detail through `colony.SanitizeSignalContent` — the same sanitiser every failure-log writer already uses, never a new scrubber — and drops an incident whose text the sanitiser refuses, recording it in the summary by identifier. It computes `content_digest` with `crypto/sha256` over the normalised sanitised text, and uses that digest as the dedup key: an incident whose digest already exists appends its provenance reference to the existing fixture rather than creating a second one. It derives the fixture identifier deterministically from the digest so a re-run produces the same identifier. It sets privacy to the repository-local disposition by default and to the redacted disposition when the sanitiser altered the text, never to the public disposition automatically.

`writeFixtureBank(bank regressionFixtureBank) error` is the only writer of the bank file, going through the store's own atomic-update helper the way every other store in this repository writes, and aborting the write when the bank is unchanged so a re-run touches no bytes.

`retireFixture(id, successorID, reason string) error` sets the retirement fields and never removes the fixture from the bank. A retirement naming a successor that does not exist is refused by name.

Extend `cmd/fixture_conversion_test.go` with `TestUnconfirmedIncidentProducesNoFixture` covering each source's own refusal as a subtest and asserting the refusal names the missing confirmation fact; `TestSameIncidentTwiceProducesOneFixture` asserting on the file's bytes; `TestTwoIncidentsWithOneDigestShareAFixture` asserting two provenance references on one fixture; `TestUnsanitisableIncidentIsDroppedNotStored`; `TestRetirementNamesASuccessorAndKeepsTheFixture`; `TestEmptyIncidentSetWritesAnEmptyBank`; and `TestFixtureBankHasOneWriter`, an abstract-syntax-tree scan proving no function other than `writeFixtureBank` writes the bank path, with its own non-vacuous synthetic fixture.

Every test drives a real reader against real seeded source data written in that source's own real shape. Do not construct a `confirmedIncident` literal to test the conversion's own gate — that would test the conversion against an input the readers can never produce.</action>
