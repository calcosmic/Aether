<objective>
Give every live memory store a declared schema version and a common provenance shape, tighten the one untyped history shape into a typed one, and settle every field that no part of the running program writes.

Purpose: the store census found the same weakness repeated across stores — a file-level version but no per-record version, provenance present in one store and absent in the rest, and one history shape that is an untyped map so nothing can be checked about it. That is why two separate audits have had to re-derive what is live and what is not, and why two frozen capability dispositions went stale. A schema that says what version a record is and where it came from is what makes the rest of this phase's promotion, rollback and lineage claims checkable rather than asserted.

Output: one shared schema and provenance contract; a typed application history; and a field-level census that fails by name when something is written by nothing.
</objective>

## Planner Assumptions (no CONTEXT.md — owner may veto)

**Assumption E — an old record is read, never rejected and never rewritten in place.**
Records saved before this change do not have a version stamp. They are read as what they are, with sensible defaults for anything missing, and they are left alone on disk. Nothing is bulk-rewritten, so nothing can be lost by a migration going wrong.
*If the owner disagrees* (wants old records upgraded on disk): that is a separate, larger change with its own backup step; this plan deliberately does not do it.

**Assumption F (edge probe, LEARN-01, unclassified — surfaced, not resolved) — "compatible versioned schemas" means one shared version contract, not one shared file format.**
The requirement's wording does not say whether the stores must share a format or merely agree about versioning and provenance. This plan reads it as the latter: each store keeps its own file and shape, and they agree on how a version is declared and how provenance is recorded. The skills store is kept in a database rather than a file and cannot share a file format at all, which is the strongest argument for this reading.
*If a later reviewer disagrees:* the affected work is this plan and the skills-authority work in plan 204-09.
