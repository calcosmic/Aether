<objective>
Close verification gap SC3c: of the 47 fixtures in the versioned regression-fixture bank, only 7 carry a named guard test; 40 sit on the counted-unguarded list, so most confirmed incidents in this project's own bank are not actually regression-protected.

Purpose: shrink that floor honestly, and close the hole that lets it be inflated. Today `assertSeedBankUnguardedWithinFloor` only fails when the real count EXCEEDS the floor — a floor set generously above reality would pass forever, which is exactly the "number written down is not the number the tests prove" failure D-09 forbids.

Output: a materially smaller unguarded count, each new guard citing a real existing test for that fixture's own incident, and a two-sided ratchet so the recorded floor must equal the proven count.

**Scope boundary (from 204-CONTEXT.md Deferred Ideas):** guarding all 40 is explicitly NOT required here. D-09 requires the floor to shrink honestly, not to reach zero.

**Downstream consumer (why this plan runs in Wave 1 and 204-12 in Wave 2):** gap-closure plan 204-12 replaces the always-pass shadow grader with a classifier that branches on whether a bank fixture carries a guard, and its tests resolve one guarded and one unguarded example fixture from the bank at run time. This plan therefore lands FIRST, and must leave the bank with at least one guarded fixture and at least one unguarded fixture — which D-09's "not all 40" boundary already guarantees, and which is now an explicit acceptance criterion below rather than an accident.

**Depends on executed plans:** 204-05 (`cmd/fixture_conversion.go`, the bank), 204-07 (`cmd/eval_gates.go`, the guard index and floor). Both are merged.
</objective>
