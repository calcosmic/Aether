<objective>
Start the two-week trial properly: fix the dates, the projects and the meaning of "blocker"
before it begins, and put in place the one thing that records a blocker without the owner
having to stop and type anything.

Purpose: at the end of the fortnight one number decides whether investment in the whole
framework continues. That number is only as honest as the recording, and the recording only
happens if it costs the owner nothing. Everything here exists to make the final count
trustworthy — and to make it impossible to argue the definition either way once the numbers
are in.

Output: a written start record, an empty ledger, and a short temporary instruction in this
repository's own CLAUDE.md that makes every chat here write a blocker down before it fixes it.
No new command, no new code, no new test.
</objective>

<what_this_plan_is_not>
This is not a build phase and this plan must not turn it into one.

The milestone decision names the failure directly: *"GSD's full ceremony is part of how the
work turned inward. Each phase here stays small and its proof is a real run in a real chat,
never paperwork, and one review round."* A tracking system, a dashboard, a metrics harness or
a reporting pipeline built to measure this trial has already failed on the phase's own terms.

**What was considered and rejected, so it is not reconsidered mid-execution:**

- **A new `aether` command to record or tally blockers.** Rejected: it is a new feature, which
  the milestone forbids outright, and it would need the owner to remember to type it at the
  exact moment he is annoyed and mid-task somewhere else.
- **Using `/ant-flag` in this repository as the ledger.** Rejected on three specific facts, not
  on taste. `.aether/data/` is in `.gitignore`, so the record would be local-only and not part
  of this phase's committed evidence — and UED-20's stated proof is the log itself. This
  repository's flag store already holds its own unrelated rows, so the trial's count could not
  be cleanly separated from them. And a flag that gets resolved stops being open, which would
  silently delete fixed blockers from a count that must include them. `/ant-flag` stays useful
  for anything the owner wants tracked in the project where it happened; it cannot be the count.
- **A halfway check-in.** Rejected as ceremony. The guard against an unused recorder is that the
  owner is not the one operating it (D-03 means he is already in this chat when a blocker
  happens, and the chat does the writing), plus Task 3 proving the path on the first real day.

**What is being added, and why it is the smallest thing that works:** two markdown files in
this phase's own directory, and one short dated section in a file every chat here already
loads. The start record and the ledger are phase reports, which is the row this repository's
own "Where Unfinished Work Is Recorded" table already assigns to
`.planning/phases/<phase>/` — the same shape as phase 209's `209-TIMING.md`. Nothing here is
a new tracker and nothing here is permanent.
</what_this_plan_is_not>
