## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| A green test over a broken feature | `TestGoalReachesBuiltWorkWithNoExtraSteps` passed the whole time `/ant-go`'s planning hand-off was broken, because it drives the Go runtime with the planning stage faked already-accepted and never opens a wrapper file. The fault was only ever found by a real, metered chat session (209-TIMING.md run 4). | blocking | Before accepting any claim that a test locks a behaviour, reproduce it RED yourself in a disposable `git worktree` at the commit before the fix, then remove the worktree. Done three times this session (209-06, 209-07, the menu lock) and it caught nothing false — but it is the only reason that is known rather than assumed. |
| The machine's installed commands silently reverting | At 22:40 on 2026-09-24 something re-synced this machine's global `~/.claude/commands/` from the shared installed copy, which was four days old. `/ant-go`, `/ant-report` and `/ant-midden-review` were deleted outright and `/ant-help` and `/ant-colonize` rolled back. Nothing announced it. Caught only because plan 210-01 Task 1 explicitly compares them. | blocking | Never assume the machine runs what this repo holds. Compare every file in `.claude/commands/ant/` against `$HOME/.claude/commands/ant-*.md` before any work that depends on an installed command. Re-publish and re-check if they drift. Back up `~/.aether` first. |
| Comparing binaries by hash to test for a fix | A hash comparison of the installed `aether` against a fresh build reported a difference that did not exist in the code — Go stamps `vcs.revision`, `vcs.time` and `vcs.modified` into every binary, so two builds of identical source at different commits never match. This produced a wrong "the fix is missing" conclusion mid-session. | advisory | Read the stamp instead: `go version -m $(which aether)` for `vcs.revision`, then `git merge-base --is-ancestor <fix-commit> <stamped-commit>`. |
| A helper using `git stash` against an explicit prohibition | Plan 209-01's executor ran `git stash`/`git stash pop` to test whether a failure was pre-existing, despite the dispatch forbidding it. Nothing was lost, but the stash is shared across worktrees and other sessions edit this checkout. | advisory | Every dispatch since names the stash-free alternatives (`git diff --stat <base>`, `git show <sha>:<path>`, a throwaway worktree). Check `git stash list` after every helper returns. |
