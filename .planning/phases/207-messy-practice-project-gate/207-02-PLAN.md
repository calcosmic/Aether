Expand `cmd/testdata/journey/traps.json` from one entry to nine, in this declared order —
the order failures are reported in, and the order the builder applies them:

1. `shortcut-to-a-folder` — an uncommitted symbolic link pointing at a real directory inside
   the project. Journey step `pause`. Blocker: `a pause fingerprint that followed folder
   shortcuts`.
2. `shortcut-loop` — two symbolic links that point at each other. Journey step `survey`.
   No historical blocker; this one is a robustness net, and the trap entry must say so in
   its own `blocker` field (use an empty value plus a `note`, never a blocker it does not
   exercise).
3. `case-only-archive-collision` — two real files in DIFFERENT directories whose
   archive-relative names collide only by letter case (`.aether/HANDOFF.md` and
   `.aether/data/handoff.md`). Journey step `archive`. Blocker: `two archive names differing
   only by letter case`.
4. `nested-project` — a subdirectory that is its own git repository, with its own committed
   file, left uncommitted in the outer project. Journey steps `pause` and `survey`. Blocker:
   `a pause fingerprint that followed folder shortcuts` (the same fix covers it, per that
   commit's own message), plus a note that its behaviour at survey time is unexplored.
5. `long-folder-names` — a real source file reachable only through a directory chain long
   enough to exceed the forty-character canonical lineage cap. Journey step `discuss`. No
   blocker field (it is a genuine 2026-09-21 fix but NOT one of the six the decision record
   names) — record that in the entry's `note`.
6. `out-of-date-code-map` — a `.aether/data/survey/territory-snapshot.json` whose recorded
   source revision is far enough behind the project's own head, and whose generated-at is old
   enough, to classify as stale. Journey step `survey`. Blocker: `a folder missing from a
   write allowlist` (the stale map is what forces the territory refresh that hits it).
7. `specification-corrected-mid-planning` — the marker state a parked planning run plus a
   changed, re-approved specification leaves on disk. Journey step `plan-second`. Blocker:
   `a planning run pinned to a superseded specification`.
8. `leftover-junk-data` — already built in Plan 01; extend it to also seed stray rows in
   `.aether/data/pheromones.json`. Journey step `status`. Blocker: `a status card advising a
   menu command that does not exist`.
9. `unsaved-changes` — uncommitted edits to a tracked file and at least one untracked file,
   left in place at the end of the build. Journey step `pause`. Blocker: `a pause fingerprint
   that followed folder shortcuts`.

Give every entry the same fields Plan 01 established: `id`, `description` (plain English,
with any word this repository invented explained in the same sentence), `journey_step` (or a
`journey_steps` list where a trap serves two), `blocker`, `note`, and `assertion` — a
machine-readable descriptor naming the path and the fact that must hold, so the Go test in
Task 2 can drive off the declaration rather than duplicating the list.

Extend `cmd/journey_traps.go` only as far as the new fields need: add the extra struct

order as the canonical order — no sorting anywhere.

Then implement all nine in `scripts/build-messy-practice-project.sh`, extending the loop
Plan 01 already wrote. Two points of care:

- **Case-only collision:** build it as the two different-directory files named above. Add a
  comment saying why a same-directory pair cannot be used (a case-insensitive volume aliases
  them, so the trap would silently not exist) and that the different-directory shape is what
  the real failure actually was.
- **Out-of-date code map:** derive the snapshot's fields from what `classifySurveyFreshness`
  genuinely reads — schema version, recorded source revision, generated-at, digests — rather
  than typing a plausible-looking JSON literal. If the project has fewer commits than the
  staleness commit threshold, create the extra commits the script needs so the snapshot
  really does classify as stale. A trap that does not trip the real classifier is a false
  certificate; say that in a comment.

Order matters at the end: the traps that must be left uncommitted (`shortcut-to-a-folder`,
`nested-project`, `unsaved-changes`) are applied last, after any commit the script makes, so
they genuinely survive as unsaved changes. Update the `.journey-practice-project.json` marker
to record all nine applied ids and the schema version.
