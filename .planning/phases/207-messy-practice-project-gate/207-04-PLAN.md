  <action>
Wrap the fourteen-step run in a trial loop, three trials by default, each trial starting from
a freshly built practice project and a fresh session id. Allow the trial count to be lowered
for development, and make that impossible to hide: a report with fewer than three trials is
refused by the verdict, naming the count.

Per trial, record: index, session id, start and end time, the caps in force, every step's
result, and one outcome from a closed vocabulary — `passed`, `flaky-failure` (failed, every
failure classified transient), `real-failure` (at least one failure classified real), or
`incomplete` (the trial was cut short; name the step it stopped at). An incomplete trial is
never `passed`.

Extend `journeyGateVerdict` — the one verdict function, never a second one — to enforce, in
this order, each refusal naming what was wrong:
  1. scope must be `whole-chain`;
  2. mode must be `live`;
  3. at least three trials;
  4. for every trial, declared step count equals executed step count (a trial that stopped
     part way fails here, with both numbers named);
  5. no trial may be `real-failure`, and not every trial may have failed — three flaky
     failures in a row is a real failure however each one classified, because the point of
     three trials is to tell noise from a product defect;
  6. every case in the expected-red register must be reported with result `still-red`; a case
     reported `now-green` fails, saying the register is stale and the entry must be removed;
  7. any failing check that has no case in the register fails outright.

Run every expected-red case for real inside the `status` step, record its genuine result in
the report's `expected_red` section with the case id, the `closed_by` value and the detail,
and never mark it as caught or fixed.

Write one report per run to the practice project's
`.aether/data/worker-debug/journey-report.json`, and give each concurrent run its own
practice-project directory and its own report path so two runs cannot overwrite each other's
results. Print, at the end, a short plain-English summary: how many trials passed, which
steps failed and whether each failure was noise or real, the caps that were in force, the
observed wall clock and — where the tool reports it — the observed cost, and one line per
expected-red case saying it is still red and what closes it.
