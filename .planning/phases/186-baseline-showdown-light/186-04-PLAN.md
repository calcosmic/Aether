<objective>
Capture, as committed evidence, exactly what an Aether worker is told on a real mid-project
colony — and prove the capture itself changed nothing.

`aether build --print-brief --full` capture. Its value is as a context-composition baseline:
Phases 189 and 190 change what workers receive, and without this snapshot there is no before to
compare against. The read-only proof matters independently — this repo has a documented history
of inspection commands that mutated state despite saying they did not.

`bench/evidence/print-brief-capture.md` (provenance and read-only proof), and
`bench/evidence/capture-print-brief.sh` (the one command that retakes it).

  <action>
Create `bench/evidence/capture-print-brief.sh`, executable, with the repo's standard header:
`set -euo pipefail`, doc block, `ROOT` resolution, `fail`/`step` helpers.

It takes two arguments: the path to a repository containing a real mid-project colony, and the
phase number to capture. It must NOT create or advance a colony — CONTEXT.md requires a real
mid-project colony, and one manufactured by the capture script would be a fixture, not evidence.
If the named repo has no `.aether/data/COLONY_STATE.json`, or the named phase is out of range,
fail with a named message telling the operator to point it at a real colony.

Sequence:
1. Record `shasum -a 256` of `.aether/data/COLONY_STATE.json` and a recursive listing with
   modification times of everything under `.aether/data/`, into a before-snapshot file.
2. Build the binary from this repo's source (`go build -o "$WORK/aether" ./cmd/aether`) so the
   capture is of the current code, not whatever version happens to be installed. Record the
   binary's `version` output.
3. Run `("$BIN" build <phase> --print-brief --full)` from the colony repo, capturing stdout and
   stderr separately. Assert exit 0; on non-zero, print the first 20 lines of stderr and fail
   with the real reason.
4. Re-record the same checksum and the same listing into an after-snapshot file.
5. Assert the before and after checksums are identical, and that the two listings are identical.
   On any difference, print the diff and fail with "print-brief mutated colony state — the
   inspection command is not read-only". This is the assertion that gives the capture its value;
   without it the file is just output.
6. Write the captured stdout to `bench/evidence/print-brief-capture.txt`.

Add a `--check` mode that runs the whole sequence but compares the fresh capture against the
committed `print-brief-capture.txt`, reporting whether the composition has changed and by how
many lines and which section headings differ. This is what Phases 189/190 will run to show the
brief changed. `--check` must exit 0 when unchanged and non-zero with a readable diff summary
when changed, so it can be used as a gate later without being rewritten.

Redact nothing automatically, but before writing, scan the capture for anything matching common
secret shapes (`sk-`, `ghp_`, `AKIA`, `-----BEGIN`) and fail loudly with the matching line
numbers if found rather than committing them — the capture is going into git.
  </action>

    - The script contains no reimplementation of brief composition — it contains no reference to `attachBuildDispatchContext`, `resolveCodexWorkerContext` or any Go symbol
    - The script computes a checksum of `COLONY_STATE.json` both before and after — `grep -c 'shasum' bench/evidence/capture-print-brief.sh` returns at least 2

    - Running it a second time against the same colony produces a capture whose composition-table section headings are identical to the first (the command is deterministic in structure)
    - `bench/evidence/capture-print-brief.sh --check` exits 0 immediately after a capture is taken
    - The script contains the four secret-shape patterns `sk-`, `ghp_`, `AKIA`, `BEGIN`
  </acceptance_criteria>
