<objective>
Execute ONE benchmark run — `aether-interactive` against `01-bug-fix` — with a human operator at
the keyboard, then generate and commit its evidence.

**Rescope, 2026-08-18 (owner decision).** This plan was twelve runs across three lanes and four
categories. The comparative baseline against GSD is cut. The fix phases 187–191 each carry their
own fail-able wiring criteria and never needed a number from it; the `Depends on: 186` lines were
sequencing, not information, and those phases are now unblocked to start immediately.

What survives, and why it is not zero: this repository's own audit found eighteen of twenty-five
milestones spent restoring something previously marked done. Wiring tests catch "this is never
called". They do not catch "it runs, it returns, and the answer is wrong" — the failure mode that
wrote a blank `.aether/CONTEXT.md` on 2026-08-17 and reported success. One real run against a
repository Aether has never seen is the cheapest instrument that catches that class. It is a
smoke alarm, not a scoreboard.

Cut from this plan: the GSD lane, the autopilot lane, categories 02–04, the per-lane summary and
every cross-system comparison. All of that is Phase 192's job and Phase 192 is unchanged. The
harness retains the capability — nothing built in plans 01–06 is deleted or disabled, and any cut
cell can be run later with the same one command.

Purpose: prove the apparatus works end to end on a real task, and learn whether Aether can finish
a small piece of real work unaided. The run cannot be automated — Aether's lifecycle is
interactive and the operator must supply the enumerated scripted inputs. The operator's discipline
is what makes the intervention count meaningful.

Output: `bench/results/<date>/` with one run directory, `bench/results/RESULTS.md` recording that
single row and the cut scope, and a README section stating plainly what one run does and does not
establish.
</objective>
