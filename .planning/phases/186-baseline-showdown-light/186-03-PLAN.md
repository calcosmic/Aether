Create `bench/lib/operator-log.sh`, executable and sourceable, backing an append-only JSONL log
at a path given by the `OPERATOR_LOG` environment variable.

Functions:
- `oplog_start RUN_ID LANE CATEGORY REPO MODEL` — writes the opening record with
  `event: "run_start"` and an RFC3339 UTC timestamp, plus the run's identifying fields.
- `oplog_input TYPE TEXT` — appends `event: "operator_input"` with `input_type` (which must be
  exactly one of `scripted` or `unscripted`; any other value is refused with a named error),
  the input text, and the timestamp. Refusing a third type matters: an untyped input would be
  silently uncounted, and the intervention count is one of the two headline metrics.
- `oplog_wait_start` / `oplog_wait_end` — bracket periods where the harness is waiting on the
  operator rather than on the system, so wall-clock-net can be computed by subtracting waits.
- `oplog_event NAME JSON_FIELDS` — a generic record for harness milestones (first file write,
  SIGKILL sent, resume issued).
- `oplog_end STATUS` — closing record with `event: "run_end"` and the status.
- `oplog_summary LOGFILE` — reads a completed log and emits one JSON object with:
  `scripted_inputs`, `unscripted_inputs`, `autonomous` (true only when `unscripted_inputs` is 0),
  `wall_clock_seconds` (run_end minus run_start), `wait_seconds` (summed wait brackets), and
  `wall_clock_net_seconds` (the difference). The `autonomous` field must be derived, never
  passed in — a run cannot declare itself autonomous.

Every write is an atomic append of one line. Timestamps use `date -u +%Y-%m-%dT%H:%M:%SZ`. Unlike
the hook-side capture this pattern comes from, failures here are NOT silent: if `OPERATOR_LOG`
is unset or its directory is not writable, fail with a named message. A benchmark run whose
operator log silently vanished would produce an intervention count of zero and look like the
best result in the table.
  </action>

    - With `OPERATOR_LOG` unset, any log function exits non-zero with a message naming `OPERATOR_LOG`
    - A synthetic sequence of start, two scripted inputs, one unscripted input, one wait bracket and end produces a log whose `oplog_summary` reports `scripted_inputs` 2, `unscripted_inputs` 1, `autonomous` false, and `wall_clock_net_seconds` less than `wall_clock_seconds` (asserted in Task 4)
    - A sequence with zero unscripted inputs produces `autonomous` true

    - Every record carries a timestamp matching `^[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}Z$`
