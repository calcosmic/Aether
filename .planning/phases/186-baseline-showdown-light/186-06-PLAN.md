Create `bench/harness/run-lane.sh` as a sourceable library holding everything lane-specific, so
the cell runner contains no `if lane == gsd` branching in its measurement or judging code. It
exports:
- `lane_prepare LANE WORK` — creates the lane's isolated HOME via `hermetic_home_setup`, then
  installs that lane's system only: `hermetic_home_install_aether` for `aether-interactive` and
  `aether-autopilot`, `gsd_install_into_home` for `gsd`. Fail on an unknown lane name rather than
  defaulting.
- `lane_invocation LANE CATEGORY` — prints the entry command sequence for that cell, read from
  the task spec's `## Per-lane invocation` section rather than duplicated here. Duplicating them
  would let the runner and the spec drift, and the spec is the reviewed artifact.
- `lane_working_state_paths LANE` — prints the paths that lane legitimately creates
  (`.aether/**` for the Aether lanes, `.planning/**` and `.claude/**` for GSD), for the
  cleanliness checker.
- `lane_force_model LANE MODEL` — applies the pinned model to that lane. For the Aether lanes
  this means setting agent frontmatter to `inherit` through configuration in the isolated HOME,
  never by editing this repository's source. If the lane cannot be forced to the pinned model by
  configuration, the function must print a `MODEL-DEVIATION lane=<lane> reason=<reason>` line and
  return 0 — CONTEXT.md requires the deviation be recorded, not that the run be abandoned. The
  cell runner copies that line into the run's evidence.

Create `bench/harness/run-cell.sh`, executable. One invocation runs exactly one lane × one
category. Arguments: lane, category, and an output directory. Structure follows
scripts/smoke-daily-driver.sh: strict mode, ROOT, `WORK="$(mktemp -d)"`, trap cleanup with
`chmod -R u+w` before `rm -rf`, tool preflight, numbered `step` stages.

Stages:
1. Validate the lane is one of `gsd`, `aether-interactive`, `aether-autopilot`, and the category
   is one of `01-bug-fix`, `02-brownfield-feature`, `03-interrupted-execution`,
   `04-fresh-repo-lifecycle`. Reject anything else by name.
2. Fresh clone of the category's substrate repo at its pinned SHA into `$WORK/substrate`,
   honouring substrate.md's fresh-clone contract. Record the starting branch and SHA. For
   category 04, create an empty git repo instead, per that task's spec.
3. Apply the category's `## Setup` (for 01 and 03, the seeded defect and failing test).
4. `lane_prepare`, then `lane_force_model` with the pinned model from the `BENCH_MODEL`
   environment variable, failing with a named message if `BENCH_MODEL` is unset — an unpinned
   model silently breaks the parity claim.
5. Set `OPERATOR_LOG` to the cell's log path and `oplog_start`. Print the cell's permitted inputs
   from `bench/harness/permitted-inputs.md` to the operator's terminal, so the scripted answers
   are visible at the moment they are needed rather than in another file.
6. For category 03 only: start a background watcher on `$WORK/substrate` that detects the first
   file write (poll `find "$WORK/substrate" -newer <marker> -type f` at one-second granularity,
   excluding `.git`), records `oplog_event first_file_write`, sleeps 120, then sends SIGKILL to
   the run's process group and records `oplog_event sigkill_sent`. State the exact rule in a
   comment: first file write inside the substrate clone, plus 120 seconds, SIGKILL to the process
   group — identical for all three lanes.
7. Hand control to the operator to execute `lane_invocation`'s commands interactively. The cell
   runner does not attempt to drive the interactive session itself; it prints the commands, waits,
   and brackets the wait with `oplog_wait_start`/`oplog_wait_end`. Resume after the operator
   signals completion.
8. Measurement, all after the run and all by script: `measure_tokens` against the lane's isolated
   HOME; `git-cleanliness.sh` against the substrate clone with the category's allowlist;
   `oplog_summary` against the cell's log.
9. Judgement: make a fresh clone of the substrate's resulting state into `$WORK/judge` and run the
   category's acceptance script against that clone with `ACCEPTANCE_JSON` set. Judging a fresh
   clone rather than the working directory is what makes uncommitted work correctly count as
   not-done. For category 04 also export `AETHER_REPO` pointing at this repository.
10. Hallucinated-completion detection: record whether the system claimed success (captured from
    the run's terminal transcript, saved by the operator to a named file per the runbook) AND the
    acceptance script failed. Both conditions must hold for the flag to be true. If the claim
    file is absent, record the flag as `unknown` rather than `false` — an absent input must never
    be silently favourable.
11. Write `<output-dir>/<lane>__<category>/run.json` containing every measured field, the model
    deviation line if any, the parallel-mode note (`in-repo`, with the recorded reason that
    worktree mode is disqualified until Phase 187), the substrate SHA, the acceptance verdict and
    per-assertion JSON, and the paths of the preserved raw evidence. Copy the lane's session
    transcripts, the operator log, the acceptance JSON and the terminal transcript into that
    directory before the trap deletes `$WORK`.

The cell runner must never compute a metric from anything either system said about itself, with
the single exception of the claimed-success flag — which exists precisely to be contradicted by
the acceptance script.

Create `bench/run.sh`, executable — the one documented command. Usage:
`bench/run.sh --lane <lane> --category <category>` runs a single cell;
`bench/run.sh --dry-run` prints the full twelve-cell matrix with, for each cell, the lane, the
category, the substrate repo and SHA, the acceptance script path, and the exact `run-cell.sh`
command that would execute it — and executes nothing. `--dry-run` is how a reader confirms the
harness is complete without spending a run.

`run.sh` also handles: tool preflight (extending the standard `go node npm jq git` list with
`claude` and, for the GSD lane, `gsd-sdk`); creating the dated results directory
`bench/results/$(date -u +%Y-%m-%d)/` if absent; requiring `BENCH_MODEL`; and refusing to run any
cell if `bench/acceptance/verify-predates-runs.sh` exits non-zero. That last refusal is the point
at which the acceptance-ordering discipline becomes enforced rather than documented — a run that
would invalidate the ordering claim is blocked before it happens, not detected afterwards.

Create `bench/harness/permitted-inputs.md`: for each of the twelve cells, the complete enumerated
list of inputs the operator is permitted to give. Each entry states the prompt or situation, the
exact permitted response, and whether it is an approval, a first-option selection, or a scripted
answer. Add the governing rule at the top in plain English: anything the operator types that is
not on this list is an unscripted intervention, it is logged as one, and it makes that run
non-autonomous. Note that the list is written before any run and is not to be extended after
runs begin — extending it mid-benchmark would convert interventions into permitted inputs
retroactively.

Create `bench/results/generate-table.sh`, executable, taking a dated results directory as its
argument. It reads every `*/run.json` beneath it with `jq` and emits markdown on stdout:
- A per-run table with exactly the columns CONTEXT.md specifies: lane, category, repo, acceptance
  pass/fail, interventions scripted/unscripted, hallucinated-completion flag, unnecessary-mod
  count, cleanliness score, tokens, model calls, wall-clock-net.
- A per-lane summary block: runs completed, autonomous success count out of 4, total and median
  tokens, total unscripted interventions, hallucinated completions, and mean cleanliness.
- A `## Recorded deviations` section listing every model deviation, the in-repo-mode note with
  its reason, and any cell whose hallucination flag is `unknown`. A deviation that is not
  surfaced in the table is a deviation that has been hidden.
- A footer stating the token measurement mechanism (`session-transcript`) and the pinned model,
  read from run.json rather than hardcoded, so the table can never claim a parity that was not
  achieved.
It must fail with a named message, not emit a partial table, if fewer than the expected number of
run.json files are present — unless `--partial` is passed, in which case it emits the table with
a clearly-marked incomplete banner naming the missing cells.

Add a `make bench-dry-run` target to the Makefile invoking `bench/run.sh --dry-run`.

Create `bench/RUNBOOK.md` — the procedure a human follows for the twelve runs, written for
someone who will be sitting at the keyboard and does not want to reason about the harness while
doing it. Plain English throughout; every repo term glossed on first use.

Required content:
- `## Before you start` — the one-time checks: the smoke passes, the ordering checker passes, the
  model is chosen and exported as `BENCH_MODEL`, and the terminal is set up to save a full
  transcript (name the mechanism — `script` or the terminal's own logging — and the file path
  convention the cell runner expects for the claimed-success detection).
- `## The order to run them in` — all twelve cells listed, with the recommendation to complete one
  lane's four categories before moving to the next lane so that lane-level setup is done once, and
  the counter-note that this ordering must be identical across lanes so no lane benefits from the
  operator's growing familiarity. State which ordering was chosen and why.
- `## Running one cell` — the exact command, what the harness prints, where it pauses, what the
  operator does at each pause, and how to signal completion.
- `## What you may type` — points at `permitted-inputs.md`, restates the rule that anything else is
  an unscripted intervention, and states plainly that logging one is not a failure of the operator
  but a measurement — the honest number is the point, and suppressing an intervention to make a
  lane look better destroys the comparison.
- `## The interrupted-execution runs` — what the SIGKILL looks like when it happens, that it is
  expected, and the single resume command per lane.
- `## After each cell` — confirm `run.json` was written, confirm the raw evidence was copied,
  and do not edit anything by hand.
- `## After all twelve` — generate the table, commit the dated results directory, and re-run the
  ordering checker to confirm it still passes now that results exist.
- `## If something goes wrong` — the three most likely failures (authentication expiring
  mid-benchmark, a substrate test suite going red for an unrelated reason, the harness pausing
  where the operator did not expect it) and what to do about each, including the rule that a
  cell abandoned partway is recorded as abandoned with its reason, never silently re-run — a
  re-run without a record turns one bad result into a better one.

Then append two sections to `bench/README.md`: `## Running the benchmark` (the one documented
command, the dry-run, and a pointer to the runbook) and `## What lands in bench/results/`
(the directory layout per cell and what each file is, in plain English). Do not restate the
runbook's procedure in the README; one procedure, one home.
