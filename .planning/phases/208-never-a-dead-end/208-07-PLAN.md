<objective>
Make the journey do the thing the requirement names: run each printed next command. A refusal a
real chat met during a journey step has its way out executed for real, in that same practice
project, and the step fails when the way out does not work.

Purpose: a next command that is a field rather than prose can still be wrong. The only proof that
a refusal is not a dead end is that the command it printed actually runs.

Output: an extractor over the step's own transcript, a runner that executes what it finds, and a
guard proving the extractor can find a real refusal.
</objective>

In `journeyDriveStep`, after `journeyAssertStepFact` has run and passed, call a new
`journeyRunPrintedNextCommands`. It reads the step's own transcript with `journeyPrintedRefusals`,
maps each printed command with `printedCommandToRuntimeCommand`, and for each one runs it as a real
subprocess with the practice project as the working directory, `binDir` first on PATH,
`AETHER_OUTPUT_MODE=visual` set, and a per-command timeout well inside the step's own wall-clock cap
(take it from the step's `journeyCaps`, not a new constant).

The step fails, classified as a real failure and not noise, when any of these is true for a printed
command: `printedCommandToRuntimeCommand` returned not-ok; the subprocess reported an unknown
command or an unknown flag; the subprocess timed out; or the subprocess's own output is itself a
refusal block whose next command is empty. The failure detail names the printed command verbatim
and which of those four happened. A non-zero exit that is none of those is not a failure — a
recovery command may legitimately report that work is still outstanding.

Record the counts on the result: `journeyStepResult` gains `RefusalsPrinted` and
`NextCommandsRun`, both carried into the report, and `journeyReportSummary` gains one line naming
the totals across the trial — so a run that met no refusals says exactly that rather than reading
as a silent pass. Extend `journeyGateVerdict` only to the extent of carrying these numbers through;
do not make a zero-refusal run fail, because a clean run legitimately meets none.

Update `cmd/journey_test.go`'s offline report-shape assertions for the two new fields and the new
summary line.
