# Phase 163.1: Wrapper-Runtime Completion Contract - Context

**Gathered:** 2026-08-01
**Status:** Ready for planning

<domain>
## Phase Boundary

When a wrapper hands finished worker results back to the runtime, the contract
layer (schema → docs → brief text → validator) agrees with itself, rejects a
bad submission with every violation listed at once, and always leaves an honest
recovery path. A wrapper that follows the documented contract succeeds on the
first submission. Sourced from the 2026-07-31 M4L real-world usage diagnosis;
every finding was verified against source with file:line evidence by four
review agents before this phase was scoped. The six S-size companions were
already fixed directly (commits 4b54f88e..ee0ad076) — this phase covers only
the design-level remainder (the seven numbered requirements in ROADMAP.md
§Phase 163.1).

</domain>

<decisions>
## Implementation Decisions

The user delegated all four gray areas ("you decide"). Decisions below are
locked with rationale; downstream agents should treat them as chosen, not open.

### Reconcile escape hatch (ROADMAP req 5)
- **D-01: Read-only artifact evidence is the mechanism.** A criterion bound to
  an artifact the task legitimately did not modify is satisfiable by
  hash-verified evidence: verification confirms the criterion against the
  artifact's current content and records its hash, without requiring a
  `files_modified` claim. `codexBuildClaims.ArtifactEvidence`
  (cmd/codex_build.go:146) already exists as a struct field — extend that
  path rather than inventing a parallel one. `--reconcile-task` gains the
  ability to record read-only evidence. Rationale: covers the observed failure
  (test-only task, criterion bound to an untouched source file) without ever
  legitimizing a false modification claim; task-scoped claim strictness stays
  intact.
- **D-02: Cross-task claim satisfaction is NOT added.** Task-scoped claim sets
  stay disjoint (cmd/criterion_evidence.go:520-540 behavior preserved).
  Read-only evidence makes cross-task credit unnecessary, and keeping tasks
  accountable for their own claims preserves the anti-Frankenstein integrity
  the rest of the system depends on.

### Contract source of truth (ROADMAP req 1)
- **D-03: Go structs remain canonical; the JSON Schema is generated from
  them.** Matches the project's UX architecture rule ("runtime owns truth").
  A generator emits the completion-packet JSON Schema from the Go types
  (codexExternalBuildCompletion, codexExternalBuildWorkerResult,
  codex.WorkerHandoff) into `.aether/schemas/`, run via publish or a
  `go:generate` step — drift between struct and shipped schema must fail a
  test, not be discoverable only downstream.
- **D-04: Docs and brief text are pinned by tests, not generated.** Two
  invariant tests: (a) the contract doc's worked example validates against the
  generated schema; (b) the wrapper field list (build.md) and the worker
  response contract (pkg/codex/worker.go) name exactly the schema's fields.
  Per phase-163 D-05 ("instructions, permissions, and schemas must agree")
  and the Definition of Done: a command exists that fails when they disagree.

### Failure report shape (ROADMAP req 2)
- **D-05: All violations, one response, structured + human-readable.** Batch
  validation collects every violation across every worker and returns them in
  the error envelope's `details` field as a list of
  `{worker, field, value, rule, message}` objects, plus a multi-line
  human summary. No more one-error-per-round-trip.
- **D-06: The packet stays atomic (all-or-nothing acceptance).** One worker's
  bad paperwork does not silently drop that worker — the whole packet is
  rejected with the full violation list, and the corrected packet is cheap to
  resubmit because of D-07/D-08. Rationale: partial acceptance creates
  split-brain staging state; atomicity plus cheap retry is simpler and equally
  recoverable. (Note: sanctioned-path claims already stopped being violations
  in commit 4b54f88e.)

### Attempt recovery model (ROADMAP req 3)
- **D-07: Stage-time validation equals finalize-time validation.** The staged
  path (`build-completion-stage`) runs the same semantic validation as direct
  finalize BEFORE binding the packet digest — a packet that would fail
  finalize never binds to the attempt.
- **D-08: Non-terminal attempts accept a corrected digest.** Until an attempt
  reaches a terminal state (finalize succeeded), a new completion packet may
  replace the bound one (`CompletionSHA256` rebind allowed;
  cmd/build_attempt.go:313,346,369 sites). First successful finalize seals the
  attempt; after that, only byte-identical resubmits (idempotent) are
  accepted, as today.
- **D-09: Worker names stay stable across re-plans of the same phase.**
  `ensureUniqueBuildDispatchNames` (cmd/codex_build.go:2574-2603) stops
  suffixing `-rN` for re-plans of an unfinalized attempt of the same phase —
  dedup keys on (phase, attempt lifecycle), not global spawn-tree history.
  Manual result-remapping across retries must never be needed again.

### Verification honesty (ROADMAP req 4 — direction pre-decided by Phase 160 D-01)
- **D-10: Skipped-required is a HALT, not a pass.** `runVerificationStep`
  (cmd/codex_continue.go:2659-2696) stops returning `passed:true` for
  skipped/unresolvable commands. A required check with no resolved command
  surfaces as its own loud state (`blocked: no verification command resolved`)
  with actionable guidance naming where to configure one (AGENTS.md /
  CLAUDE.md `## Verification Commands`, `.aether/data/codebase.md`). Gates
  halt; enrichment warns — per Phase 160 D-01.
- **D-11: Line-continuation joining.** `extractVerificationCommands`
  (cmd/codex_continue.go:2452-2481) joins backslash-continued lines inside
  fenced blocks before parsing, so documented multi-line commands are not
  silently truncated to their first line.

### Brief file channel (ROADMAP req 6)
- **D-12: Dual channel for one release, file preferred.** The composed brief
  (`composeBuildManifestBrief` output — base + pheromone + handoff sections)
  is written to `worker-briefs/{name}.md` (today the file holds only the base
  brief — that mismatch is the bug), a `brief_path` field is added to each
  dispatch entry, and the wrapper contract sanctions reading the file at
  `brief_path` as the verbatim source. The inline `brief` field remains in the
  manifest for compatibility this release. All four contract surfaces update
  together per build.yaml's drift guard (Claude wrapper, OpenCode wrapper,
  Codex skill, cmd/command_guide.go).

### Claude's Discretion
- Publish-order fix (ROADMAP req 7): mechanical — verify after hub sync (or
  sync before verify) in the publish pipeline; reproduced twice on 2026-07-31.
- Exact schema generator implementation (hand-rolled reflection vs a small
  library), violation-object field naming, the loud-state string wording, and
  test file placement.
- Whether `brief_path` is repo-relative or absolute in the manifest (pick what
  the existing manifest path conventions use).

<specifics>
## Specific Ideas

- The M4L diagnosis narrative is the acceptance story: "a worker that follows
  the documented contract, including copying its worked example verbatim,
  cannot be finalized" must become impossible — and provably so, via the D-04
  invariant tests.
- Six sequential rejection round-trips → one structured rejection is the
  headline UX improvement for wrapper authors.

</specifics>

<deferred>
## Deferred Ideas

- Per-worker partial packet acceptance (quarantine one worker's bad result,
  accept the rest): rejected for this phase in favor of atomic packet + cheap
  retry (D-06). Revisit only if real usage shows atomic-retry is still
  painful.
- Generating wrapper markdown from the schema (full codegen of docs): D-04
  chose test-pinning instead; full generation is a possible future hardening.
- Preflight cwd isolation for the OpenCode probe (no --strict-mcp-config
  equivalent exists): noted in the 2026-07-31 P2 verification, small and
  independent — fold into any nearby phase touching platform_dispatch.go.

</deferred>
