# Phase 163.1 Plan 08: Submitted Bytes Are the Truth Summary

**`loadExternalBuildCompletion` now keeps the wrapper's original decoded JSON alongside the typed struct and tolerates a single wrong-typed field instead of aborting the parse; `validateCompletionPacketSemantics` validates that submitted JSON directly, making every `additionalProperties: false` clause in the completion-packet schema reachable at runtime for the first time.**

## Accomplishments

- A completion packet with a misspelled or unknown field (e.g. `files_modifed` instead of `files_modified`) is now rejected, naming the offending property via the schema's `additionalProperties: false` rule -- previously this silently vanished during `json.Unmarshal` before the schema was ever consulted
- A packet with a wrong-typed field (e.g. `dispatches[0].status: 5`) no longer aborts validation on the first problem -- the type error is tolerated during decode, and structural validation reports it as one violation among however many others the packet has, in a single rejection
- Fixed a subtle correctness trap along the way: `encoding/json` allocates a zero-valued struct behind a pointer field the moment it discovers a type mismatch on that field, so a naive `activeManifest() != nil` check would have treated `"dispatch_manifest": "not-an-object"` as "manifest present" and silently skipped structural validation entirely. Caught this with a test before it shipped and fixed it with a raw-JSON-shape cross-check (`manifestKeyPresentAsObject`)
- The stage-time path (`aether build-completion-stage` / `cmd/build_attempt.go`) inherits the fix automatically with no signature change, since it validates the same `completion` value the loader returns -- proven by test, not assumed
- Packet digests (`jsonSHA256`) and the committed JSON Schema are both provably unchanged by this plan

## Decisions Made

- Kept `submittedRaw` unexported rather than introducing a wrapper type or exported field, so both `encoding/json.Marshal` (digest computation) and `invopop/jsonschema` reflection (schema generation) skip it automatically with zero extra code
- Chose a raw-JSON-shape cross-check (`manifestKeyPresentAsObject`) over parsing `json.UnmarshalTypeError.Field` path strings to detect "manifest field allocated but never actually populated" -- more robust and independent of `encoding/json`'s internal error-message format
- Task 3's fixtures splice defects into a decoded `map[string]any` (from a harness-generated conformant baseline) rather than string-replacing marshaled JSON text, avoiding ambiguity between the manifest's own dispatch definitions and the completion's worker results, which share field/worker names

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `activeManifest() != nil` alone falsely treated a corrupted manifest field as present**
- **Found during:** Task 1, while writing the test for a string-valued `dispatch_manifest`
- **Issue:** `encoding/json` allocates a zero-valued struct behind a pointer field before it discovers the JSON value given for that field is not an object, so a tolerated type error on `dispatch_manifest` itself left `completion.DispatchManifest` non-nil (pointing at an empty struct) instead of nil. The plan's literal spec (branch on `activeManifest() == nil`) would have silently skipped structural validation for exactly the packet class Task 1 was built to catch.
- **Fix:** Added `manifestKeyPresentAsObject(raw)`, which checks the raw decoded JSON map directly for a `dispatch_manifest`/`manifest` key whose value is actually an object, and cross-checks it alongside `activeManifest() != nil` at both the direct-form and envelope-form decision points.
- **Files modified:** cmd/codex_build_finalize.go, cmd/codex_build_finalize_test.go
- **Verification:** `TestLoadExternalBuildCompletion_StringDispatchManifestReturnsStructuralViolation` fails without the fix (confirmed while iterating) and passes with it; full `go test ./cmd/ -count=1` green.
- **Committed in:** d69742c1 (Task 1 commit)
