# Phase 163.1 Plan 09: Criterion Evidence On The Plan-Only/Finalize Path Summary

**`aether continue --plan-only` and `continue-finalize` now evaluate criterion evidence and honor `--read-only-artifact`, closing the gap where the escape hatch was fully wired but silently inert on the only path an external wrapper actually drives.**

## Performance

- **Duration:** ~50 min
- **Started:** 2026-08-01 (approx, before first commit)
- **Completed:** 2026-08-01T10:45:00Z
- **Tasks:** 3
- **Files modified:** 6 (2 new test files, 4 modified files)

## Accomplishments

- `runCodexContinueVerificationSnapshot` (`cmd/codex_continue_plan.go`) now calls `evaluatePhaseCriterionEvidence` — the exact same call the direct `aether continue` path has made since 163.1-06 (`cmd/codex_continue.go:1596`) — and folds `Enforced`/`Passed`/`BlockingIssues` into the snapshot's `ChecksPassed`/`Passed`/`BlockingIssues`, and populates the previously-always-zero `CriteriaPolicy`, `CriteriaEnforced`, `CriteriaPassed`, and `Criteria` report fields. Since this one function backs both `runCodexContinuePlanOnly` and `runCodexContinueFinalize`, the fix closes the gap on both entry points a wrapper actually uses.
- `runCodexContinuePlanOnly` now calls `applyReadOnlyArtifactEvidence` (recording hash-verified, task-scoped read-only evidence) immediately after the manifest loads and before the verification snapshot runs — mirroring the direct path's ordering (`cmd/codex_continue.go:577-584`) so the same invocation that records evidence also sees it during criterion evaluation.
- New `verifyPlanReadOnlyArtifactEvidence` (`cmd/readonly_evidence.go`) is continue-finalize's loud check that a plan manifest's `read_only_artifacts` were genuinely recorded by an operator-invoked plan-only run: it loads the current claims, and for each spec requires a matching, task-scoped, `ReadOnly:true` entry — a missing or cross-task-mismatched spec produces one error naming every offending spec and the exact `aether continue --plan-only --reconcile-task <id> --read-only-artifact <spec>` recovery command. It is deliberately a **verify**, not a **record** — continue-finalize never re-hashes, since doing so would silently overwrite the plan-time hash and destroy tamper detection across the external review window (T-163.1-46).
- `runCodexContinueFinalize` calls `verifyPlanReadOnlyArtifactEvidence` right after `validateExternalContinueState` and before the shared verification snapshot runs; a comment beside the `assessCodexContinue` reconstruction states explicitly that read-only evidence reaches assessment through the persisted claims file, not through the `ReadOnlyArtifacts` options field, so a future reader doesn't mistake that field for live wiring again.
- `TestContinuePlanOnlyEnforcesCriterionEvidence` and `TestContinuePlanOnlyWithoutCriterionRequirementsLeavesBlockersUnchanged` (`cmd/codex_continue_plan_test.go`) prove Task 1 at the plan-only level: a bound-v1 phase with an unclaimed criterion artifact now reports `CriteriaEnforced:true`, `CriteriaPassed:false`, `Passed:false` (even though every shell verification step passes cleanly), while a phase with no evidence requirements is unaffected.
- `TestVerifyPlanReadOnlyArtifactEvidence` (`cmd/readonly_evidence_test.go`, 5 subtests) proves Task 2's finalize-side check in isolation: empty specs no-op, matching task-scoped evidence passes, an unrecorded spec fails naming `--read-only-artifact`, evidence recorded for a different task doesn't satisfy a spec, and evidence present but not marked read-only is rejected.
- `TestContinuePlanOnlyCriterionEvidenceRequiresReadOnlyArtifact` and `TestContinueFinalizeReadOnlyArtifactEvidenceAdvancesAndDetectsTamper` (`cmd/continue_criterion_evidence_finalize_test.go`) prove the full plan-only → continue-finalize path end-to-end: blocked without the flag, `criteria_passed:true` with it, evidence surviving into `last-build-claims.json` without a false `files_modified` claim, tampering the artifact between plan-only and finalize re-blocking with `changed after build evidence was recorded`, and a hand-edited `read_only_artifacts` spec with no recorded evidence failing loudly with the recovery command rather than being silently trusted (T-163.1-45).

### Clarification (not a code deviation)

Task 3's `<behavior>` and acceptance criteria describe the finalize result as showing `advanced:true`. Given the pre-existing, unconditional "`--reconcile-task` always warns, and that warning always blocks" behavior documented in 163.1-06's own SUMMARY (and protected there by an explicit instruction not to weaken `TestContinue_ReconcileDoesNotBypassClaims`), and given `validateReadOnlyArtifacts` requires a read-only spec's task ID to also be passed to `--reconcile-task` (T-163.1-31), `blocked:true` at the top level is unavoidable for any invocation using `--read-only-artifact`. `TestContinueFinalizeReadOnlyArtifactEvidenceAdvancesAndDetectsTamper`'s first subtest instead proves "advances" in the sense the D-01 decision actually promises: `verification.criteria_passed` flips to `true`, `criteria_enforced` is `true`, and the criterion-specific blocking issue disappears — exactly mirroring 163.1-06's own documented clarification for the direct continue path's equivalent test.
