<objective>
Make `--read-only-artifact` mean something on the path an external wrapper actually uses:
`aether continue --plan-only` → external review → `aether continue-finalize`.

Purpose: closes VERIFICATION.md gap 3 (requirement 163.1-REQ-5). Today the flag is parsed
(cmd/codex_workflow_cmds.go:229), validated (cmd/codex_continue_plan.go:95), persisted into the plan
manifest (cmd/codex_continue_plan.go:138), re-validated at finalize
(cmd/codex_continue_finalize.go:509) — and then does nothing, because
`applyReadOnlyArtifactEvidence` is called only from `runCodexContinue` (cmd/codex_continue.go:582)
and `evaluatePhaseCriterionEvidence` has exactly one call site in the whole `cmd` package
(cmd/codex_continue.go:1596), inside the direct path. `runCodexContinueVerificationSnapshot`
(cmd/codex_continue_plan.go:213) — the verification used by BOTH the plan-only and the
continue-finalize path — never evaluates criterion evidence at all, so the gate the escape hatch
exists to satisfy never runs there and the flag is a silent no-op.

This is the milestone's own disease in miniature: fully built machinery with no caller.

Output: criterion evidence evaluated in the shared snapshot; read-only evidence recorded at
plan-only time, before that snapshot runs; and a loud failure at continue-finalize when a plan's
read-only specs have no recorded evidence, so the flag either takes effect or says so.
</objective>
