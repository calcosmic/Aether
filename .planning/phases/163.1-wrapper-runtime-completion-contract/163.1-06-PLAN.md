<objective>
Give a criterion bound to a file the task legitimately did not modify an honest way to be
satisfied, without ever legitimizing a false modification claim.

Purpose: Requirement 5 and decisions D-01/D-02. `evaluatePhaseCriterionEvidence`
(cmd/criterion_evidence.go:364-461) requires `claimed[artifact]` — the artifact must appear
in `files_created`, `files_modified`, or `tests_written` — before it will even look at the
recorded hash. A test-only task whose criterion is bound to an untouched source file is
therefore unsatisfiable except by lying. `attachBuildArtifactEvidence`
(cmd/criterion_evidence.go:270-286) only snapshots paths drawn from those same three claim
lists, so there is currently no path to register hash evidence for an unmodified file.

Output: a `ReadOnly` marker on artifact evidence that only the runtime can set, a task-scoped
bypass of the claimed gate, and a `--read-only-artifact` recording flag on `continue`.
Cross-task claim satisfaction is explicitly NOT added (D-02).
</objective>
