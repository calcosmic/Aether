# Phase 163.1 Plan 02: One Rejection, Every Violation Summary

**Replaced six sequential first-error-and-return rejections in the build-finalize validation chain with a single `validateCompletionPacketSemantics` entrypoint that accumulates every structural, claim-path, and dispatch-level violation into one `completionContractError`, atomically, before any colony state is touched.**

- **Tasks:** 2/2 completed

## Accomplishments

- `collectClaimPathViolations` + `validateExternalWorkerResultClaimPaths` (task 1) report every bad claim path across every worker and every field (`outputs`, `files_created`, `files_modified`, `tests_written`) in one call instead of stopping at the first. `validateAndNormalizeClaimPathToRoot`'s existing rejections (null byte, non-repo-relative, `.aether/data` policy, path resolution) are preserved byte-for-byte — only wrapped with a `claimPathRuleError` carrying one of four rule strings (`claim_path.null_byte`, `claim_path.repo_relative`, `claim_path.aether_data`, `claim_path.escapes_root`), extracted via `errors.As`, never by matching message text.
- `mergeExternalBuildResults` now returns `(dispatches []codexBuildDispatch, violations []contractViolation, err error)`. Every one of its six original early-return sites (missing name, duplicate result, ambiguous/already-matched name, missing result, identity mismatch, non-terminal status, invalid handoff) accumulates a `contractViolation` and `continue`s instead of returning, so later dispatches in the same packet are still checked. `err` is now reserved for genuine internal failures the wrapper cannot fix by resubmitting.
- `validateCompletionPacketSemantics(root, completion) []contractViolation` is the new single entrypoint: it runs structural validation (plan 01's `validateCompletionPacketStructure` against the packet marshaled to `any`), claim-path validation (task 1), and dispatch-level validation (task 2), accumulating all three into one slice. `runCodexBuildFinalize` calls it once, before the checkpoint save, `beginBuildAttempt`, `bindBuildAttemptCompletion`, or any `transitionBuildAttempt` call — a rejected packet leaves the build attempt and colony state exactly as it found them (D-06).
- `completionContractError` carries the violation slice and renders a multi-line human summary (`N completion packet violation(s)` + one indented line per violation). The `build-finalize` cobra handler unwraps it via `errors.As` and passes the violations slice as `outputError`'s `details` field, so the CLI's JSON envelope surfaces the full structured list, not just the first problem.
- Wiring real structural validation into the finalize path for the first time (previously wired but never called per 163.1-01's summary) exposed that several pre-existing hand-built test fixtures and one aggregation-path gap produced nil (not empty) required-array JSON fields. Fixed both the fixtures and the one real gap (see Deviations).

- **Found during:** Task 2, running the plan's own `<verification>` block (`go test ./cmd/... -count=1`) against `TestBuildFinalizeAcceptsVerificationOnlyOutputEvidence`
- **Issue:** `codexBuildClaims.FilesCreated`/`FilesModified` are non-`omitempty` `[]string` fields (schema requires them present as arrays), but `validateAndNormalizeClaimPathsToRoot` returns `nil, nil` for a zero-length input, so a legitimate verification-only completion packet's `claims.files_created`/`files_modified` would marshal to JSON `null` and fail structural validation for the first time now that it's actually checked.
- **Fix:** After `validateAndNormalizeBuildClaims` in `claimsOrAggregate`'s explicit-`Claims` branch, normalize `nil` to `[]string{}` for both fields. The aggregation branch (no explicit `Claims`) was already safe — `uniqueSortedStrings` always returns non-nil.
- **Files modified:** `cmd/codex_build_finalize.go`
- **Verification:** `TestBuildFinalizeAcceptsVerificationOnlyOutputEvidence` passes; also updated the test itself to submit explicit `FilesCreated: []string{}, FilesModified: []string{}` since a wrapper submitting an empty claims object should send explicit empty arrays, not omit the keys
- **Committed in:** `80f247f8` (Task 2 commit)

**2. [Rule 3 - Blocking] Pre-existing hand-built manifest/claims test fixtures used nil required-array fields**
