<objective>
Make the file the four contract surfaces already point at actually contain the brief they
promise, name that file in the manifest, and stop renaming workers when a phase is
re-planned.

Purpose: Requirement 6 (D-12) and the D-09 half of requirement 3. Today
`writeCodexBuildArtifacts` (cmd/codex_build.go:1769-1783) writes only
`renderCodexBuildWorkerBrief` output — the base brief — while the manifest's inline
`dispatch.brief` carries the composed brief (base + pheromone signals + prior handoffs)
from `composeBuildManifestBrief`. The wrappers mandate passing 6-22KB briefs VERBATIM,
which is unsatisfiable through a JSON field subject to Read-tool long-line truncation.
Separately, `ensureUniqueBuildDispatchNames` dedupes against the entire global spawn-tree
history, so re-planning the same phase renames every worker `-r2`, `-r3`, forcing manual
result remapping.

Output: composed brief in the file, `brief_path` in each dispatch entry, all four contract
surfaces updated together per build.yaml's drift guard, and phase/attempt-scoped naming.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-163.1-16 | Tampering | `brief_path` pointing outside the store, letting a wrapper be steered to read an arbitrary file | mitigate | `brief_path` is set only from `displayDataPath(briefRel)` where `briefRel` is built from `buildDirRel` + `worker-briefs` + the dispatch name; never from worker or user input. A test asserts every emitted `brief_path` resolves under the store base path |
