# Decision: v1.29 "Use It Every Day" (owner, 2026-09-21)

## Why
On 2026-09-21 the owner used Aether in three real projects for the first sustained day. Six separate
bugs each stopped his work dead; all six were the program refusing something it should have allowed
or handled (a folder missing from a write allowlist, two archive names differing only by letter
case, a fingerprint no helper can compute, a planning run pinned to a superseded specification, a
pause fingerprint that followed folder shortcuts, a status card advising a menu command that does
not exist). About 5,900 automated tests caught none of them. His words: "I need to make this now
working as the framework I can use for developing stuff because now it's like I'm just going in
circles." He also asked why the Go program exists at all, since the spring (markdown-only) version
felt better; the answer recorded that day: the program exists because the chat cannot be trusted with
bookkeeping, and the mistake was moving the *experience* into it too and adding strict rules faster
than real use could test them.

## Ruling
A milestone with one rule: **no new features and no new strict rules.** Five phases:
206 screens reach the owner; 207 a messy practice project as the release gate; 208 never a dead
end; 209 a light default path; 210 a two-week freeze in which only bugs hit in real use are fixed.
The owner approved this shape and the research-backed additions on 2026-09-21 ("yes i like the sound
of all of that").

## Done means
The owner takes one real piece of work from start to finish in each of his real projects without
pasting a bug into the Aether chat. Not "all phases ticked".

## Stopping rule (agreed up front)
If, after the freeze, he still hits a blocker more than about once a week, investment in the full
framework stops. The parts that already earn their place (quick jobs, flags, the memory of his
preferences and lessons) are kept on top of plain Claude.

## Guard against ceremony
GSD's full ceremony is part of how the work turned inward. Each phase here stays small and its proof
is a real run in a real chat, never paperwork, and one review round.

## Research
`.planning/research/2026-09-21-popular-frameworks.md` and
`.planning/research/2026-09-21-reliability-and-delivery.md` (GitHub projects over 1,000 stars).
Two findings shaped the milestone: none of the popular projects read lets its program refuse the
user (they derive, warn and continue), and Claude Code's hook field `systemMessage` shows text to
the user directly with no model turn (verified in a real `claude -p` run the same day).

## Relation to v1.28
Phase 205 (owner-driven acceptance of ten journeys) is superseded: Phase 207 automates the journey
and Phase 210 is the owner's acceptance. Phases 204.2 to 204.5 stay parked.
